# 第二周：从真实 API 执行证据练习 Python 数据处理

这个练习读取已有执行记录，不执行、重跑或修改业务接口。它检查指定执行和子用例的关联，确认记录来自反馈一级分类 GET，再对该次真实响应提取字段并运行本地数据处理检查。字段和业务码来自历史观察，尚未由业务方审核为正式合同。

仅使用 Python 3 标准库，没有第三方依赖；项目没有默认平台地址，不保存、打印凭据。平台只读模式需明确指定地址、服务端可信地址配置和已授权会话令牌；它会执行两次平台 GET，业务接口请求为 0。禁用系统代理和重定向。文件模式不会访问网络，文件应为来自真实平台执行的最小脱敏投影，保留执行 ID、子用例 ID、请求方法和路径、状态、断言及 code/data 必需字段；不保存令牌、响应头或不必要的业务数据。**程序不能独立验证用户提供文件的真实性**，输出会明确标注；应另行核对导出过程。确保文件权限和存放位置由使用者控制。

## 干净环境复现

```bash
python3 -m venv /tmp/week2-real-venv
/tmp/week2-real-venv/bin/python -m unittest discover -s tests -v
/tmp/week2-real-venv/bin/python run.py --evidence /安全路径/证据.json \
  --execution-id 真实执行ID --case-id 真实子用例ID
```

以上命令在本目录执行，虚拟环境路径请使用未存在的新目录。`unittest` 使用合成数据验证工具的行为，并非业务执行结果；只有用真实证据运行 `run.py` 产生的输出，才是相应记录的本地处理结果。

也可在安全的终端环境里设置与 `--platform-origin` 完全相同的可信地址 `WEEK2_ALLOWED_PLATFORM_ORIGIN`，并配置 `WEEK2_PLATFORM_TOKEN` 后运行：

```bash
python run.py --platform-origin 明确指定的平台地址 \
  --execution-id 真实执行ID --case-id 真实子用例ID
```

令牌必须由平台授权获得，切勿写在命令、文件、工单或聊天中。支持 HTTPS，HTTP 只允许在平台服务所在服务器上使用带端口的 `http://127.0.0.1:8088`（须先确认服务确实监听该地址）；禁止向非本机明文发送令牌。输出只包含安全状态、断言通过情况、请求 ID、执行时间和检查 ID，不输出原始响应、令牌或响应头。证据拉取失败保留平台 HTTP 状态，显示为阻塞；必须重新核查权限、地址或证据来源，不能记为测试通过。

所有检查属于本地数据处理：包含真实数据的字段类型检查，以及在真实记录副本上构造空值、错误类型等边界输入；它们不是多条独立的真实接口请求。`code=0`、字段含义和异常行为待业务审核。无业务数据创建或清理，此次不能证明写操作的隔离和清理能力；人工耗时、真人业务规则及讲解继续待办。
