# API 测试平台体验点检与改进计划

## 点检范围

2026-08-26 使用全新浏览器页面，从任务平台登录后进入 API 测试平台，按真实数据依次检查：工作台、接口资产、用例管理、任务管理、基线用例、定时任务、执行记录、测试报告和环境配置。首次实站点检只做读取和页面切换；修改后在本地隔离数据中点击了任务恢复、用例调试、基线回归、报告查看、定时任务执行详情和飞书测试发送等核心操作，不删除线上已有数据，也不向线上机器人发送测试消息。

## 已确认的问题

### P0：结果可信度

- 测试报告会把 `239 / 240`、`716 / 719` 显示为 `100%`。这会误导报告阅读者，任何存在失败、异常、跳过或取消的执行都不能展示为满分。
- 定时任务列表只显示原始 Cron，没有下次执行时间、最近触发时间和最近结果。用户无法在列表中判断调度是否生效。

### P1：状态可追踪

- 任务列表存在重名任务，但只有接口数、基线数、环境和状态，缺少更新时间、最近执行结果和执行入口，无法快速区分同名任务。
- 任务详情显示原始英文状态 `ready`，与列表的中文状态不一致。
- 基线列表展示内部采纳原因 `passing debug evidence`，不应把实现文案暴露给用户。
- 飞书机器人配置只有保存，没有“发送测试通知”。用户必须等到一次真实执行后才能知道机器人是否可用。

### P1：操作语义

- 工作台同时出现多个“保存”动作，任务、范围、草稿和执行的对象边界不够清晰。
- 用例详情存在“保存并调试”和“保存并执行”两套相近动作，需要明确唯一主路径，避免新手误以为会产生两种不同执行结果。
- 接口资产页实际承担同步源和版本管理，入口文案需要强调资产来源与版本，而不是让用户误以为这里直接管理所有接口用例。

### P2：长列表效率

- 基线页真实数据超过 280 条、执行记录超过 50 条，一次展示全部内容影响定位和渲染。
- 用例页已有分组、筛选、搜索和独立详情，信息架构正确；不应再把完整用例列表塞回工作台。

### P2：配置可理解性

- 环境详情中多个服务键可能映射到同一个地址，也可能存在未配置地址。现有汇总已基本可用，后续可增加主动连通性检测，但必须明确检测方法和鉴权副作用后再实现。
- 登录成功后旧的失败提示可能残留，属于上层任务平台登录体验问题，不在本轮 API 测试前端范围内。

## 信息架构结论

- 左侧现有九个入口已经覆盖“设计、资产、用例、任务、基线、调度、执行、报告、配置”完整生命周期。
- 本轮不新增重复的“总览”或“管理中心”入口。报告页继续承担项目质量总览，工作台继续承担单次设计和调试；用例管理与任务管理保持独立页面。
- 优先补齐每个资产的状态、最近运行证据和直接下一步操作，比增加导航项更能缩短使用路径。

## 实施顺序

1. 修复通过率展示，保证异常执行不会显示 `100%`。
2. 为定时任务补充人类可读计划、时区、下次执行、最近触发和最近结果，并可跳转对应执行记录。
3. 为任务列表补充更新时间和最近执行摘要，统一状态中文展示。
4. 本地化基线采纳原因，清理内部技术文案。
5. 为项目飞书配置增加显式测试发送能力，不关联任何真实测试执行。
6. 收敛重复保存/执行动作，并补齐按钮说明。
7. 完成单元测试、静态检查、生产构建和真实浏览器回归。

## 暂不实施

- 不新增重复左侧入口。
- 不在没有探测契约前直接增加环境“连通性检查”，避免探测请求产生业务副作用。
- 不改变工作台、用例、任务和报告现有路由，不迁移用户数据。

## 实施结果

- 已修复通过率取整问题：只要通过数小于总数，页面和飞书卡片都不会显示 `100%`。
- 已为定时任务补充可读周期、服务端时区、下次执行时间、最近触发方式、最近执行结果和对应执行记录入口。
- 已为任务列表和详情补充最近执行结果、通过率、更新时间，并统一任务状态的中文展示；最近执行摘要独立读取，不会被后续 AI 生成摘要覆盖。
- 已将基线内部采纳原因 `passing debug evidence` 本地化为面向用户的文案。
- 已为项目飞书配置增加“发送测试通知”，测试卡片明确标记为配置验证且不关联测试执行。
- 飞书配置和发送只接受飞书/Lark 官方 HTTPS 机器人地址，拒绝 HTTP、私网、回环、伪造域名和非机器人路径。
- 已修复用例编辑器“保存并调试”事件未接通的问题，并移除页面外层重复的“保存并执行”入口。
- 已为基线和执行记录增加分页，避免一次渲染完整长列表。
- 已补齐手机和平板导航、上下文区折叠、工作台面板切换，以及用例、任务、报告的移动端列表/详情切换。
- 左侧九个入口保持不变；实站点检确认生命周期覆盖完整，没有新增一个与现有页面职责重叠的入口。
