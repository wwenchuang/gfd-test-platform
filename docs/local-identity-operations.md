# 本地账号与权限上线说明

## 范围与入口

本轮引入独立本地账号，不要求先启用 API 测试模块，也不接管外部 Sonic 账号。

- 配置区的“成员与权限”包含成员、角色、数据授权、操作记录。
- 用户名是不可变的身份标识，姓名可使用中文。成员只停用，不删除历史身份。
- 角色控制动作；数据授权控制可访问的 UI 应用、API 项目及 API 环境。项目和环境权限取交集。
- 新成员默认没有数据范围。仅分配“测试成员”角色不会自动开放全部项目。
- 自定义角色可以复制、编辑和删除；使用中的角色不能删除，最后一个有效超级管理员不能停用或降权。
- 新成员、管理员重置密码后，必须修改密码才可进入业务页面；403 表示权限不足，不会当作登录失效处理。

## 首次切换

1. 使用现有 `admin` 登录。环境中原有管理员口令只用于首次迁移，不重写已有项目 owner 或历史基线。
2. 在“个人账号”中修改原来多人共用的密码；之后修改环境口令不会覆盖身份库的新密码。
3. 创建至少一个实名超级管理员作为备用账号，验证登录和改密后再向其他成员分发账号。
4. 为成员选择角色和明确的数据范围。推荐先给一个测试项目及其测试环境，验证后再扩大。
5. 使用只读成员和测试成员各验证一次：授权数据能看到；未授权数据不能通过直接链接访问；只读不能执行或修改。

临时密码只显示一次，不存入浏览器持久存储，不写审计记录。关闭后忘记只能重置。不要把密码贴进代码、工单或部署命令历史。

## 部署与持久化

使用仓库现有更新入口，不另外在堡垒机创建同名脚本：

```bash
cd /opt/midscene-task-platform-src
git pull --ff-only origin main
bash deploy/update-main-server.sh
```

安装器新增 `TASK_AUTH_DB=/opt/midscene-auth/identity.sqlite3`。身份库必须在发布源码、运行代码目录之外；安装器检查规范化路径，发布不会覆盖身份库。身份目录应只向服务用户及系统管理员开放。不要把身份库、WAL 或备份加入 Git。

密码依赖随虚拟环境安装。运维脚本请使用 `/opt/midscene-task-platform/.venv/bin/python`，不能临时切回未安装依赖的系统 Python。会话摘要、撤销和限流状态保存在 SQLite，服务重启不会恢复已经注销的会话。

已有旧版签名登录令牌不再有效，首次部署后各浏览器需要重新登录。这不会删除任务、用例、基线或执行报告。

## 备份与应急恢复

在线一致性备份使用 SQLite 备份 API，不能在运行中只复制主数据库文件而遗漏 WAL。以下命令以服务账号执行，输出路径不得已存在；备份包含密码摘要与会话数据，应限制访问并纳入管理员备份策略。

```bash
cd /opt/midscene-task-platform
runuser -u midscene -- .venv/bin/python -m task_server.identity backup --output "/opt/midscene-auth/identity-backup-$(date +%Y%m%d-%H%M%S).sqlite3"
```

遗失管理员密码时，系统管理员可在主机控制台重置明确指定的现有超级管理员。密码交互输入，不放在命令参数中；命令不创建新身份库、不创建新管理员、不启用原本停用的账号。

```bash
cd /opt/midscene-task-platform
runuser -u midscene -- .venv/bin/python -m task_server.identity reset-admin --username admin
```

重置会撤销该管理员全部旧会话，下次登录需再修改密码。恢复备份必须先停止平台、API Worker 和 Scheduler，确认备份及配置的身份库路径，保留当前库/WAL/SHM 后再由管理员替换，恢复服务用户所有权和 0600 权限。不要直接覆盖运行中的数据库；旧备份可能恢复尚未撤销的旧会话，恢复后应再次撤销全部成员会话并验证登录。

## 连接与网关

**向同事分发个人密码前必须配置 HTTPS。** 目前公网 HTTP 不会因账号改造而变为加密连接。浏览器仍使用现有 Bearer 会话方式；HttpOnly Cookie 和企业单点登录属于后续独立改造。

AI 网关新增鉴权文件并随安装器、离线包一起发布。来自浏览器、代理和非本机请求的模型调用会向后端 `/api/auth/me` 验证会话；校验失败或后端超时会拒绝请求，不降级成匿名调用。

- 直接在主机运行 Nginx：网关默认监听 `127.0.0.1`。
- Docker 网桥代理：安装器检测到非 host 网络的 Web 容器时，绑定 `0.0.0.0` 以保持现有连通性；必须通过安全组/防火墙限制 8090 仅可信代理可达。非回环请求仍须认证。
- 特殊拓扑可在安装时显式设置 `AI_GATEWAY_HOST`；后端地址由 `AI_GATEWAY_AUTH_BASE_URL` 配置，必须为回环地址。
- 反向代理必须保留 `Authorization` 并设置 `X-Forwarded-For` / `X-Forwarded-Proto`，不能把外部请求伪装成无标记的内部调用。
- 兼容旧 Python 调用的“无代理头、本机回环”网关请求仍属于主机信任边界，不向外部开放。

## 数据边界

API 同项目的授权成员协作用例和基线，资源 owner 保持原项目 owner，创建人/修改人记录实际成员。个人工作区与个人提供方凭据仍按账号隔离。定时任务在触发时重新检查实际用户状态、角色和环境权限。

定时任务因为账号、角色、目标或环境失效被阻断时会保留配置并显示中文原因；其他有权限的任务继续执行。恢复授权并成功提交下一次执行后，阻断提示清空。执行日志的实时连接也绑定原登录会话，退出、撤销会话或取消数据授权后不能用旧票据重连。

Runner/Sonic 的心跳和结果回调只接受原有机器凭据，普通网页会话不能伪造执行结果。部署不改变已有 Runner Token 协议；运行环境、用例及桥接脚本的必要机器读取入口继续保留。机器凭据仍属于受信任执行主机边界，不应分发给普通成员。

重试会重新检查原任务继承的执行模式与自动修复设置，而不是只检查按钮提交的新字段。文件修复默认会创建重跑任务，因此需要执行和基线权限；明确关闭重跑时仍可只修复文件。

环境 `services.*.metadata.production=true` 可显式标记生产环境；当前或历史名称中的“生产/正式/prod/production”也进入生产保护。已标记环境不能通过改名或写 `production=false` 降级绕过执行权限。没有标记且名称无法识别的历史生产地址，平台不能凭 URL 可靠判断，管理员必须收紧环境范围并补标。

请求地址和重定向只能落在当前显式选择的环境服务 origin 和基础路径内，运行时变量不能改变服务地址，也不能覆盖 Host。如果一个流程确实需要多个服务，应在环境里配置各自的服务并在步骤中选择，不要在接口路径中拼接未配置域名。历史版本的敏感请求头通过 API 读取时遮蔽，新建/编辑/同步/恢复出的版本会将字面凭据转为加密变量；旧数据库及其备份中的历史明文未作批量迁移，仍需管理员保护存储访问。

UI 模块由平台保存的应用配置确定归属，不根据中文名字猜测。历史模块未关联应用或被多个应用共同关联时，受限用户不能越过范围访问。先在应用配置关联模块，再授权成员。

现有 Agent 自动编排内部会检索跨应用资料，因此本轮仅对完整应用范围且具有平台配置、UI 执行权限的管理员开放创建/确认/重试。UI AI 生成与自动修复使用共用 Top3 基线检索库，暂要求完整 UI 应用范围及对应编辑/执行权限；受限成员可使用已授权应用下的手工 YAML 管理和执行。API 项目内的 AI 生成不受此 UI 限制。未完成检索库和每个内部工具的资源隔离前，不应只放开页面入口。

以下不是本轮账号权限的安全承诺：公开静态 HTML 报告地址、外部 Sonic 页面、操作系统/数据库管理员访问。敏感历史报告需要另行配置受保护的下载代理或网络访问控制；不能用业务 API 的 403 测试代替这些验收。

## 验收与故障区分

- 401：没有有效会话，重新登录。成员被停用、会话撤销、密码变化后出现 401 属于预期。
- 403：身份有效但缺少动作权限或数据范围；核对角色、应用映射、项目与环境交集，不要反复改密码。
- 429：登录尝试过于频繁，等待限流窗口，不要持续重试。
- 503：身份库/后端暂不可用，检查服务日志、身份目录权限及磁盘；不能删除身份库“重试”。

本地测试只证明代码和隔离数据链路通过。正式环境仍需在部署后执行以上实名账号、只读、越权、停用、定时任务和 HTTPS 验收。既有全平台点检与真实基线回归计划继续保留，不因本次身份改造重置。
