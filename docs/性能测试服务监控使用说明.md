# 性能测试服务监控使用说明

当前实现：复用 Prometheus 兼容数据源，选择整机、指定容器或指定 Pod 内各容器或 PostgreSQL 指定数据库。整机提供 CPU、内存、网络收发速率、磁盘读写吞吐、IOPS、平均 I/O 延迟和文件系统已用空间；容器 / Pod 复用已有 cAdvisor，提供 CPU 实际核数与内存 working set。**服务名称只是方便识别；整机指标代表该主机全部进程，不能当作某个应用或容器的独占资源。** PostgreSQL 以外数据库类型、最大连接额度/慢查询/锁等待、工作负载聚合、Pod 就绪/重启、容器网络/磁盘尚未接入，未采集不能推断正常。

## 首次配置

1. 在 API 平台选择应用，进入“环境配置”，选择环境，打开“服务与监控”。
2. 新增监控服务，填写名称、业务用途、Prometheus 查询地址、精确的 instance 标签，选择资源范围、指标和查询间隔。指定容器还需填写精确非根 cgroup id；Pod 需填写 namespace 与 Pod 名称，报告按真实容器分列，不推测整个工作负载。
3. 首次授权一个监控地址需要平台配置权限，管理员在网页勾选明确授权。后续可复用已有配置。私网允许显式授权，但云元数据、回环和链路本地地址仍禁止访问；平台后台必须能连接数据源。
4. 如需只读 Bearer 令牌，直接在网页填写，必须使用 HTTPS。令牌加密保存、不回显；编辑时留空保留旧令牌。
5. 测试连接：不仅看能否访问，还要求存在匹配指标、新鲜源采样，主机百分比还需有效资源分母。容器 CPU 无正配额时仍保留实际核数、占比未知；内存仅展示 working set，不推测硬限制。CPU 与网络/磁盘速率至少需要两分钟历史；监控刚启动时应等待数据积累。

采样间隔是查询评估步长，不会提高 exporter 本身采样精度。CPU 使用两分钟平均变化率；短测试可能包含测试前的数据。内存口径为 `(MemTotal - MemAvailable) / MemTotal`，不是简单的 MemFree。

## 每次执行

选择场景和环境、设置压力、选择发压节点，然后勾选监控服务。可以在向导内新增配置，无需退出。切换环境会清除旧环境的监控选择。

- 必选：启动时要求该配置版本在五分钟内完成新鲜采样检查；不满足时阻止开始。
- 可选：缺失时警告，不单独阻止性能阈值判断；但不能据此判断资源正常。
- 前后观察窗口：默认各六十秒，可设为零至六百秒。建议源已有充分历史，否则前观察阶段可能没有 CPU 证据。
- 创建的是草稿，不会立即发压。草稿仍按“目标连通性 → 单用户预检 → 开始压测”执行。
- 执行卡片提供“检查监控采样”，可以检查草稿绑定的旧配置版本。编辑环境配置不会更改历史执行快照。

## 报告与异常

平台后台每轮只读采集，网页自动刷新。压力结束后继续等待后观察窗口及约三十秒迟到数据回补；完成后冻结结果，再生成最终 AI 诊断。监控访问不会自动重跑业务请求。

“被测资源”独立于发压节点。每项展示主机/容器/Pod 与设备的实际标签、数据源、统计口径、时间、单位和峰值；详细表格保留源采样时间、分母及已用核数/内存。容器 CPU 百分比只用同一容器、同一时间新鲜的正 quota/period；没有配额时显示未知。网络与磁盘按设备展示，不能把物理盘/分区、虚拟网卡重复相加。缺失为“采样缺失”，不补零，不跨缺口连线。

必选监控缺失会使完整性能结论为证据不足，但请求、延迟和错误数据仍保留。AI 只能基于已有证据提出建议；整机 CPU 升高不能直接证明某个服务有瓶颈，更不能凭此断言内存泄漏或慢 SQL。

## 部署与验收边界

新增数据库迁移 `0011_load_monitoring`，平台后端和 API Celery worker 都必须升级并重启。平台现有安装脚本会执行数据库迁移。不要仅替换前端静态文件。

本批监控采集由平台后台完成，不要求专用发压节点安装 node_exporter；node_exporter 应部署在需要观察的被测主机上。此前统计采集修复涉及 Agent 0.1.4，是另一项升级。

本地已用实际 Prometheus 2.54.1 和确定性模拟 exporter 验证查询，并以 PostgreSQL 和 Safari 检查配置契约与页面。真实业务监控源尚未提供，不能将本地数据称为线上业务资源验收通过。


无已有主机监控源时，管理员可使用 [标准采集部署包](../deploy/load-monitoring/README.md)。默认回环监听、独立非 root 进程、资源与保留上限，内网只读网关显式绑定真实私网 IP 并限制后台 IP；不挂 Docker socket，也不自动远程安装。容器与 Kubernetes 需复用已经部署的 cAdvisor / kubelet 指标，不把主机包冒充容器采集器。

扩展表达式通过真实 Prometheus promtool 的确定性时序测试，覆盖网络/磁盘速率、0.5 核 / 1 核配额、64 MiB working set、Pod 基础设施排除、无限额和配额过期。可运行 `promtool test rules tests/api_testing/fixtures/load_monitoring_promql.yml` 重验。这不是 Linux systemd/Nginx 包的部署验收；目标主机安装、源标签对账与线上完整流程仍需在真实环境执行。


PostgreSQL 模板需要精确 `instance + datname`，只支持已有 postgres_exporter 的数据库连接数、提交/回滚事务速率。连接数包括空闲连接，事务吞吐不等于业务链路吞吐，回滚不直接代表业务失败。只读源中无匹配指标时明确显示缺失。

文件系统已用空间为 `size_bytes - free_bytes`，百分比以同一挂载的 size 为分母；保留 device/mountpoint/fstype，不叠加重复挂载。平均磁盘 I/O 延迟为两分钟累计耗时 rate / 完成操作数 rate，不是请求 P95。零操作时明细显示“无 I/O，延迟不可定义”，该指标没有有效延迟证据；空闲预检时可将此监控设为可选，不能填零掩盖无样本。
