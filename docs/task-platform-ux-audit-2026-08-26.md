# 功夫豆测试平台体验走查记录（2026-08-26）

## 2026-08-28 全平台连续点检与展示收敛

本轮延续原有“主平台 + API 测试 + 基线整改”清单，没有因上下文切换重建计划。线上读取点检覆盖主平台五个导航组与 API 平台九个入口；写操作和新版页面在本地隔离数据中复验。

### 本轮已实现

- 基线页将“筛选结果 / 已选择”改为独立数字指标，与批量按钮分区；数字、单位和标签不再逐字断行。桌面 1440px 与手机 390px 都增加真实渲染断言和截图。
- API 测试在无会话时于 Vue 挂载前跳转登录，并保留 `#/baselines` 等精确深链；已登录的管理台也会执行 `return_to`。Nginx 为无尾斜杠 `/api-test` 使用相对跳转，避免公网 `:8088` 端口丢失导致 404。
- 主平台默认只展开当前 Agent 导航组，对历史“全部展开”偏好做一次收紧迁移；“失败重跑 / 失败分析”合并为唯一“失败处理”入口，旧深链会自动归一。
- Agent 无任务首屏从多块空记录、空待确认和空产物改为一块三步新手引导；Figma、需求文档和截图改为默认收起的“补充需求资料（可选）”，不影响有任务时的完整证据与产物。
- 切换管理页前先完成脏 YAML 自动保存；保存成功后关闭上一页弹窗、更多菜单和 Toast。保存失败则留在原页，导航高亮不会先跳走。
- AI 生成弹窗不再在未选应用时默认读取 `com.kfb.model` 知识；记录页每次只渲染 20 条，其余手动继续加载。
- API 生成状态明确告知“可离开页面 / 结果已保存在用例列表”；执行列表显示真实页码范围，日志中的 `PASSED / FAILED / DONE` 转为中文状态。
- 定时任务的基线、用例或应用业务已删除/停用时，列表直接显示“执行已阻断”原因，禁用启用和手动执行，不再显示虚假的下次运行时间。
- AI 校验诊断继续使用平台配置的千问和脱敏后当前接口合同，新增约束禁止编造 token、设备号或请求 ID；固定值指导用 `{{变量名}}`，动态值要求指出前置接口和响应提取路径。
- 主平台 JS/CSS 缓存标识升级为 `20260828-full-platform-ux`，避免部署后仍运行旧界面。

本轮完整门禁通过：548 项后端测试、62 个 Vue 文件共 372 项测试、Vue TypeScript 生产构建、9 张 API 桌面/平板/手机视觉截图，以及 1 条 Chromium“导入 -> AI 设计 -> 调试 -> 采纳基线 -> 回归 -> 报告”闭环。主平台桌面/手机视觉冒烟、后端静态 63 项、前端静态 84 项、Python 编译、Bash 语法和 `git diff --check` 均通过。

## UI 与 API 飞书通知卡片补充点检

用户提供的线上飞书截图证明，Sonic/UI 自动化通知被错误标成“API 基线回归”；API 通知则把“API 基线测试”、任务名和任务类型混在同一层级。根因分别位于 `build_sonic_suite_summary_card` 和 `NotificationService._card` 的硬编码文案，而不是飞书机器人本身。

已实施：

- UI 卡固定展示“UI 自动化”，API 卡固定展示“API 测试”；“基线回归”只作为执行场景。
- 标题统一为“应用｜业务｜测试类型｜执行场景+结论”，正文统一为结论、上下文、指标、异常、报告入口五层。
- API 增加“触发方式”，区分手动、定时和保存任务触发；无任务快照显示“未保存任务”。
- UI 增加 Sonic 测试套名称，保留设备、模块、异常说明和平台/Sonic/Midscene 报告入口。
- 应用统一为“智小白3D”，家用/共享从项目名、Sonic 测试套和模块中识别并单独展示，不再把业务当应用。

验证生成的四类标题：

- `✅ 智小白3D｜家用｜UI 自动化｜基线回归通过`
- `❌ 智小白3D｜共享｜UI 自动化｜基线回归未通过`
- `✅ 智小白3D｜家用｜API 测试｜基线回归通过`
- `❌ 智小白3D｜共享｜API 测试｜基线回归未通过`

本轮没有真实发送飞书消息。部署后需分别执行一条 UI 基线和一条 API 基线，确认飞书客户端的多行字段、机器人显示名称和精确报告链接；如果 UI 与 API 仍使用同一个机器人名称，应调整对应 Webhook 配置，而不是再次混改卡片渲染器。

## 范围与方法

- 线上页面：`http://101.34.197.12:8088/task-manager.html`
- 账号状态：用户已协助完成登录；使用新页面逐项进入 Agent、用例、执行、报告、配置入口。
- 检查维度：首次进入、列表扫描、筛选定位、详情查看、历史操作、配置入口、失败反馈、长列表性能和窄屏布局。
- 破坏性操作边界：走查允许创建临时数据；删除既有记录和真实发送飞书仍保留页面内二次确认，本轮未代用户确认发送外部消息。

## 现场证据

1. Agent 运行记录一次渲染 26 张完整卡片，页面 DOM 约 4583 个节点、367 个事件监听器；每张卡片包含结果、轨迹和操作，缺少搜索、状态筛选和分页。
2. Agent 工作台的原生模型下拉会在首屏加载完整模型目录，模型较多时既增加请求和 DOM，也不利于用户快速选择默认策略。
3. “应用配置”进入后直接弹窗，“执行环境”进入后自动触发 Sonic 全量扫描，“群通知”和“缺陷草稿”只有说明页；导航名称与实际页面职责不一致。
4. 执行报告最多一次渲染 200 行，失败任务工作台最多一次渲染 80 个任务；历史记录缺少组合筛选和分页。
5. 登录失败后再成功，旧错误 Toast 可能继续悬浮；新建模块、任务和上传文件的服务端失败被吞掉，页面仍本地添加并显示成功。
6. 主页面依赖 Google Fonts，内网或受限网络会让静态资源加载受到外部站点影响。
7. 本次复查使用新 Playwright 浏览器登录线上页后，Agent 工作台首屏仍能看到大量 AI Gateway 实时目录模型选项；这说明模型目录仍可能在普通渲染路径被拉取并进入下拉。
8. 本次复查进入用例/执行相关页面后，网络记录出现大量 `/api/yaml-stats?module=...` 串行请求，每个模块一次；436 个 YAML 的统计预热被拆成几十个请求，刷新慢主要来自这个瀑布。
9. 用户重新部署后再次用新浏览器登录线上页，`task-manager.html` 仍引用 `20260826-platform-management-ux` 静态版本；浏览器继续下载旧 `agent-workbench.js` 和 `agent-status.js`，所以线上仍会请求 `/ai-gateway/ai/providers`、`/ai-gateway/ai/model-router`，并继续出现逐模块 `/api/yaml-stats?module=...` 请求。
10. 新开 `/api-test/` 标签页会先跳到 `task-manager.html?return_to=%2Fapi-test%2F` 登录；登录成功后停留在管理台而不是回到 API 测试页，导致用户需要重新点击 API 测试入口。
11. “预览计划”使用浏览器原生 `alert()` 展示长文本，内容不可复制，且会阻塞页面继续操作；这在真实点击时比普通页面弹窗更不友好。
12. 部分空状态仍指向“系统设置”，但当前导航中实际入口叫“环境体检”，会让用户按提示找不到对应页面。

说明：浏览器自动化控制链本身的等待时间不计入产品加载性能；上面的 DOM、入口行为和渲染数量来自页面状态与代码路径交叉验证。

## 已实施

### 列表与历史操作

- Agent 运行记录增加任务/应用/结果搜索、结果状态筛选、Agent 模式筛选和每页 8 条分页。
- 执行报告增加任务/应用/报告搜索、执行状态、失败归因筛选和每页 15 条分页。
- 失败分析任务增加搜索和每页 12 条分页。
- 报告与失败分析按需读取最近 500 条 Runner 和 200 条生成任务；页面明确展示当前可搜索范围，服务端同时返回是否仍有更早记录，避免把前端分页误解为全量历史。
- 筛选栏保持稳定尺寸，小屏自动单列；长列表不再一次性创建全部详情 DOM。

### 工作台与性能

- 工作台首屏只加载自动策略和已配置的 AI Gateway Provider；完整模型目录改为用户点击“加载更多模型”后按需获取。
- 复查后进一步收紧 Agent 模型选择器：普通工作台渲染不再请求 `/ai/providers`，只保留“自动（按模型策略）”和已缓存选择；点击“加载更多模型”时才同时读取 AI Gateway Provider、模型路由和 Task 服务端模型目录。
- YAML 等级统计预热从逐模块请求 `/yaml-stats?module=...` 改为一次读取 `/yaml-stats` 后填充缓存，避免进入资产/执行页面时产生几十个模块统计请求。
- 移除 Google Fonts 依赖，改用系统中文字体和系统等宽字体。
- 所有本轮修改的静态资源统一更新缓存版本，部署后无需依赖用户手工清缓存。
- 重新部署复查后将静态资源版本再次提升为 `20260826-redeploy-audit`，覆盖 `agent-workbench.js`、`agent-status.js`、登录和相关管理页脚本，避免浏览器继续命中旧 JS。
- 登录区改成真实表单，支持回车提交；成功登录后会解析安全的同源 `return_to` 并跳回原目标页，例如 `/api-test/`。
- Agent 启动前预览改成页面内弹窗，展示模式、应用、输入来源、风险和平台门禁，并提供“复制预览”。
- 环境相关空状态和工作流标题统一为“环境体检”，不再把用户引向不存在的“系统设置”入口。

### 配置与导航

- 应用配置、群通知、执行环境改成独立状态页；编辑继续复用原应用配置弹窗。
- 进入执行环境不再自动扫描 Sonic，快速体检、深度体检和旧步骤扫描均为明确按钮动作。
- “设备连接”改为“执行环境”，“系统设置”改为“环境体检”。
- 运行记录、待确认、失败报告和待确认缺陷草稿增加侧栏计数；导航分组展开状态和最后管理页可恢复。

### 缺陷草稿闭环

- Agent 产品缺陷和失败分析生成的草稿会真实持久化，不再只存在当前浏览器或单次 run artifact。
- 新增缺陷草稿列表、状态/关键字筛选、复制、拒绝、来源执行 ID、报告链接和人工确认发送。
- 草稿发送时按应用包名解析对应 Webhook；发送成功、失败、拒绝均保留状态和操作信息。
- 草稿提交和拒绝只接受已验证管理员会话，Runner Token 无权触发外部发送；操作人由后端会话取得，不接受浏览器请求体伪造。
- 草稿写入和发送使用线程锁与进程文件锁，临时文件名唯一；同一草稿的并发提交只能发送一次。飞书 `code / StatusCode` 的数字和字符串成功码统一识别，避免消息已送达却仍显示失败并诱发重发。
- Agent 失败任务和模型轨迹随草稿保留。
- 真实发送前保留二次确认，不会因进入页面或生成草稿自动发群。

### 结果真实性

- 新建模块、任务和上传 YAML 的服务端错误不再被吞掉；失败时停止本地更新并显示具体错误。
- 登录成功会清理旧登录错误和 Toast，避免成功状态仍展示失败提示。

## 暂缓与原因

- 后端历史接口仍以有限条数返回，前端已控制 DOM 数量；真正的游标分页需要统一 Agent run、job 和报告存储协议后再做。
- 缺陷草稿当前沿用带跨进程文件锁的服务端 JSON 持久化，适合现有单机部署；多主机共享部署前应迁移到数据库并增加全局幂等键。
- 本轮未真实提交飞书卡片，也未删除线上既有运行记录；相关流程通过单元测试、静态检查和页面二次确认验证。
- 旧页面仍保留部分 emoji 导航图标和历史样式，未在本轮做全站视觉重构，以免扩大回归范围。

### 新发现与已实现

1. 登录、Agent 历史、Jobs 和模型配置存在重复请求；已增加进行中请求复用，并移除登录后的重复加载。
2. Agent 详情读取会触发全量陈旧记录恢复并争用共享锁；已改为只读持久化详情，失败时保留摘要并提示降级。
3. 历史记录缺少批量处理且被无关执行侧栏压窄；已支持当前页全选、清空选择、批量删除终态记录，并在历史和待确认页隐藏执行侧栏。
4. “失败重跑”只有分析和修复，没有重跑闭环；已增加筛选、分页和二次确认后的真实重跑动作。
5. 用例资产加载时先显示 0，再变成 437，容易被误判为空；已先显示加载态。执行页 437 条 YAML 和长原始错误一次性渲染，已改为搜索、每页 30 条和截断摘要。
6. 新建 YAML 固定设备 ID 且包含空 action；已改为设备中立、可直接填写的 `ai` / `aiAssert` 模板。
7. 模型目录约 200 项、应用模块约 100 项均缺少定位能力；已增加搜索，并突出应用模块已归属、总数和未归属统计。
8. 缺陷草稿进入时等待接口完成才换页，用户会短暂看到上一页报告；已改为先渲染草稿加载页，失败可在本页重试。
9. Trace、Sonic、安装包和 Runner 共用“还没有执行报告”空状态；已按各自功能提供独立下一步提示。
10. 英文装饰标题、纯数字步骤和原始失败代码影响理解；已改为中文业务标签，HTTP、JSON、Cron、Webhook 等必要技术词保留。
11. API 测试当前环境是“生产环境（新）”，但多个入口可直接发请求；已在环境栏持续标识生产风险，并为调试、任务、基线、定时手动执行、历史重跑和步骤预览增加统一确认，说明环境、对象、数量和真实请求后果。
12. API 步骤预览需要执行上游请求，却被设计成无风险预览；已纳入执行确认，并把用例管理页缺失的环境上下文传入步骤编辑器。任务执行取消确认后不会先保存任务范围。

## 2026-08-27 所属业务创建与通知闭环

### 发现的问题

- 平台只有“智小白3D”一个应用，但历史卡片、项目名和用例名称把“家用/共享”混入应用字段，通知无法稳定区分应用与业务。
- 只在生成后编辑单条 UI 用例业务不够便捷；一次批次通常包含同一业务，逐条标记重复且容易遗漏。
- 全自动 Agent 也是 UI 用例创建入口，如果只修改“新建自动化测试”弹窗，会产生两套创建合同。

### 已实施

- “应用配置”增加可配置业务线：默认家用/共享，只输入中文名称，可新增、重命名和停用；平台生成稳定内部 ID，页面不要求用户填写英文。
- “新建自动化测试”固定展示应用“智小白3D”，按启用配置动态渲染无默认值、必选的业务分段控件；整批继承，单条可改。
- Agent 执行配置增加同一业务字段，计划预览显示中文业务；用户去安装 App 再返回时保留当前草稿，启动后清空，避免下一次静默沿用。
- UI 生成请求、后台任务、资产元数据、用例 JSON、生成汇总和任务元数据贯通 `business`；重新生成继承原批次，历史未标注批次要求补选。
- API 用例保存、执行快照、基线与定时目标加载同一业务配置；UI/API 通知优先使用执行时快照并按配置解析中文名，避免类型混用。
- Sonic 直生成短链路使用真实稳定 case_id 保存业务；没有向 Midscene YAML 增加 `business` 字段。
