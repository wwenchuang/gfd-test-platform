# UI 中断执行的人工停止核对

本功能是异常恢复的次级操作。正常测试继续使用开始、取消、报告和重跑；T4b1 的 `ui_process_stop_proof` 能力检查仍然必须通过。

当旧执行丢失回执、执行器崩溃或领取响应丢失，平台继续保留已领取手机的租约。不要把关闭浏览器、手机离线或等待超过 120 秒当成执行已停止。执行者应先到该执行机，核对本次任务及它启动的全部子进程确实结束；不能只核对父进程，也不能停止其他任务的进程。

平台在已中断且仍有已领取租约的尝试上显示“核对停止状态”；取消中的尝试需要超过现有 120 秒回执丢失阈值才显示。具有 `ui.execute` 权限的本人可处理自己的批次；超级用户可处理其他执行者的批次，但仍需当前应用权限。普通查看者无此操作。

展开对应用例，核对显示的手机和应用，点击“核对停止状态”，勾选“已在执行机确认该任务及其子进程已结束”，提交“确认已停止”。勾选默认关闭；取消或按 Escape 不发送恢复请求。若核对期间状态、回执或租约变更，平台返回冲突并刷新，请重新核对。

确认后，平台在同一 SQLite 事务中写入操作人、时间、原因、批次/尝试/任务/手机/执行器绑定，撤销旧领取凭据，并只释放匹配的租约。平台详情标记“人工确认停止”，中断保留中断，取消保留取消；绝不转为通过。后台同步旧 Job 和重新生成本次报告；已冻结报告版本、已存在附件、通知记录保持完整。旧凭据的后续进度、结果和上传被拒绝。人工确认不会自动重跑；需要测试时再明确开始或重跑，生成新的批次、尝试和领取凭据。

## 发布与回退

随平台常规发布更新后端、`js/ui-batch-view.js`、`js/ui-test-home.js` 和 `css/ui-simple.css`，保留 `UI_SIMPLE_FLOW_ENABLED` 既有开关及访问策略。不要只发布页面按钮。服务首次访问会在私有 UI SQLite 中将 `user_version` 从 3 升至 4，新增有索引的审计表；历史快照、私有附件、分片和通知 outbox 不删除。发布前按现有程序备份私有数据库。旧服务版本不能打开 schema 4，回退必须协调兼容代码与数据库恢复，不能为回退删除审计记录或降低版本号。

本任务不提供持久化领取日志、启动时自动核对进程或自动恢复。Runner 崩溃后的自动证明仍是后续工作。上线验收需要在两种执行机上验证真实任务及子进程停止、人工核对、同机后续运行、旧回执及上传拒绝，并核对平台详情与报告结论。本次本地自动化测试不替代真实执行机验收。
