# 接口清理历史证据的服务端读取

测试工作台可读取 `scheduled_cleanup_diagnostics.py` 生成的脱敏诊断快照，展示属于同一次定时执行且证据完整的记录。该功能只读，不触发接口测试；没有配置或证据不完整时显示“暂不可用”。

管理员需将现有诊断原始 JSON 放到服务进程可读取的私有目录，不能放在网页静态目录，并设置服务进程环境变量 `TASK_PRACTICE_CLEANUP_EVIDENCE` 为文件的绝对路径。文件必须为普通文件，不可为符号链接，不可被用户组写入或被其他用户访问；例如归属服务用户、权限 `0600`。服务运行在容器中时需通过受限只读挂载提供，不能假设宿主机路径在容器内可见。部署前需核实文件来自已保存的诊断快照且服务可读；不要在文件中添加请求、响应、变量名或变量值。

一种可选部署方式是使用服务专属的宿主机目录 `/var/lib/midscene-practice-evidence`，而非 Web 根目录；由管理员先确认容器内实际运行 UID/GID，并让该目录仅对相应服务账号可读和可遍历。可使用目录权限 `0750`、文件权限 `0640`，组写入及其他用户访问必须关闭；若目录和文件归服务用户所有，也可分别使用 `0700` 与 `0600`。实际账号与既有部署方式须现场确认，不要假定容器使用宿主机同名用户或能够读取管理员个人目录。

容器示例应在现有 Task Server 服务的 Compose 配置中将私有**目录**只读挂载，例如宿主机 `/var/lib/midscene-practice-evidence:/run/practice-evidence:ro`，并在该服务的环境项设置 `TASK_PRACTICE_CLEANUP_EVIDENCE=/run/practice-evidence/cleanup-diagnostics.json`。先核对 Compose 实际文件、服务名、UID/GID 和只读挂载，再在合适的发布窗口按现有部署流程重建相关服务容器；改变容器启动环境或挂载需要重建服务，可能短暂中断服务。文件内容每次请求重新读取，同目录原子替换快照不需要重启。上面是示例，当前未配置或上线。

更新快照时，先在私有目录备份上一份文件并保留同等权限；将新文件写入同目录临时文件，核验诊断来源、SHA-256 与原始受限快照一致，并检查只包含诊断脚本允许的结构、状态和输出有无，不包含变量名/值等敏感数据。确认属主和权限后以同目录重命名原子替换目标文件，避免读取到半写文件。需回滚时，把受限备份复制为同目录临时文件，校验哈希及权限后再次原子替换；目录挂载保持只读。若原诊断不完整、权限错误、服务不可读或记录已不可访问，保留“暂不可用”，不要手工补写通过状态。

接口每次请求检查活动个人账号、平台配置与 API 查看权限，并使用 API 执行记录现有权限规则检查全部执行用例的项目和环境；用例环境版本必须与所属执行一致。任一记录无权查看、环境版本不一致、记录消失、文件权限不安全或数据库不可用均隐藏整个摘要。接口仅返回执行编号、历史时间和白名单摘要，响应禁止缓存；文件中的任务编号、用例编号和清理步骤细节不会传给浏览器。

诊断原本没有重新确认定时任务当前成员；历史的正常路径和非空提取不证明业务数据归属、资源物理清理或异常恢复，也不证明新的清理链候选已上线或适合上线。此项说明和授权的原执行链接不能替代生产兼容性验收。
