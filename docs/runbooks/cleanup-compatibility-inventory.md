# 清理链兼容性只读盘点

本工具是候选清理链保护的上线前静态排查辅助，不能证明业务数据归属、生产数据已清理或变更适用于全部真实运行。盘点不发业务请求，不修改任务、用例、基线、调度或数据；查询在 PostgreSQL 只读、可重复读事务内执行，每条语句超时 5 秒，结果仅含用例版本 ID、总数及结构布尔值。

范围为所有活动基线引用的用例版本，加上**存在启用定时任务的项目中的全部用例版本**。该范围刻意包含非定时用例和历史版本，尚未解析每个定时任务的精确成员；多项命中并不代表它们均在定时任务中。范围外的手动运行和其他未来用例未检查；输出 `indeterminate: true` 时必须人工复核，不得当作无风险。已启用的调度项目中的损坏引用、外部依赖、业务级默认值及运行时覆盖也无法凭结果证明安全。

`multi_cleanup` 为至少两步启用的清理，`earlier_output` 为其前面某步存在提取，`optional_or_default`、`conditional`、`pre_alias`、`polling` 分别表示配置结构中存在可选或默认提取、条件、前置复制/编解码、多次轮询。它们是结构提示，不证明变量确实由后续清理使用。结果不包含请求模板、变量名和值、密钥、响应及用例名称；扫描过程中脚本会在内存短暂读取 `processing_spec`，不持久化原始配置。

在目标服务器的受限环境使用配置好的只读数据库账号（按现网凭据管理方式注入 `API_TESTING_DATABASE_URL`，不要把 URL 写进命令、日志或聊天），从源码根目录运行：

```bash
python3 scripts/audit_cleanup_compatibility.py
```

使用的账号必须对 `api_cases`、`api_case_versions`、`api_baselines`、`api_scheduled_jobs` 具备 SELECT 权限；推荐数据库层也限制账号为只读。依赖 `requirements-api-testing.txt` 中的 psycopg 3。异常只显示通用错误，避免泄露连接串，退出码非零代表盘点未完成。请先验证输出范围，再按实际定时任务目标逐项确认命中版本的清理依赖和残留处理，兼容性未确认前不应将候选保护直接部署。
