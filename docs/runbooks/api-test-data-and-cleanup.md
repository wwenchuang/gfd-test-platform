# 接口测试数据与清理操作指引

适用于现有功夫豆测试平台的接口测试。当前 3D 家用业务使用生产环境；先确认执行环境、接口用途与资源归属，再运行测试。记录运行标识，不要在文档、用例名称或日志中写入真实个人信息、密码、Token 或密钥。

## 一次测试怎么做

1. **确认范围。** 在「接口资产」确认项目、接口版本和执行环境；检查目标用例的主请求、前置及清理步骤，识别是否会写入、发送消息或操作设备。不能确定副作用时先查清，不以 HTTP 方法推断安全。
2. **准备数据。** 确认本轮测试账号有使用权限、字段符合实际业务规则。文本预览的 seed 和数据编号可用于复现文本，但它们不会自动成为执行编号，也不能单独证明资源唯一或轮次隔离。
3. **运行并核对。** 检查实际请求、业务响应和断言，不只看 HTTP 状态；保存平台执行记录链接。生成或引用测试资源时，只记录本次响应或可信步骤中得到的唯一标识及其归属。
4. **核对本轮清理。** 在「执行记录 → 用例明细」查看主体和清理步骤，确认清理请求的资源标识与本轮创建结果一致，再通过真实业务支持的查询核对状态。删除步骤通过、查询不可见或标记删除都不等于物理删除或关联资源已清除。
5. **清理失败或结果不明。** 保留执行编号、失败步骤和脱敏证据，停止重复写入和清理；先查清实际状态和资源归属。响应丢失、超时或任务中断时，如果无法唯一确认本轮资源，不按最新记录、列表位置或范围进行删除。不能确认归属的项目标记待排查，不标为通过。

- 反馈分类只读用例执行 `1eb0c640-d78a-41f9-b441-02785fd87e1c`：2026-11-06 返回 HTTP 200、业务码 0，3 条断言通过。这是一次结果，不证明其他接口或后续运行通过。
- 会话创建及清理执行 `0157b386-1475-4946-aae8-1664498ecc69`：经授权的单次生产执行按创建响应中的会话标识做了标记删除，随后详情不可查询；关联资源及物理删除没有证实。不要把此历史记录视为后续测试的清理证明。

## 串行、并行和异常测试

- 本轮生产写入资源的响应丢失后，现有证据不足以按请求号唯一找回，故不开展重复创建、并发或自动恢复清理；也不以先前单次成功证明幂等。
- 数据工厂、账号隔离和小规模并发需要能够识别各轮资源、证明账号隔离，并能定向清理及处理异常后才能计为通过。静态预览、不同文本编号或本地模拟结果都不能替代真实业务资源隔离证据。
- 对外部依赖构造 400、500、超时、断连及坏 JSON 时，记录具体注入位置和观察到的结果。仅客户端的受控测试不能证明业务应用本身的异常路径已验证；对照真实接口定义保留独立的契约检查。
- 证据应包含环境、版本、时间、执行编号、实际结果及清理状态；暂不可验证的条目保留为未完成，不以已有回归总数冒充本次验收。
