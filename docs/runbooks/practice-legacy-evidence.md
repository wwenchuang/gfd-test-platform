# 历史实战记录授权与旧静态资源处置

实战页历史业务记录在服务端按每条执行的项目和环境权限核验；还核对执行的子用例数量及其环境版本与父执行一致。任一执行失权、记录缺失、子用例与环境不一致或授权子进程超时，该记录不返回编号和摘要。权限变更时网页立即清空旧内容；按需重新读取不会发起业务测试。记录是历史审计摘要，不能代替原执行明细或异常路径验收。

## 发布前

1. 从远端最新主线合并本功能和未授权 POST 返回值保护，重新检查相关文件及在线版本，避免与并行发布交叉覆盖。后端需与新页面一起发布；如果服务端未提供授权接口，网页显示不可用，而非回退到硬编码的结果。
2. 只读盘点真实线上所有静态服务根目录、容器、CDN 和回源缓存；枚举 `ui-simple-entry` 的现行、历史哈希和非哈希资源，以内容匹配或审计过的哈希清单确认哪些包含真实历史编号或业务摘要。检查首页和本地缓存策略，不打印脚本内容及编号。不假定单个 nginx 容器覆盖全部入口。
3. 保留受限的服务器备份、资源清单、文件哈希和权限；确认所有任务空闲、排他发布窗口、服务健康及可回滚策略。旧版代码备份不能保存在静态 Web 根目录或仍可匿名读取的位置。

## 切换与核验

1. 更新后端，并在有权限、缺项目权限、缺环境权限、权限被撤回和执行子项环境错配等情况验证接口；无权限响应及超时均不含历史编号或摘要，HTTP 响应为 `private, no-store`。只核验已存记录，不新增业务请求。
2. 发布不含历史编号和业务摘要的新 JS/HTML。发布后对每个静态根目录及容器中**所有命中的旧版本**禁止再次读取（例如在每个入口配置精确 410，并核验非匹配请求不受影响；或将命中资源移至受限备份）。不能只替换当前引用的一个哈希文件；SPA 的 `try_files` 回退也必须对这些路径返回 404/410，而不是旧内容或 200 页面。针对同名非哈希路径也需核验其现有内容已被安全版本替代。
3. 无认证地逐个请求经盘点的旧哈希与源路径，确认不再返回旧 JS 或历史编号；同时以授权账号验证新页面可正常打开历史记录，受限账号/撤权后不可读，刷新与原执行链接正常。再复查 CDN 或反向代理直接入口。旧标签可能继续使用已缓存脚本或在移除旧文件后加载失败；提示用户刷新以获得新版本，不能为兼容而把旧脚本重新公开。
4. 浏览器或第三方已经下载的旧资源无法由本次发布收回；服务端撤销历史路径和刷新不能消除已复制的数据。按实际部署范围记录尚未清理的缓存、入口和第三方副本，不将新源码合并或网页显示为权限整改完成的证据。

新代码有权读取记录时仅展示其对应的历史执行，读取失败统一提示不可用或无权；不会因授权失败而泄露默认编号。该保护依赖同时发布的 `week2-real` POST 去标识修复，不能仅发布本页面改动后宣称全部接口安全。
