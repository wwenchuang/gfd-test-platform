# API 性能测试平台设计

## 背景与目标

现有 API 平台已经具备项目、Apifox 接口资产、环境与密钥、功能用例、基线、任务、执行记录、SSE、报告、定时任务、权限和飞书通知。性能测试应复用这些上下文，但不能把当前面向功能验证的 `HttpExecutor` 简单改成并发循环：功能执行按步骤保存完整证据，高并发会产生不可控的数据量，而且执行器本身会成为压测瓶颈。

本功能在现有 API 平台中增加独立的性能测试域，使用固定版本 k6 产生负载。平台负责场景、环境、权限、调度、状态、指标汇总、报告和 AI 诊断；Docker 压测 Agent 负责执行 k6。第一版允许一台 Agent，协议和数据模型同时支持多 Agent 分片，新增服务器只需部署并注册 Agent，不需要修改场景或平台代码。

目标如下：

- 同时支持单接口极限压测和完整业务链路并发压测。
- 支持固定并发、阶梯并发、固定到达率和阶梯到达率。
- 所有平台环境均可选择，不按环境类型硬限制压测；生产环境保留现有 `api.production` 权限和明确风险确认。
- 压测能力取决于已注册 Agent 的容量，可通过增加 Agent 横向扩展。
- 主平台所在机器默认只作为备用 Agent，不能被自动分配大量压力。
- 实时展示实际负载、延迟、错误、业务断言、丢弃迭代和 Agent 资源。
- 报告必须分别判断“目标负载是否达到”和“服务阈值是否通过”。
- AI 基于确定性统计证据诊断瓶颈，不能替代原始指标或无依据猜测根因。

## 非目标

第一版不包括：

- 浏览器页面压测、移动端 UI 压测或 Sonic 设备并发。
- Grafana Cloud 等商业托管平台依赖。
- Kubernetes Operator。
- 用户任意编写并执行 k6 JavaScript。
- 多地域网络模拟。
- 自动扩容云主机。
- 定时压测和持续性能门禁。
- 自动中断已运行的低优先级任务来抢占资源。
- 对真实打印、设备控制、支付、短信、删除非本轮数据或高成本 AI 接口开放默认压测。

## 核心设计决策

### 独立执行域

性能任务不创建 `ApiExecution` 和逐请求 `ApiExecutionAttempt`，也不进入当前 `api-testing` Celery 队列。新增性能场景、运行、Agent、分片和指标模型，内部协调可继续使用 Redis，但远程 Agent 只通过平台 Agent API 通信，不直接连接 PostgreSQL 或 Redis。

### k6 Docker Agent

每台压测服务器运行一个 `midscene-load-agent` 容器。镜像包含固定版本 k6 和轻量控制进程，负责注册、心跳、领取分片、生成临时工作目录、启动 k6、聚合输出、上报指标、响应停止命令和清理临时文件。

Agent 使用出站连接访问平台，因此不要求压测机开放入站管理端口。新服务器需要一次性安装 Docker 并运行平台生成的注册命令；注册后，节点选择、优先级、任务分配和软容量均在平台配置。

### 不存储逐请求明细

k6 指标通过管道进入 Agent 本地聚合器。Agent 每 5 秒上报指标桶，运行结束后上报最终 summary。平台只保存聚合数据、有限失败样本、有限慢请求样本和事件，不把每个请求写入 PostgreSQL。

### 规则诊断优先于 AI

报告服务先计算目标达成、阈值、拐点、错误类型、慢步骤、节点容量和历史变化，再把结构化证据交给 AI。AI 失败时，完整统计报告仍可使用；AI 诊断失败不改变性能运行结果。

## 用户操作流程

API 平台新增一级导航“性能测试”，包含以下页面：

1. `压测场景`：创建、编辑、复制、校验、版本和归档。
2. `压测任务`：创建运行配置、选择节点并启动。
3. `压测节点`：注册、查看心跳、设置调度级别和容量。
4. `执行记录`：查看排队、预检、实时运行、停止和历史状态。
5. `性能报告`：指标、阈值、节点、失败样本、对比和 AI 诊断。

创建场景使用五步向导：

1. 选择“单接口”或“业务链路”。
2. 从接口资产或现有功能用例复制请求、前置步骤、变量提取、断言和清理步骤。
3. 配置数据池、变量作用域和数据唯一性。
4. 执行静态校验和单用户预检。
5. 保存不可变场景版本。

创建任务使用五步向导：

1. 选择场景版本和环境版本。
2. 选择负载模型并填写目标。
3. 配置性能阈值和自动停止规则。
4. 选择节点策略、是否允许备用节点及任务优先级。
5. 查看容量估算、预计请求量、风险提示并确认运行。

任何保存、预检、启动、停止、重新诊断和归档动作都必须有成功或失败反馈；列表刷新后仍能看到最终状态。危险操作使用二次确认，但确认框本身不作为执行完成证据。

## 场景模型

### 单接口模式

一次迭代执行一个目标接口。支持环境变量、数据池变量、请求头、查询参数、路径参数、请求体、业务断言和响应变量提取。主要用于容量上限、延迟拐点和单接口回归。

### 业务链路模式

一次迭代代表一个完整业务流程，按顺序执行多个步骤。步骤支持：

- `setup_once`：由控制服务在所有分片开始前执行一次。
- `agent_setup`：每个 Agent 分片开始前执行一次。
- `vu_once`：每个虚拟用户第一次迭代前执行一次。
- `iteration`：每轮用户流程执行。
- `cleanup_once`：所有分片结束或停止后，由控制服务执行一次。

链路中的提取变量只能向后引用。写操作必须标记本轮数据归属并提供清理路径；清理在主体断言失败时仍会尝试。Agent 在运行中持续上报已创建资源的归属标识，以便节点丢失后由控制服务执行补偿清理。

### 从功能用例复制

功能用例是创建性能场景的来源，不是运行时引用。复制后形成独立的场景版本快照，避免功能用例后续更新改变历史压测。系统根据接口标签和工作流策略标出：

- 可直接压测。
- 需要数据池或幂等键。
- 需要可验证清理。
- 默认禁止压测。

真实打印、设备动作、共享支付、短信验证码、删除非本轮数据和高成本 AI 任务默认禁止。管理员能看到原因，但第一版不提供绕过按钮。

### 数据池

第一版支持 CSV 和 JSON 数组。数据在保存时校验字段、行数和编码，运行时按 Agent 分片和 VU 确定性分区，避免多节点重复使用同一条唯一数据。

支持三种取数方式：

- 循环共享：允许重复，适合只读查询。
- 每个 VU 固定一行：保持用户身份或会话稳定。
- 每次迭代独占一行：数据耗尽时停止分配并在报告中说明。

密钥、Token 和密码继续来自环境资产，不能上传到普通数据池。

## 负载模型

第一版提供四种模型：

| 页面名称 | k6 executor | 主要参数 | 用途 |
| --- | --- | --- | --- |
| 固定并发 | `constant-vus` | VU、持续时间 | 模拟固定并发用户 |
| 阶梯并发 | `ramping-vus` | 多阶段 VU 与持续时间 | 找并发拐点 |
| 固定吞吐 | `constant-arrival-rate` | 每秒迭代数、持续时间、预分配 VU | 保持目标 QPS/链路吞吐 |
| 阶梯吞吐 | `ramping-arrival-rate` | 多阶段目标速率 | 找吞吐上限和退化阶段 |

页面不使用 k6 全局 `--rps`。链路模式的“目标 QPS”明确表示每秒完整链路迭代数，同时单独统计链路内各接口的实际请求速率。

预检先以 1 VU 执行一次完整迭代，确认请求、提取、断言和清理都成立，并利用预检耗时估算到达率模式所需 VU。用户可以在容量不足时保存配置或继续执行，但页面必须标记“预计无法达到目标”，运行结果不得显示为通过。

预检必须同时确认所有选中 Agent 的本地校准有效，并从每台节点完成目标地址连通性检查。容量不足可以由有执行权限的用户明确选择“仍然执行并记录为证据不足”；校准无效、版本不匹配或目标地址不可达属于硬阻断，不能绕过。

## 多 Agent 调度与优先级

### 节点调度级别

每个 Agent 具有一个调度级别：

- `preferred`：首选节点，自动调度优先使用。
- `normal`：首选容量不足时使用。
- `fallback`：只有任务明确允许备用节点时才使用。
- `disabled`：只保留注册信息，不领取任务。

主平台所在服务器默认是 `fallback`。专用压测服务器默认是 `preferred`。

### 节点容量

每个 Agent 同时维护两类上限：

- 本地硬上限：容器 CPU、内存、最大 k6 进程数、最大 VU、最大迭代率和最长运行时间。平台不能突破。
- 平台软上限：管理员在节点页配置，必须小于等于 Agent 上报的硬上限。

Agent 上报 CPU、内存、磁盘、出口 IP、k6 版本、Agent 版本、当前分片和最近心跳。低可用内存、磁盘不足、版本不兼容或健康检查失败时，调度器不分配新任务。

新节点注册成功不代表已经具备可信压测容量。Agent 必须先运行不访问业务系统的本地 k6 校准，测量可持续虚拟用户、迭代率、CPU 和内存峰值，并把 Agent 版本、k6 版本和硬件签名一起保存。校准在七天后过期；Agent/k6 版本或硬件签名变化时立即失效。平台的实际可调度容量取本机硬上限、平台软上限和有效校准容量三者的最小值。未校准、校准失败或校准过期的节点只能查看和重新校准，不能领取正式任务。

每次正式运行的预检还会从所选 Agent 检查目标环境的 DNS、连接/TLS 和单链路耗时，用真实预检耗时估算到达率所需 VU。这一步只验证连通性和低负载业务正确性，不把目标服务的表现混入节点本地校准。节点页和运行确认页分别显示“未校准 / 校准中 / 校准有效 / 已过期 / 校准失败”、最近校准时间、校准容量、当前可用容量和中文处理建议。

### 任务节点策略

任务支持：

- 自动选择：按调度级别、健康、可用容量和当前负载选择；默认不使用备用节点。
- 指定节点：用户选择一台或多台 Agent。
- 指定节点组：按标签选择，例如“腾讯云压测节点”。

分片前显示每台节点预计承担的 VU 或迭代率。控制服务使用同一全局分片序列为每台 k6 进程生成不重叠执行片段，数据池也按相同片段分区。某节点中途离线时，第一版不自动把剩余压力迁移到其他节点，避免服务突然承受额外负载；运行转为降级状态，报告标记未达到完整目标。

### 任务队列优先级

任务优先级为 `urgent`、`high`、`normal`、`low`，只影响等待任务的领取顺序，不抢占已经运行的任务。同一项目默认只运行一个性能任务；管理员可在容量允许时调整项目并发上限。

## 运行状态机

运行状态与性能结论分离。

运行状态：

```text
draft -> preflighting -> queued -> starting -> running -> stopping -> finished
                                   |          |           |          |
                                   +----------+-----------+-> failed
                                              +--------------> cancelled
```

- `preflighting`：静态校验、单用户执行、节点容量和目标可达性检查。
- `queued`：配置有效，但等待 Agent 容量。
- `starting`：分片已分配，等待所有选中 Agent 确认。
- `running`：至少一个分片运行；页面显示已启动和计划节点数量。
- `stopping`：用户停止、阈值自动停止或系统保护触发，等待 Agent 优雅退出。
- `finished`：所有分片正常结束。
- `failed`：启动失败、所有 Agent 丢失或平台无法形成有效报告。
- `cancelled`：运行未开始即取消，或运行中停止后完成收尾。

性能结论独立为：

- `passed`：目标负载达到且所有必选阈值通过。
- `failed`：目标负载达到，但至少一个必选阈值失败。
- `inconclusive`：目标负载未达到、节点丢失、数据耗尽或证据不足。

停止任务时，控制服务向所有分片发送停止指令；Agent 对 k6 发送优雅中断，超过宽限时间后强制结束。无论正常结束还是停止，都要上传已有指标、执行允许的清理并形成报告。重复停止请求必须幂等。

## 指标与报告

### 实时指标

Agent 每 5 秒上报：

- VU、迭代开始数、完成数和 `dropped_iterations`。
- 总请求率和按接口/步骤的请求率。
- HTTP 2xx、3xx、4xx、5xx和网络错误。
- 业务断言成功率与链路成功率。
- `p50`、`p90`、`p95`、`p99`、平均和最大响应时间。
- 发送与接收字节数。
- Agent CPU、内存、磁盘和进程状态。

时间桶包含 `run_id`、`shard_id`、`agent_id`、`scenario_step_id` 和时间窗口，写入使用幂等唯一键。重复上报覆盖同一分片同一窗口，防止重试导致汇总翻倍。

### 阈值

任务可配置：

- 最低实际迭代率或接口 QPS。
- 最大 HTTP 错误率。
- 最大业务断言失败率。
- 最大链路失败率。
- `p95`、`p99` 或最大响应时间。
- 最大 `dropped_iterations` 比例。
- 自动停止阈值及连续触发窗口。

自动停止默认要求连续三个指标桶触发，避免单点抖动导致误停。达到保护阈值时停止原因写入事件和报告。

### 报告顺序

报告按以下顺序展示：

1. 目标负载是否达到。
2. 必选阈值是否通过。
3. 负载、延迟和错误时间序列。
4. 接口和链路步骤排行。
5. 各 Agent 分片与资源状态。
6. 失败和慢请求脱敏样本。
7. 与同场景上一次可比运行的变化。
8. AI 诊断。
9. 场景、环境、负载、节点和阈值快照。

对比只使用同一场景版本或用户明确选择的兼容版本；环境版本和负载模型不同会醒目标记，不能直接给出无条件退化结论。

## AI 诊断

### 确定性证据包

报告服务先产生结构化证据：

- 目标值、实际稳定值和达成比例。
- 每个阶段的吞吐、延迟、错误和丢弃迭代。
- 首次明显退化的时间与负载。
- 最慢接口和链路步骤。
- HTTP、网络、超时、业务断言和数据池失败分类。
- 各 Agent 资源峰值与时间相关性。
- 与可比历史运行的绝对值和百分比差异。
- 有限且脱敏的错误样本。

### AI 输出

AI 返回固定 JSON 契约：

- `conclusion`：是否达到目标及主要结论。
- `bottleneck_category`：目标服务、网络、压测节点、测试数据或证据不足。
- `evidence`：引用指标、时间窗口和节点/步骤。
- `recommendations`：按优先级给出可验证建议。
- `next_run`：下一轮负载阶段、时长和节点建议。
- `confidence`：高、中、低及原因。

API 响应文本和失败样本按不可信数据处理，只进入结构化字段，不能作为提示词指令。Authorization、Cookie、环境密钥、密码和完整敏感响应不进入 AI 输入。

任务完成、失败或停止收尾后自动生成一次诊断。用户可以点击“重新诊断”，该动作只基于相同证据重新分析，不重新执行压测。每次诊断保存模型、提示词版本、证据摘要哈希、状态和时间。AI 不可用时显示明确原因和解决办法，统计报告保持可用。

## 数据模型

新增表如下，均延续现有 UUID、owner、created/updated 和乐观锁约定：

### `api_load_agents`

- 名称、状态、调度级别、节点组和标签。
- Agent 与 k6 版本。
- 本地硬上限、平台软上限和当前占用。
- CPU、内存、磁盘、出口 IP、最后心跳和离线原因。
- Agent 认证凭据只保存哈希。

### `api_load_agent_enrollments`

- 一次性注册令牌哈希、过期时间、使用状态和创建人。
- 可预设节点名称、节点组和调度级别。

### `api_load_scenarios`

- 项目、名称、类型、当前版本、状态和说明。

### `api_load_scenario_versions`

- 不可变版本号。
- 来源接口/功能用例版本快照。
- 步骤、变量、数据池契约、断言、清理、风险分类和编译器版本。
- 校验结果和最近预检结果。

### `api_load_datasets`

- 项目、名称、字段结构、行数、存储引用、敏感级别和数据使用方式。
- 数据内容不直接写入普通 JSONB 字段。

### `api_load_runs`

- 项目、场景版本、环境版本和创建人。
- 负载模型、阈值、节点策略、优先级和配置快照。
- 状态、性能结论、停止原因、时间、总指标和 AI 诊断状态。

### `api_load_run_shards`

- 运行、Agent、分片序号和全局分片序列。
- 分配负载、状态、心跳、k6 进程信息、最终 summary 和错误。

### `api_load_metric_buckets`

- 运行、分片、步骤、时间窗口和聚合指标。
- `(run_id, shard_id, scenario_step_id, bucket_started_at)` 唯一。

### `api_load_samples`

- 运行、分片、步骤、类型、耗时、状态码、业务码和脱敏摘要。
- 每种类型和步骤有固定上限，超出只累计数量。

### `api_load_events`

- 运行级有序事件，用于 SSE 和审计。

### `api_load_ai_analyses`

- 运行、模型、提示词版本、证据哈希、状态、结构化结果和错误。

## API 契约

面向用户的接口位于 `/api/api-testing/v1`：

- `/load-scenarios`：列表、新建、更新元数据和归档。
- `/load-scenarios/{id}/versions`：创建版本、详情、校验和预检。
- `/load-datasets`：上传、校验、预览字段和归档。
- `/load-runs`：创建、列表和详情。
- `/load-runs/{id}/start`：幂等启动。
- `/load-runs/{id}/stop`：幂等停止。
- `/load-runs/{id}/events`：SSE。
- `/load-runs/{id}/report`：确定性报告。
- `/load-runs/{id}/ai-analysis`：读取或重新生成诊断。
- `/load-agents`：用户侧节点列表、更新级别/上限和停用。
- `/load-agent-enrollments`：创建一次性注册令牌。

Agent 协议使用独立 `/api/api-testing/load-agent/v1`：

- `/register`：一次性令牌换 Agent 凭据。
- `/heartbeat`：状态、容量、版本和当前分片。
- `/claim`：长轮询领取分片。
- `/shards/{id}/started`：确认启动。
- `/shards/{id}/metrics`：批量幂等上传指标桶。
- `/shards/{id}/samples`：上传有限样本。
- `/shards/{id}/events`：上传运行事件。
- `/shards/{id}/finish`：最终 summary。
- `/shards/{id}/commands`：长轮询停止命令。

远程 Agent 不直接访问用户端 API，也不持有平台管理员会话。

## 权限与安全

新增权限：

- `api.loadtest.view`：查看场景、运行和报告。
- `api.loadtest.edit`：创建和编辑场景、数据池及任务配置。
- `api.loadtest.execute`：预检、启动和停止。
- `api.loadtest.manage_agents`：注册、配置和停用 Agent。

选择生产环境继续要求现有 `api.production`。项目和应用数据范围沿用现有 API 授权，后端对每个资源再次校验，前端只负责提前反馈。

Agent 注册令牌一次有效且短期过期。注册后使用可撤销 Agent 凭据，任务凭据只对一个分片和有限时间有效。环境密钥只在任务启动时通过受保护连接送达 Agent 内存，不写入生成脚本、日志、指标或工作目录；任务结束立即销毁。

当前平台公开入口仍是 HTTP。跨服务器传递环境密钥前必须满足以下之一：

- Agent API 配置 HTTPS；或
- 两台服务器通过受控私网/VPN通信，并显式启用私网传输。

不能把现有 HTTP 传输风险描述成已经解决。公网明文连接不得发送环境密钥。

## 故障与恢复

- Agent 心跳超时：分片标记 `lost`，运行结论为 `inconclusive`，不自动向其他节点补压。
- 平台进程重启：从数据库恢复非终态运行，继续读取 Agent 心跳和指标；重复上报幂等。
- Agent 容器重启：若原 k6 进程不存在，报告分片失败并上传已有数据；不擅自重启完整压测。
- 指标暂时上传失败：Agent 本地保留有界队列并重试；超限后记录丢失窗口。
- AI 服务失败：报告完成，诊断单独失败并允许重试。
- 清理失败：报告醒目标记遗留资源及拥有者标识，不能显示链路完整通过。
- 用户重复点击启动或停止：使用幂等键返回同一运行状态。

## 部署方式

仓库提供：

- `deploy/load-agent/docker-compose.yml`
- `deploy/load-agent/.env.example`
- `deploy/load-agent/install.sh`
- `deploy/load-agent/upgrade.sh`
- `deploy/load-agent/uninstall.sh`
- 节点连接和健康检查命令。

平台节点页生成包含平台地址和一次性令牌的部署命令。当前主机若部署 Agent，默认使用 `fallback`，Docker 默认限制 1 CPU、1 GiB 内存及较低 VU/迭代率；第二台专用服务器配置为 `preferred`，实际硬上限根据该服务器资源设置。

新增节点需要执行一次部署命令。以后启停、调度级别、节点组、软容量和任务选择直接在平台操作；修改容器硬资源或升级 Agent 镜像时执行平台提供的升级命令。

## 第一阶段交付范围

第一阶段一次性交付以下闭环：

- 单接口和有序业务链路场景。
- 从接口资产或功能用例复制并保存独立版本。
- CSV/JSON 数据池和确定性多 Agent 分区。
- 四种负载模型。
- Docker Agent 注册、心跳、优先级、容量和多 Agent 分片。
- 自动选择、指定节点和节点组策略。
- 预检、容量估算、启动、实时 SSE、停止和恢复。
- 聚合指标、阈值、有限样本和性能报告。
- 规则诊断、AI 自动诊断和重新诊断。
- 权限、审计、敏感信息脱敏和飞书完成通知。
- 一台 Agent 和两台 Agent 的真实执行验证。

第一阶段不加入定时压测、混合场景权重、跨地域或自动扩容。这些在基础执行和报告证据稳定后进入第二阶段。

## 验收标准

### 功能闭环

- 新人能从接口资产创建单接口场景，完成预检、配置负载、选择节点、执行、停止和查看报告。
- 新人能从现有功能用例复制业务链路，看到哪些步骤可压测、哪些被安全策略阻断以及解决办法。
- 所有按钮和状态均有可观察结果，刷新和直接链接不会丢失任务上下文。

### 执行准确性

- 使用可控目标服务验证固定 VU、阶梯 VU、固定到达率和阶梯到达率。
- 报告的请求数、迭代数、错误数和 k6 summary 一致。
- 两台 Agent 分片执行时，分片范围和数据池互不重叠，汇总不重复。
- 未达到目标负载时结论为 `inconclusive`，不能显示性能通过。
- HTTP 200 但业务断言失败时，业务失败率正确增加。

### 停止与故障

- 运行中停止能结束所有分片、保存已有指标、执行允许的清理并形成报告。
- 模拟一台 Agent 离线时，不把流量突然迁移到其他节点，报告指出缺失分片。
- 平台重启后运行状态能够恢复，重复指标不会翻倍。

### 节点保护

- `fallback` 节点在任务未允许备用节点时不被选择。
- Agent 拒绝超过本地硬上限的任务，即使平台软配置错误。
- 主平台本机 Agent 的 Docker CPU 和内存限制可以从节点页证据中确认。

### AI 诊断

- 可控慢接口、错误接口、业务失败和压测节点资源不足分别得到对应证据分类。
- AI 结论引用具体指标和时间窗口；证据不足时返回低可信度，不能编造服务端根因。
- AI 不可用时确定性报告仍完整，重新诊断不触发压测。

### 安全

- 数据库、事件、脚本、日志、报告和 AI 输入均不出现明文 Authorization、Cookie、密码或环境密钥。
- 过期或撤销 Agent 凭据无法领取任务或上传指标。
- 公网 HTTP Agent 连接不能取得环境密钥。

## 后续阶段

第二阶段增加按权重混合场景、定时压测、历史趋势门禁和更丰富的服务端观测数据。第三阶段根据实际容量需求增加多地域节点、云主机自动扩容或对接外部指标存储；这些能力不影响第一阶段的场景版本、Agent 协议和报告模型。
