# API 环境资产中心设计

## 目标

把当前“按接口版本编辑一份环境表单”的页面，收敛为按项目管理的环境资产中心。用户能先选择项目，再查看该项目已保存的环境，手动从 Apifox 更新，编辑并生成新版本，归档或恢复环境，并带着选定环境进入工作台。

本轮不实现定时调度器，但要保持数据边界稳定，使后续定时任务可以引用已保存任务或基线分组，并单独配置是否发送飞书结果。

## 核心原则

1. 环境是项目级稳定资产，环境版本是修改历史。
2. 接口版本只记录环境的来源，不作为环境列表的默认过滤条件。
3. 编辑已保存环境会生成新版本，不覆盖历史版本。
4. “删除环境”默认执行归档；被任务、基线或执行记录引用的资产不物理删除。
5. Apifox 只在用户主动同步时访问；平时读取平台已保存的数据。
6. 工作台通过稳定的 `project_id`、`source_revision_id` 和 `environment_revision_id` 上下文进入。
7. 飞书机器人按项目保存，不附着在单个环境版本上。

## 页面结构

### 项目列表

左栏展示当前账号可见的 API 项目：

- 项目名称。
- 活动环境数量。
- 最近环境更新时间。
- 当前选中状态。

切换项目时只刷新环境资产列表，不自动访问 Apifox。

### 环境资产列表

中栏按稳定环境资产展示，而不是把每个修订版本都列成一个环境：

- 环境名称和说明。
- 当前活动版本。
- 服务地址、公共变量和敏感变量数量。
- 来源接口版本和最近更新时间。
- 活动 / 已归档状态。

列表支持搜索、查看活动环境、查看已归档环境。环境操作包括“编辑”“进入工作台”“前往同步”“归档”和“恢复”。

### 环境详情

右栏按以下区域展示：

- 概览：名称、说明、状态、来源和当前版本。
- 服务地址：展示易读服务名称、模块和 Base URL，不直接把 Apifox 内部 UUID 当作名称。
- 变量与凭证：公共变量可回显，敏感变量只显示已配置状态和指纹。
- 默认请求头：继续支持变量引用。
- 版本历史：展示修订号、创建时间和来源接口版本。

详情默认只读。点击“编辑环境”进入现有结构化表单，保存后创建新修订并自动切到新版本。

## 同步语义

环境页不复制 Apifox 发现逻辑。点击“前往同步”带当前项目上下文进入接口资产同步页；用户手动读取 Apifox 项目和环境、检查变化并保存。保存成功后回到环境中心即可看到新的环境修订。

这样可复用现有人工检查、差异确认和接口版本生成能力，同时保证环境中心平时只读本地资产。

## 删除语义

- “归档”把环境状态改为 `archived`，默认列表隐藏，但历史任务、基线和执行记录仍可解析原修订。
- “恢复”把环境重新设为 `active`。
- 本轮不提供物理删除，避免破坏执行审计。

## 工作台联动

从环境资产进入工作台时，路由必须带：

- `projectId`
- 当前环境的 `sourceRevisionId`（有来源时）
- `environmentRevisionId`

工作台优先应用路由上下文，只展示该项目和接口版本下的接口，并使用该环境调试、生成用例和执行。

## 任务与定时任务扩展边界

任务中心作为独立执行资产维护任务名称、任务类型、接口范围、用例版本和默认环境。任务类型至少可区分单接口、多接口和基线回归。

后续定时任务只保存稳定引用：

- 普通回归引用 `task_id`。
- 基线回归引用 `baseline_group_id` 或一组基线资产 ID。
- 运行时选择目标 `environment_id`，再解析其当前活动修订；如需固定版本则显式保存 `environment_revision_id`。
- `notify_feishu` 是调度配置的布尔开关。
- 飞书 Webhook 从项目级机器人配置读取，调度记录不复制 Webhook 或用例内容。

这使项目更新环境、用例或基线分组后，定时任务仍能使用稳定资产；同时每次执行快照继续记录实际使用的修订，保证审计可追溯。

## 后端接口

新增或补齐：

- `GET /api/api-testing/v1/environments?project_id=...&status=active|archived|all`
- `GET /api/api-testing/v1/environments/{id}/revisions`
- `DELETE /api/api-testing/v1/environments/{id}`：归档。
- `POST /api/api-testing/v1/environments/{id}/restore`：恢复。

现有读取修订、导入环境和创建修订接口继续保留。

## 错误处理

- 项目、环境不存在或不属于当前用户时返回 404。
- 归档已归档环境、恢复活动环境应幂等返回当前资产。
- 保存失败保留用户表单内容并显示中文错误。
- 没有活动环境时展示空状态和“前往同步 / 新建环境”入口。

## 验收

1. 切换项目后只展示该项目环境。
2. 刷新页面后已保存环境直接可见，不需要读取 Apifox。
3. 编辑环境生成新版本，旧版本仍在历史中。
4. 归档后环境从活动列表消失，可在已归档列表恢复。
5. 点击“进入工作台”后项目、接口版本和环境上下文一致。
6. 页面不再把内部 UUID 当作服务名称突出展示。
7. 项目级飞书配置不随环境版本切换而丢失。
