# Bounded business planning, one global case

Actual two-request Qwen diagnostic returned both replies while the original full consolidate hit parent deadlines. It retained required interactions but failed normal temporal gates. Implement the request-allocation mechanism, retaining every global gate; it does not itself solve visual or temporal defects. Detailed read-only design/evidence: `.superpowers/sdd/bounded-planner-production-design.md`. This spec governs implementation if that report offers alternatives.

## Global constraints

- All AI Qwen; no model/stage/schema/provider/deadline/correction/revisit/image/source-budget changes, no source-specific targets/IDs/answers, no action deletion or semantic/lifecycle classifier. Legacy/default consolidate wire and behavior unchanged. Explicit default-off `bounded_business_planning` keyword, supplied only by business runtime. No separate execution stages/cases or bypass of gates.
- Small pure `ui_video_planning_groups.py`: allocation, owned reply shape checking and detached merge. Master image selection remains unchanged <=60 originals; retain full global frame metadata, full candidate rows at original positions (including all nonowned prose/questions/domains), all original root questions, actual Top3 baselines and app/goal/duration. Only attached image list/assets and request output ownership differ. Full-context version is a deliberate difference from tested diagnostic minimal rows; latency remains to be measured.
- One group if <=34 candidates and <=40 images; otherwise at most two nonempty contiguous groups of <=34 owned candidates and 2..40 actual images each. One candidate/two images legal. Enumerate cuts, exclude strict geometric envelope crossings as in diagnostic; inclusive equality allowed. Split images at next-owned start, carry every owned original ordinary-domain ref and every owned action ref already selected in master, preserve original order/dedup per group/union master. No invented images/domain expansion. Deterministically minimize max image count, max owned count, max stable-JSON owned byte size, then cut index. If no representable cut/capacity, fail locally before provider. No oversized fallback/third initial group/truncation.
- Closed trusted `planning_scope` records global indices and read-only context ownership, group index/count, original global required list and preserved global intervals. Group `required_candidate_indexes` is its owned intersection. Conditional generic prompt instructions say output only owned events, retain full one-case chronology, context text is unverified and only attached images are pixels; absence of scope preserves exact old rendered prompt. No expected source answers.
- Load master actual assets once. Build **all** group payloads/assets and run normal `validate_video_stage` plus the same ModelJobs `_encode`/MAX_REQUEST admission before the first request of each pass. Do not duplicate/drift serializer or launch group0 before finding corrupt/missing/oversize group1 input. Preserve original master10MiB and file bounds. Runtime provides source boundary/budget/time preflight for the pending group's count: no reset/refund/new clock, remaining original reservations >=groupcount, remaining original wall time >=groupcount*120+.5 before promising full windows. Normal boundary again immediately before each dispatch. Keep normal ModelJobs/BusinessJobs ownership/proofs/receipts/physical reservation/fresh-owner transport behavior.
- Planning allocation frozen across existing passes; no per-group semantic correction loop. Existing whole-plan correction re-runs the entire pass with safe platform feedback, at most two passes. Existing one global ordinary-outcome review and pending-plan behavior unchanged, global input recovery unchanged. All calls through existing business runner, no bare AI/factory/fallback. More physical calls can arise from legitimate grouping/correction/ordinary review/inputs/qualified mandatory transport retry; diagnostic's two-call absolute restriction is not production policy. Original32 trajectory asks, nine-packet38 reservations/formula,4500source/engine-tail480.5/120call and lifetime-two transport replacements unchanged. Capacity may explicitly fail; do not claim worst-case six tail calls guaranteed.
- Local reply validation rejects unknown root/event keys, malformed primitive/container types, bool indices, duplicate/order/wrong-action/unowned output, malformed outcome refs outside actual attached image set. Ordinary temporal-domain validity remains normal global gate/repair; do not turn an attached-but-late outcome into unconditional local refusal. Optional observations need not emit. Missing required is decided globally after existing print/retry preparation, not premature local required completeness.
- Merge original global order, reject duplicate events/omissions/conflicting markers, stable exact questions without truncation/resolution; original questions/audit blockers restored by existing normal path. Earliest nonempty title deterministic; raw alternate titles preserved in normal receipts. Multiple-scenarios OR all. One selection can cross group ownership; only existing global selection/reuse/authorization gates decide validity.
- Omission owner is omitted candidate; repeated_by can be any original global index, validated by unchanged global `review_retries` after merge. <=20 total declarations, no inferred omission. Only cancel-owning group may propose one print_recovery four-index marker; all four original global indices, other indices may cross group. Existing prepare/review/bind full order/failure/region/terminal gates authoritative. No new pixel supply after seeing replies; unsupported cross-group terminal-image case fails normal protected result gate, never invents success.
- Local ownership/merge errors get existing one safe whole-plan correction via a distinct local error classification; provider/runtime/auth/storage exceptions propagate unchanged. Never catch provider ValueError as schema correction. Retain actual partial raw reply evidence and original primary gate failure; collect secret inputs for redaction as existing correction path does. No partial case on group2 failure. All existing final analysis/evidence/draft/question/input/review/side-effect gates remain.
- Production/test scope only; no provider/API/browser/source regen/draft/device/deploy/push by implementer. Parent coordinates actual evidence/review/integration and full original+designated phone acceptance. Passing mocks is not acceptance.
