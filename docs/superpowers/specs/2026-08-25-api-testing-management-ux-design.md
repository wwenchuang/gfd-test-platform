# API 测试平台管理体验优化设计

## 目标

在不修改数据库结构、API 请求契约和现有执行语义的前提下，解决部署环境中已经出现的规模化管理问题，让新用户能够按“准备 -> 设计 -> 回归 -> 结果 -> 配置”的顺序完成工作，同时保留熟练用户的批量操作效率。

本次设计基于线上环境的实际操作结果：当前项目包含 1007 个接口、1006 条用例、138 个用例分组、289 条基线和最近 50 次执行。优化必须在这些真实数量下可用，不能只针对少量测试数据。

## 约束

- 不新增数据库字段或迁移。
- 不改变用例、任务、基线、定时任务和执行记录的保存结构。
- 不改变 setup -> main -> always-run cleanup、业务断言和基线准入语义。
- 不把完整用例或任务列表重新放回工作台。
- 不隐藏一次性基线；只做明确标记和筛选，用户仍可主动执行或调度。
- 不在浏览器状态、日志或报告中新增任何密钥、Token、Authorization 或 Biz 明文。

## 方案选择

### 方案 A：只调整样式和间距

优点是改动最小，但无法解决 138 个分组平铺、原生大下拉框、执行结论不可见和调试报告污染项目指标的问题，因此不采用。

### 方案 B：基于现有数据增加前端工作视图

通过树形目录、客户端筛选、批量操作、统一结论和展示层归并解决问题，不改变持久化结构。该方案风险可控，可以直接兼容历史数据，本次采用。

### 方案 C：增加收藏、最近使用和正式回归标签

长期最灵活，但需要新增用户偏好和资产标签字段。该方案留作后续，不与本次交互修复混合。

## 一、全局导航分区

保留现有独立页面和路由，只将九个同级入口组织成四个功能区：

- `设计准备`：工作台、接口资产、用例管理。
- `回归编排`：任务管理、基线用例、定时任务。
- `结果分析`：执行记录、测试报告。
- `项目配置`：环境配置。

桌面端显示分区标题；窄屏只保留图标和现有 tooltip，避免压缩主操作区。导航不新增统计请求，也不因为数量加载失败影响页面访问。

## 二、用例列表的规模化操作

### 树形分组

将 `家用业务 / app接口 / 我的` 这类完整路径拆成逐级目录。默认只展开第一个根目录或当前选中用例所在路径；子目录只有展开后才渲染。搜索时自动展开命中路径并继续高亮命中内容。

目录节点显示本节点及后代的用例总数。`展开全部`和`收起全部`继续保留，但展开全部属于用户主动操作，不作为默认状态。

### 工作视图

列表顶部增加不持久化的视图切换：

- `全部`：所有已保存用例和候选。
- `当前任务`：当前任务接口范围内的用例。
- `有编排`：存在前置或清理步骤的用例。
- `一次性`：名称或分组明确包含“一次性”的用例。
- `候选`：尚未保存的生成候选。

视图与搜索条件叠加，数量实时显示。没有匹配项时说明当前筛选为空，而不是误报项目没有用例。

### 分组移动

移除每条用例行内包含全部 138 个选项的原生下拉框。用例行只保留“移动分组”图标；点击后打开可搜索分组选择器。

已保存用例增加复选框，选中后出现批量工具条，可执行：

- 移动到已有分组。
- 输入名称创建新分组并移动。
- 清空当前选择。

后端仍逐条调用现有分组更新接口。批量操作按顺序执行，发生部分失败时保留已经成功的结果，并明确显示成功数量和失败位置。

## 三、基线工作视图

保留现有分组和批量执行能力，在列表上增加组合筛选：

- 基线类型：全部、常规基线、一次性。
- HTTP 方法。
- 优先级。
- 来源：AI、平台导入、手工。

筛选仅影响当前显示和“全选当前筛选”，不会修改基线。一次性基线使用醒目标记，但仍允许保存为任务、立即执行和加入定时任务。

## 四、执行记录

左侧记录增加搜索和两组筛选：

- 来源：全部、正式回归、在线调试。
- 结论：全部、通过、有问题、执行中。

记录行主状态改为统一的业务结论，例如`通过`、`未通过`、`运行异常`、`执行不完整`。队列和运行中的记录继续显示生命周期状态；终态不再只显示含义不足的 `DONE`。

筛选不改变当前已经打开的执行详情，避免用户查看日志时页面突然跳转。

## 五、测试报告

报告页将项目范围进一步区分为：

- `正式回归`：已保存任务回归、基线回归和定时任务。
- `在线调试`：单条或临时多条调试。
- `全部记录`：需要审计全部历史时使用。

如果项目存在正式回归，默认使用正式回归计算驾驶舱；只有在线调试时自动回退到全部记录。这样调试过程中的失败不会污染领导查看的项目回归健康度。

原有“全部/有问题/已通过”作为第二层结论筛选。增加任务名称和环境搜索。报告驾驶舱只随来源范围变化，不随“有问题/已通过”列表筛选变化，避免指标含义漂移。

## 六、环境服务地址展示

不修改已保存环境内容，仅在读取视图中归并展示：

- 相同 Base URL 的多个内部服务键合并为一个有效地址项，并显示关联键数量。
- 所有空地址合并为一个“未配置服务键”项，并显示数量。
- 概览同时展示“有效地址数”和“服务键数”，不再把重复或空地址描述成可用服务。
- 编辑环境时仍完整展示和保存原始服务键，保证执行匹配不受影响。

## 七、组件与状态边界

新增或调整的主要前端边界：

- `App.vue`：静态导航分区，不加载业务数据。
- `CaseGroupBranch.vue`：递归目录节点，只在展开时渲染后代。
- `CaseGroupPicker.vue`：搜索、选择已有分组或创建新分组。
- `CaseListPanel.vue`：工作视图、选择状态和批量操作编排。
- `BaselinesView.vue`：组合筛选。
- `ExecutionConsole.vue`：执行筛选和统一结论。
- `ReportsView.vue`：正式回归与调试范围隔离。
- `environmentPresentation.ts`：纯函数归并环境服务展示。

所有筛选、展开和复选状态均为页面临时状态。刷新后可以恢复默认视图，不产生新的持久化依赖。

## 八、验证标准

- 138 个分组默认不会全部展开或渲染为 138 个完整路径标题。
- 搜索可以命中用例名称、接口路径和任意目录层级，命中内容高亮。
- 单条和批量移动分组都使用可搜索选择器，不再出现超长原生下拉框。
- 当前任务、有编排、一次性和候选视图数量与实际列表一致。
- 基线筛选与全选只作用于当前可见结果；一次性基线仍可执行。
- 执行记录终态显示业务结论，不再只显示 `DONE`。
- 正式回归驾驶舱不统计在线调试；切换到全部记录后可以完整审计。
- 重复 Base URL 只显示一个有效地址项，空地址合并显示数量，编辑数据保持原样。
- 前端单元测试、静态检查、生产构建、`git diff --check`全部通过。
- 在部署或本地生产构建上用 Playwright 复走：用例搜索和移动入口、基线筛选、执行筛选、报告范围切换、环境地址展示。
