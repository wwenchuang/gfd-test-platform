## Design

- Correct the prompt to copy target and continuation ID from the immediately preceding eligible input, and both page fields from that predecessor's page_after. Define page fields as stable page identity rather than editing/IME interval identity. State or candidate changes alone are not independent input boundaries. Real submission/field change/navigation still prevents merging; maintain complete input evidence and actual uncertainty.
- At the existing input_continuation failure add bounded indexed metadata identifying exact failed predicates, whether the immediately prior input is eligible, and the authoritative existing-history field references needed to correct identity. Short safe opaque IDs may be copied; arbitrary page/target/observation/question/value prose must not be echoed as trusted error text. Arbitrary page strings remain accepted/rejected exactly as before; use fixed history references when a literal is unsuitable. Keep the current predicate, rejection identity and precedence. No automatic renaming or merging of captured responses.
- In ask(), capture the incoming outer validation_feedback once. On inner schema/revisit/envelope correction retain it as parent_validation_feedback and keep validation_feedback for the latest inner failure. Each slot is bounded (12000 characters maximum; include an explicit truncation indicator if needed); retries do not append earlier inner messages or multiply the parent. Prompt requires both unresolved parent and latest constraints. No previous model reply or arbitrary exception text is promoted to authority. Empty parent creates no extra field.
- Keep existing prior_events and canonical schemas. A second runtime continuation-contract representation is deferred: existing history plus explicit indexed feedback provides the needed identity without duplicating schema eligibility rules.
