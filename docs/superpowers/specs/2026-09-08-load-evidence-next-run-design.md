# 基于场景和服务监控的下一轮建议

沿用用户已认可的设计：平台确定建议边界，AI解释证据，不再自由选择加压数值。直接在main实现，保留用户文档。

1. 增加可选的业务目标、单轮最大增长比例、期望观察时长（网页填写、执行快照保存）。这些是用户策略，不是行业统一标准；不配置则不自动升压。
2. 报告增加只读场景安全摘要；AI证据携带测试目的、原负载、实际服务/实例指标摘要及缺口。资源值只保留观测数据，不推断主机=服务，不把Pod重启滚动值累加。
3. 独立建议策略依次判断副作用/未知场景、失败/证据、服务监控缺失、观察不足、目标及目的。写场景/阶梯历史/突发需人工设计；缺资源先接入、失败先修复；只有完整只读证据和明确用户目标才按步长升压。
4. v6提示词只允许使用平台next_run，AI仍分析慢步骤/资源事实及待验证假设；最终结果由平台附加推荐原因、限制、目标、手动/自动停止说明。旧诊断需重算，不冒充新策略。
5. 页面同时展示AI分析和平台策略依据，禁用不可生成配置的建议，向导再次校验。测试覆盖缺监控、资源异常、阈值失败、side effect、无目标、不同目的、单位转换与不放大压力。
6. 后端/前端检查、构建、Safari本地UI与线上已有报告只读核验；代码提交推送，明确尚未部署。
