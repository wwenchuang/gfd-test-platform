# API 生成用例共享响应断言设计

## 目标

让“生成基础正向用例”和“AI 生成测试用例”使用同一套 OpenAPI 响应契约推导规则，避免 AI 草稿只校验 HTTP 状态码，同时不破坏 AI 明确设计的负向或更具体业务断言。

## 设计

- 新增独立的响应断言策略模块，集中负责成功 HTTP 状态、业务成功码、`success == true` 和 `data` 存在性断言的推导。
- `BasicCaseService` 直接使用共享策略生成确定性的基础正向断言，不再自行维护一份响应断言实现。
- `AiCaseService` 在绑定真实接口方法和路径、补齐 OpenAPI 必填参数后，在解析和保存草稿前调用共享策略。
- AI 草稿只有状态码成功断言或没有响应断言时，策略补齐契约能确定的业务断言。
- AI 已有相同业务断言或 `$.data` 下更具体的有效断言时不重复追加。
- AI 已明确断言非成功状态或非成功业务码时，视为负向场景，不追加成功业务断言。
- JSON 对象响应壳可推导业务断言；数组、二进制、流式和非 JSON 响应不强加 JSONPath 断言。
- OpenAPI 示例或 schema 明确 `code` 为 `0` 或 `200` 时使用该值；只有统一 JSON 对象响应壳但未给值时沿用平台默认 `code == 0`。

## 错误处理

共享策略只读取契约和候选断言，不访问数据库、不调用 AI，也不执行请求。无法确定响应结构时仅保留已有断言，基础正向入口仍生成契约成功状态码断言。

## 验收

- 两个生成入口对同一个正向接口得到一致的兜底业务断言。
- AI 只返回 `status_code == 200` 时自动补充 `$.code` 和契约存在时的 `$.data exists`。
- AI 已有 `$.code`、`$.data.id` 等明确断言时不产生同类重复断言。
- 预期 4xx 或明确非成功业务码的 AI 用例不被追加成功断言。
- 现有基础正向生成、AI 安全校验和草稿验证测试继续通过。
