# 实时手机卡片设计

## 目标

用户点击“刷新设备”时，平台请求在线 Windows Runner 为每台空闲手机采集一次只读 ADB 截图和状态。设备卡片用最新成功截图替换手机占位图，并显示平台占用、前台应用、电量、温度、亮屏状态、采集时间和失败原因。

## 数据流

页面先调用 `POST /api/runners/refresh` 创建带时间戳的单次采集请求，再轮询 `GET /api/runners`。Runner 下一次心跳取得属于自己的设备请求；仅对不在本地执行任务的设备运行只读 ADB 查询和 `exec-out screencap -p`，随后调用 `POST /api/runner/device-snapshot`。服务端校验 Runner、设备归属、PNG 签名、编码及大小，原子保存每台设备唯一的最新 PNG，并把状态和采集时间合并进 Runner 设备记录。截图读取接口必须登录，禁止公开静态地址。

## 状态语义

- `平台执行中`：平台存在该 Runner/设备的 pending 或 running 任务；显示任务名称，卡片不可选择。
- `空闲可选`：设备在线且没有平台活动任务。前台应用和亮屏只作事实展示，不据此推断人工占用。
- `状态待确认`：Runner 或状态采集超时/失败；保留上一张成功截图并显示“上次画面”和时间。
- Sonic 自身被其他用户占用只有取得可信 Sonic 字段时才显示占用人。本期不从前台应用或屏幕状态猜测占用人。

## 画面与隐私

截图只在显式刷新时采集，不进入普通三秒心跳。每台设备只保留最新一张，成功替换采用原子写；失败不覆盖上一张。页面图片接口校验平台登录，不把 base64 长期放进 Runner JSON。图片提供固定尺寸容器、`object-fit: cover`、加载失败回退占位图和可读替代文字。

## 失败与兼容

旧 Runner 不认识采集请求时，页面仍显示现有卡片并提示“执行器版本不支持实时画面”；不得一直假装刷新。截图超过上限、不是 PNG、设备离线、ADB 超时或设备正在执行任务时，服务端记录中文原因。刷新等待有界，页面在请求完成、失败或超时后恢复按钮。原有单选执行合同、固定设备离线保护和自动选择逻辑保持不变。

## 验收

专项测试覆盖请求去重、归属校验、PNG/大小校验、原子替换、旧截图保留、活动任务占用、忙设备不选、前端状态中文和回退。上线后必须用 Safari 点击刷新，确认两台真实手机的画面、时间、电量/温度及占用状态，并确认失败时仍能看到上次画面和原因。
