# 本地账号、角色与数据授权设计

## 已确认范围

用户确认先采用本地账号，并要求权限管理、角色配置、可配置的数据范围和直接实施。本次延续既有平台，不改 Runner 执行协议、不改历史基线内容、不操作堡垒机。

## 管理模型

- 成员：唯一且不可改的用户名、中文姓名、启用状态、角色、数据范围。账号只停用，不硬删除历史身份。
- 角色：内置超级管理员、测试负责人、测试成员、只读成员；自定义角色可复制、修改、删除。超级管理员不可编辑；最后一个有效超级管理员不能停用或降权。被成员使用的角色不能直接删除。
- 权限与数据范围分别配置。权限包括 `auth.manage`、`platform.configure`、`platform.notify`、`ui.view/edit/execute/delete/baseline`、`api.view/edit/execute/delete/baseline/environment/production`。
- 数据范围为 `ui_apps`（应用包名）、`api_projects`（平台项目 UUID）、`api_environments`（平台环境 UUID），值为 `"*"` 或明确 ID 数组。新成员默认空范围。项目与环境授权取交集，生产执行还需 `api.production`。
- 角色决定动作，成员数据范围决定对象；隐藏按钮不是安全边界。所有 HTTP 方法、直接详情、下载、SSE 和批量 ID 均须后端校验。未知资源或无法确认归属的历史 UI 数据只允许全范围管理员/相应全范围角色，不猜测归属。

## 身份与会话

身份数据使用独立 SQLite 文件（`TASK_AUTH_DB`，生产默认 `/opt/midscene-auth/identity.sqlite3`），不依赖可关闭的 API 测试模块。事务、外键、WAL、短连接、受限文件权限；部署不得覆盖身份库。

密码采用 Argon2id（至少 19 MiB、2 次迭代、并行度 1），同机哈希并发最多 2。新增/重置密码 15-128 字符，支持长口令，不返回密码哈希。新成员首次登录/管理员重置后必须改密；修改密码必须验证原密码。临时密码只在创建/重置时显示一次。

浏览器继续使用现有 Bearer 会话合同，替换自制签名令牌为随机不透明令牌，库内只存令牌摘要、身份、创建/过期/撤销时间。注销、停用、改密、管理员撤销在重启后仍有效；最多保留有限会话，过期数据定期清理。登录失败按账号和来源限速；权限在每次请求从当前身份读取，不在长效令牌中固化。

现有 `TASK_ADMIN_USER` 仅用于首次引导；首次正确登录把旧 SHA-256/环境口令升级为 Argon2id，用户名不变，现有 owner/created_by 数据不重写。之后环境变量不能覆盖数据库中的新密码。现有管理员保留应急入口并提示更换共享密码；新用户必须先改密才能调用业务接口。

公网目前为 HTTP。部署文档明确要求正式分发成员密码前启用 HTTPS；支持部署安全提示，不在此轮擅自修改域名、证书或堡垒机。后续可迁移到 HttpOnly Cookie/企业登录，本轮不同时改变所有客户端传输方式。

## 数据协作与上下游

API 资源归属项目，`created_by/updated_by` 记录真实操作者，不能把成员伪装成项目 owner。现有项目保留原 owner，获授权成员共享已有接口、用例、基线、任务和报告。个人工作区仍按个人保存，不能覆盖别人的当前选择。提供方个人凭证不能因为项目共享而泄漏；只有配置权限可维护项目共享环境，密钥只用于授权执行。

定时任务记录创建人/修改人，用户停用或权限撤销后不得继续以原高权限执行；执行时重新校验授权。执行记录和通知保留真实触发人；Runner 和 Sonic 回调使用机器凭证，只能走既有专用入口，不能管理成员角色。

主平台按应用确认 YAML、模块、知识、生成、Agent 与执行对象归属；无法确定应用的历史对象不向受限成员开放。平台全局配置、批量维护、Sonic 管理等不能按应用安全拆分的接口要求 `platform.configure` 且全范围。公开静态历史报告地址/外部 Sonic 页面不承诺由本平台账号权限隔离，必须在上线说明中单列，并禁止把 API 权限测试当成静态存储验收。

实施中确认：现有 Agent 内部工具会检索共用 YAML、执行历史和报告，只有 HTTP 入口按应用过滤不足以完成隔离。本轮 Agent 自动编排的创建、确认、重试要求完整应用范围、`platform.configure` 和 `ui.execute`。UI AI 生成/修复的 Top3 搜索目前按模块加权而不是硬隔离，因此这些入口也要求完整 UI 应用范围；受限成员仍可使用授权应用下的手工 YAML 管理和执行，API 项目内的生成不受此限制。后续如需让受限成员使用自主 Agent 和 UI AI 生成，必须先完成检索库及每个内部工具的资源授权，不能仅放开入口。生成时同时执行、修复后创建下一次执行也必须具有执行权限。

## 界面

配置区新增“成员与权限”，四个页签：成员、角色、数据授权、操作记录。成员可搜索、启停、改角色、改范围、重置密码、撤销会话。角色使用按模块分组的复选框，数据授权使用真实应用/项目/环境名称，不让用户填内部 ID。提供个人资料、修改密码、当前角色和范围摘要；403 显示缺少的权限和联系管理员的提示，不能误跳登录。

## 验收

- 两个成员分别登录，同项目可协作、不同项目不能通过列表/详情/批量/SSE/环境 ID 绕过。
- 只读成员即使手工调用 POST/PUT/DELETE 仍被拒绝，不能执行生产环境或改密钥。
- 新账号改密前无业务权限；旧临时密码、旧会话在改密/停用/重启后失效。
- 权限变更即时生效，最后管理员保护可并发验证，角色变更不可扩大未授权数据范围。
- admin 数据不丢、个人工作区隔离、计划任务重新授权、真实操作者不被 owner 替代。
- 本地完整门禁和桌面/手机浏览器覆盖创建成员、登录、改密、角色、数据范围、403、退出和管理员恢复。
