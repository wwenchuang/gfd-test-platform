# API 用例生命周期与接口同步连续性设计

## 背景

当前 API 测试流程存在六类断点：

1. Apifox 同步激活新接口版本后，工作台可能恢复历史任务并静默切回旧接口版本，导致新增接口查不到。
2. 用例与具体 `endpoint_id` 强绑定；同步会产生新接口记录，同一逻辑接口的历史用例在新版本中消失。
3. 用例管理只展示已有用例，没有无用例接口的选择和创建入口。
4. 调试、基线、回归分散在不同页面，用例列表无法说明当前生命周期状态。
5. AI 生成任务离开页面或刷新后丢失完成状态，用户不知道结果在哪里。
6. 调试仅以 HTTP 和用户断言判定；`HTTP 200 + code=1001 + code != 0` 会产生假通过并允许采纳基线。

## 目标

建立一条连续且可追踪的主链：

`接口同步 -> 当前版本接口 -> 用例创建/延续 -> 生成进度 -> 调试结论 -> 基线准入 -> 任务/定时回归 -> 报告`

## 核心决策

### 1. 当前工作区优先

平台保存的活动接口版本是工作台默认上下文。只有带 `taskId` 的显式任务深链才允许切换到历史任务的接口版本。普通进入工作台时，如果最近任务属于旧版本，只恢复任务名称等非版本状态，不覆盖当前活动版本，并提示该任务需要迁移。

### 2. 逻辑用例按 `stable_key` 延续

接口 `stable_key` 是跨同步版本的逻辑身份。新接口版本加载用例时：

- 当前版本已有用例时直接展示。
- 当前版本无用例但同 `stable_key` 有历史用例时，展示最新历史用例并标记“待适配”。
- 首次编辑、保存或调试时，以历史用例为模板创建绑定当前 `endpoint_id` 的新版本；历史版本保持不可变。
- 接口已删除或无法匹配时只在历史上下文展示，不自动猜测路径或名称。

`ApiCase` 代表逻辑用例，`ApiCaseVersion` 代表某次接口版本下的不可变快照。适配时更新逻辑用例的当前接口和活动版本，不批量复制所有历史数据。

### 3. 基线是生命周期状态

基线继续固定 `case_version_id`、环境版本和通过证据，不随接口同步自动迁移。用例列表通过后端生命周期投影展示：

- `普通用例`：已保存但无通过调试。
- `已调试`：存在最新通过或失败的调试结果。
- `已基线`：活动基线指向该逻辑用例的某个版本。
- `回归通过/失败`：最近一次基线回归结果。
- `待适配`：列表项来自同一 `stable_key` 的历史接口版本。

列表提供相应筛选，详情提供调试、基线和报告跳转。

### 4. 业务成功必须是精确结论

对于 JSON 响应中的常见业务码字段 `code`：

- HTTP 2xx 只说明传输成功，不等于业务成功。
- `equals` 或有限集合 `in` 可以精确声明预期业务码。
- `not_equals 0`、`greater_than 0` 等宽泛规则不能证明预期错误，保存前校验为错误。
- 执行时再做兜底：实际业务码非成功且没有精确命中该值的断言时，结果必须失败。
- 只有执行完成、断言通过且业务结论可信时才允许采纳基线。

调试抽屉使用中文结论区分别展示 HTTP 状态、业务码、断言和修复建议；原始证据默认折叠。

### 5. 用例管理从接口开始

用例管理增加接口选择区，支持搜索分组和选择无用例接口，并提供：

- 新建手工用例。
- 生成基础正向用例。
- 生成 AI 候选用例。

创建后自动选择结果并进入编辑区。空状态必须提供直接操作，不再显示无对应入口的提示。

### 6. 生成任务可恢复、可定位

生成状态包含排队、运行、批次、耗时、成功、失败和完成。项目维度恢复最近一条任务，包括终态；完成后加载候选或已生成用例，并提供“查看本次生成结果”，在用例列表中高亮本次结果。失败显示中文原因和重试入口。

### 7. 大列表与中文体验

- 1000+ 接口采用折叠分组、搜索后按需展示和稳定尺寸加载状态，避免一次渲染所有叶节点。
- 校验消息、状态、失败分类和按钮文案统一中文；HTTP 方法、JSONPath、路径、UUID 等技术标识保留原值。
- 可选参数提示包含字段名和处理建议，例如“可选请求头 Authorization 未填写；如由环境统一注入可忽略”。

## 兼容性

- 不批量修改历史用例、历史基线或执行证据。
- 历史接口无法通过 `stable_key` 唯一匹配时保持历史只读，不自动迁移。
- 旧任务仍可通过显式深链打开原接口版本。
- 定时任务只能选择和执行活动基线；历史或归档基线继续可管理但不能新建调度。

## 验收标准

1. 同步新接口后普通进入工作台可搜索到新增接口，不会被旧任务覆盖。
2. 用例管理可从无用例接口创建手工、基础和 AI 用例。
3. 同一 `stable_key` 的历史用例在新版本显示“待适配”，首次调试后生成当前版本并保留历史。
4. 列表可筛选普通、已调试、已基线，并显示最近回归状态。
5. AI 生成刷新后仍有进度或完成结果，并可一键定位。
6. `HTTP 200 + code=1001 + code != 0` 判定失败且不能采纳基线；精确断言 `code == 1001` 的负向用例仍可通过。
7. 截图中的英文校验提示替换为字段明确的中文提示。
8. 前后端聚焦测试、静态检查和 `tests/run_api_testing_gate.sh` 全部通过。
9. 部署后使用 Chrome 走通同步、创建、生成、调试、基线、任务/定时回归和报告主链。
