# API 测试资源归属合同：设计候选（未实现）

## 目标与现场边界

平台在现有真实业务上执行 API 测试。现有 `processing.setup_steps`、`cleanup_steps` 只描述 HTTP、条件、提取和断言；`dependency_spec` 传递值，没有声明该资源是已有资源还是本次创建，也没有把业务服务的归属证明绑定到执行。候选 `a88f9c52` 能区分部分响应来源，但真实响应中的非空 ID 仍可能指向别人的资源。清理前重新提取一个值、匹配一个客户端提供的值或给变量改名，都不自动构成归属证明。

本设计仅用于新建或显式升级的用例版本；不改变存量版本、原基线或定时任务的默认行为。旧版本的执行与清理状态不得标为“已校验归属”。本说明是设计，不是已存在的配置项，不得将本文件中的示意值直接用于生产配置。

## 三种方式与选择

1. 依靠变量名、提取先后和响应非空推断：改动小，但已有 ID、旧 ID 和他人 ID 不可区分，拒绝。
2. 每条业务用例自行写查询和断言：可复用现有步骤，但普通断言缺少可验证的执行身份、完整查询及删除目标绑定，不足以成为平台级保障。
3. **显式声明资源模式，并由平台验证业务服务提供的归属证据，再放行绑定目标的写操作**：初期需要为不同业务适配可证明的查询或原子条件；无法证明的用例保持待人工处理，不推测。选择第 3 种。

## 对使用者的配置与反馈

新手界面在涉及业务写入/清理时显示资源类型、环境、实际请求和测试账号，要求选择：

- **使用已有资源**：录入受授权的既有资源选择规则和操作前服务端校验，不把它记成本次创建，也不自动删除。要修改/删除该资源，仍需独立的业务授权及受控目标；仅选择“已有”不是权限或所有权证明。
- **本次创建并清理**：选择平台生成的运行关联字段、创建请求、归属核验查询、唯一资源 ID、清理请求及清理后验证。平台检验这些位置的绑定，而非允许任意声明一个变量即通过。缺少可验证的服务能力时，界面说明“无法自动确认归属”，创建响应丢失时给出排查记录，不猜测或自动重发。
- **只读**：不声明资源归属，不开放由此派生的写入或清理资格。

页面以业务描述组织步骤，把关联字段、验证路径等高级内容折叠；展示“已证实/未证实/无法确定”“本轮创建结果不明”“已提交清理但未验证消失”等区别，并保留原始执行报告链接。AI 可建议字段及核验步骤，提交前平台必须校验合同，用户审核业务语义；AI 不得授予写入或删除权限。

## 合同与执行绑定

新合同应随**不可变用例版本**保存并被运行快照引用，包含模式、受保护的资源种类、生成的每次执行随机关联值的输入位置、创建步骤、服务端归属查询及其可核验的关联字段/唯一 ID、允许写入的目标位置、清理及完整消失验证。具体字段需在实现阶段加入 `contracts/case.py` 的严格解析、持久化/版本迁移、`CaseService` 和快照，拒绝未知字段；不能把尚未被解析的 `processing.resource_ownership` 当成已生效。

关联值由平台为每个执行与资源实例生成，不能使用数据行、环境、预处理或依赖值覆盖。创建请求的最终渲染结果必须确实带入该值；服务端必须有可信机制保存它并支持按同一值查询。光是客户端回显、HTTP 200、返回新 ID 或字段非空均不够。查询必须具有明确的业务身份、授权及环境范围；只接受业务服务的当前响应。若查询会分页，必须证明查询结果完整且恰好命中一个记录；无法确定分页完整性、一致性、可见性、唯一性或 ID 为空时不放行。存在重复、同名旧数据、跨账号或跨环境匹配时拒绝自动清理。

平台对验证所得目标 ID 创建内部、不可由请求参数伪造的执行级证据，绑定执行 ID、用例版本、环境版本、资源实例、服务端查询/断言结果和验证时间；不得在报告或日志暴露凭据或完整业务响应。后续每个受控写请求在**真正发送前**，以最终请求的 URL、查询参数、请求体及业务定义的目标位置核验必须使用该目标，阻止旧数据行、变量默认值、预处理、环境嵌套别名、断言条件和跨依赖覆盖导致的替换。不能安全识别所有资源目标时拒绝，不靠按名称搜索或替换子串猜测。其他静态独立清理可以在合同明确证明不访问此资源且有自己的授权时继续。

跨用例依赖不把普通变量或进程内 `response_outputs` 升格成归属证明；若需要跨依赖，必须在受保护的持久化记录中传递源执行、资源实例和同一环境的已核验引用，并验证目标用例的授权与生命周期。重启、旧 worker、缺失/过期/不匹配的证据按未知处理，不从历史变量或报告重新推断。旧 worker 不能声称执行了新合同；上线需先完成全部相关 worker 升级，再允许启用合同。

## 状态和失败处理

1. **准备**：新建不可猜测的本次关联值；锁定测试用户、项目和环境，建立执行记录。不得复用其他并发执行的关联值。
2. **创建中**：发送一次创建请求。响应丢失、断线或超时时记为“创建结果未知”，不得使用旧 ID，也不得假设未创建。默认禁止自动重发；只有业务明确支持且平台验证相同幂等键语义后才能按该合同重试。
3. **核验中**：通过服务端可信查询检查关联值、资源类型、账号/环境及唯一目标。无结果可能是延迟可见或响应丢失，须按有限轮询策略区分“暂未找到”和可确定不存在；不以一次空结果宣布无残留。多结果或无法遍历完整集合为待排查。
4. **已核验**：清理前再次核验目标；如果业务有并发修改风险，应依赖服务端原子所有权条件、版本/ETag 或等效前置条件，单独 GET 后再删存在竞争，不能保证安全。没有原子约束时记录限制并不对并发归属作保证。
5. **清理已发送/结果未知**：失败或响应丢失不代表清理成功；保留本轮资源线索，先按业务支持的查询核对状态，不盲目重复副作用请求。
6. **已清理并核实**：按相同关联与权限范围证明主资源不可查询，并分别确认副本、文件或异步任务等关联资源的生命周期；业务接口无法证明物理删除时明确报告“未验证”，不能记为全量清理完成。

所有失败状态应保留脱敏的运行、步骤、类别与排查入口；避免把未执行的步骤、等待人工核对或清理未确认呈现为通过。禁止把训练用或本地模拟结果标记为真实生产验收。

## 不改变旧定时任务的分阶段落地

1. 先核对现有实际接口是否支持服务端保存关联值、精确查询、分页完成判定、目标的原子条件和关联文件删除；现有会话创建响应丢失后无法可靠找回，因此在证明服务能力前不得启用自动清理。先做只读发现与已授权的历史证据分析。
2. 加严格合同解析与版本持久化，旧版本无合同保持原行为并显示“未校验归属”；合同仅对显式启用的**新版本**生效，禁止批量迁移基线和定时任务。未知合同版本直接拒绝执行，不回退成无合同。
3. 为前置/主体/清理的请求发送边界接入证据状态机与最终目标绑定；新增独立、受授权的证据记录，不将数据集值或模板渲染结果直接信任为证明。不可修改执行中的不可变快照；检查记录与 worker 恢复的一致性。
4. 先用隔离 HTTP/数据库与故障注入验证，再选服务端已具备能力的单个真实用例，在业务允许的环境及明确授权范围内验收；创建和删除、并发、异常、分页及关联副本分别留证，未证实部分不进入定时基线。部署前检查远端、在途任务、worker 一致版本、备份与回滚，部署后实网验证。

## 验收矩阵

- 旧版本及旧定时任务的存储、解析、执行路径与行为不变；新合同缺字段、模式未知、目标位置不完整或不支持的服务能力在写入前拒绝。
- 同时运行两轮，服务端只返回各自关联资源；旧数据行、跨运行 ID、前置 copy/json、环境递归别名、可选依赖默认值、同名覆盖和旧 worker 证据均不得触发错误目标的写请求。
- 创建超时后零命中、恰好一个、多个、分页不足、服务可见性延迟、权限不足、跨项目/环境及核验响应丢失分别判定；只在可证明唯一且满足授权时放行，不自动重发无幂等保障的创建。
- 合同声明存在但没有服务端核验时，即使返回 200 和非空 ID，也不得清理。现有离线 `test_extracted_response_id_does_not_by_itself_authorize_cleanup` 为严格预期失败；它通过测试夹具绕过了尚不存在的解析器，**不是线上合同已可用**。
- 清理成功响应与物理删除分开；缺少分页结束、异步状态或副本/文件消失证据时保持待核验。清理响应超时、服务重启、竞争及原子前置条件不满足时保留记录，不声称完成。
- 原始失败请求、目标和执行关联可查，报告与网页区分已执行、已拒绝、待核对；敏感值不进入日志或可被其他项目读取的静态资源。新手可完成配置并理解为何被阻止。
