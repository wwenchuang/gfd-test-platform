继续逐条增加提示词、业务语句正则和两轮识别结果之间的合并例外，不足以解决当前可靠性问题。推荐保留现有来源、核对、编译、评分、Runner 门禁，在解析前半段引入以动作片段为单位的结构化证据链。先做隔离对照，达到固定验收标准后接入正常平台。不能以移除真实动作、人工回填输入、减少断言或放宽安全门禁换取成功率。

## 为什么交互式分析与平台表现不同

交互式复核能持续保留整段业务背景、人工基线、前后页面关系，针对疑点主动补看原图，再修正自己的解释。平台目前主要接收带时间标签的多张 image_url，按固定帧数分别请求；prior_events 只携带最近 8 项文字，缺少跨窗动作身份、精确证据关系及明确的页面状态记忆。补充历史相似图、临近图、触点局部图已有帮助，但它们没有组成统一轨迹。

另一个差别是输出责任：说明视频大意可以暂留歧义，执行用例还须确定输入值、次数、目标、等价返回、后置条件和设备环境。因此不能把交互式文字分析视为已经证明可自动生成可执行用例，也不能把模型品牌差异当成唯一根因。

现有设计让初步 aiTap/aiInput/aiAssert 同时承担观察假设与后续完整性锚点。虽然允许通过严格证据映射纠正误判，但后续模型仍要反复解释不同采样边界和动作名称，增加了与真实业务无关的失败面。保留完整性约束是必要的；需要调整的是约束所依据的对象。

## 核验的外部方法及适用边界

1. [VideoAgentTrek 官方仓库](https://github.com/xlang-ai/VideoAgentTrek) 及 [流水线入口](https://github.com/xlang-ai/VideoAgentTrek/blob/main/video2action.py)：公开代码分离关键帧检测、动作裁剪、动作识别、轨迹构建及验证。借鉴其时序定位与动作参数分工；其专用权重、桌面鼠标数据及推理成本需另测，不能直接声称适用于本安卓录屏，更不能照搬坐标作为跨端执行目标。
2. [Video2GUI 官方方法说明](https://github.com/WeiminXiong/Video2GUI#-method-overview)：先提取带时间的轨迹，再用动作前、中、后的高分辨率三图定位控件。可以借鉴证据组织。当前查看的仓库主要为展示和数据说明，不能当作已验证可直接部署的完整解析软件。
3. [Qwen3-VL 官方仓库](https://github.com/QwenLM/Qwen3-VL#video-understanding)：展示带时间元数据的视频处理方式。[Gemini 视频官方文档](https://ai.google.dev/gemini-api/docs/video-understanding) 明确提醒默认 1fps 可能遗漏快速动作。需要实测当前 Gateway/模型是否支持原生视频及时间信息；不能把多张图片与视频时序编码视为完全等价，也不能认为直接上传完整视频就能解决所有细节。
4. [OmniParser 官方仓库](https://github.com/microsoft/OmniParser)：把截图解析为结构化控件。可作为模糊图标与控件区域定位的可选对照；单帧解析不能证明用户实际点击，也不能单独解决取消任务归属或异步因果。
5. [OpenAdapt Capture 官方仓库](https://github.com/OpenAdaptAI/openadapt-capture) 和 [UFO 示范学习文档](https://github.com/microsoft/UFO/blob/main/documents/docs/ufo2/core_features/knowledge_substrate/learning_from_demonstration.md)：记录输入轨迹与画面，再做语义归纳。适合以后平台自录制增强证据；现有 MP4 必须继续支持，不能要求用户重新录制作为本次完成条件。

这些是方法参考；其公开数据或评分不能外推成本平台的准确率。

## 方案比较

| 方案 | 优点 | 主要不足 | 选择 |
| --- | --- | --- | --- |
| 继续修补现有多窗提示与正则 | 改动小，可消除个别已知误判 | 切窗、旧假设身份、文本措辞仍互相耦合 | 仅处理必要兼容问题，不作为主路线 |
| 原生视频一次直接生成 YAML | 输入连贯，接入形式看似简单 | 快速动作与细字仍可能遗漏，错误难定位，直接混合事实与执行 | 做整体理解对照，不直接生成最终执行 |
| 整体状态图＋动作片段证据＋结构化轨迹＋现有编译门禁 | 各层可单独评估，可复用当前来源/草稿/Runner | 需定义中间协议并完成对照验证 | 推荐 |

## 推荐数据流

原片及时间索引 → 整体页面状态与阶段 → 候选动作时间段 → 按需补取动作前/中/后原帧 → 动作语义与结果验证 → 规范轨迹 → 现有中文步骤/草稿编译 → 原门禁 → 指定手机运行。

### 1. 整体理解只建立页面与流程记忆

先识别页面状态、导航层级、输入区间、等待区间和恢复环路。输出结构化 page/state ID 和原时间范围，不直接输出执行动作。后续片段带着“从哪个状态来、已提交什么、等待什么结果”分析，减少把确认后的延迟响应误判成新点击。

整体理解仍是待验证假设，不能据流程合理性补动作。没有新触点不能单独证明没有操作；有按钮也不能单独证明点击。存在歧义时按需回看，并保留明确问题。

### 2. 按完整动作包组织证据

用已有变化、微动作与触点线索提出候选，保留页面转场、无明显触点导航等其它候选来源。按动作前状态、接触/编辑过程、释放、后续响应组织片段；固定帧数只作为传输上限，不定义动作边界。大段输入可跨多个传输批次，但保持同一候选身份。

触点、图标、静止卡片和系统残留轨迹必须区分。候选检测不直接授权生成 aiTap。预算不足或画面不足应明确报告证据缺口，不静默裁掉动作。

### 3. 中间轨迹以结构事实替代自然语言判门禁

建议字段包括 event_id、候选来源、证据时间范围、page_before/page_after、action_hypothesis、目标控件证据、输入编辑轮次、是否独立提交、是否切字段、响应关联和 unresolved。观察者之间引用同一个候选 ID，各自结论保留来源；复核可修正类型并说明对应原图。

输入按“同一字段的一轮修改”确定身份，实际值继续由原图恢复并经过现有敏感值处理。不能让“点击退格键”和“退格键点击”这样的中文词序成为事实判定的主要依据。新结构字段也是模型主张，必须绑定像素/时间证据并验证，不能把一个布尔值当真值。

候选原始帧不得随语义纠正被删除。每个候选最终需要解释为真实动作、同次重复采样、自动响应、录屏系统事件或明确未决项；覆盖针对证据与真实操作身份，不能强制保留首轮错误动作类型或虚构动作数量。

### 4. 语义和执行分开

规范轨迹确认以后才生成中文步骤与官方 Midscene 动作。保持原来的静态校验、评分、人工问题门禁、设备限制及一次 Runner 生命周期。内部观测坐标可用于原片控件定位，执行仍使用可见目标语义，不能回退成固定坐标脚本。

原片出现旧任务，当前环境无旧任务，分别记录为“原片事实”和“执行前置状态”。条件执行只能通过已明确支持且验证过的能力表达；不能删除原片旧任务取消步骤后声称完整复现，也不能新增生产不支持的 YAML 条件字段。

### 5. 持久化、定向回看与预算

每一层保存版本、实际模型标识、提示版本、输入帧清单、结构结果、拒绝码、调用耗时与输出位置。私有证据仍受 owner/app/source/version 权限约束。只重算依赖受影响证据的节点，复用其它结果；结构化失败说明应指出哪个候选、哪个字段、哪段证据有问题。

共享明确的总调用、图片、token 和时间预算；不能在每个子层再叠独立重试。模型或服务错误、解析证据错误、YAML 错误、设备环境错误分别统计。调整视频能力需要做 Gateway 能力检测，不能直接改 Runner 模型生产策略。

## 可执行的验证顺序

1. 固定当前源哈希、人工基线和已保存失败，建立逐动作对照，禁止把业务词输入生产提示作为答案。
2. 在独立进程输出新轨迹，与旧链路使用同一原片、相同基线比较；不修改来源/草稿，不下发设备。
3. 比较完整动作召回、额外虚构动作、目标、输入轮次和值、动作与响应关联、未决项、调用数和耗时。不能只比较 JSON/生成是否成功。
4. 本片硬项：两轮业务输入各为一轮；真实去打印动作保留；恰好两次真实下一步；旧/新模型处理取消分清；确认后自动转场不造第三次下一步；71.533–71.900s 独立收键盘保留；返回首页；不出现最终确认物理打印。人工基线用于评估，不提供给待测模型。
5. 至少连续 3 次完整解析均满足本片全部硬项，才具备接入正常平台的最低资格。这只证明该片复现；再用未参与提示修正的不同录屏，检验输入停顿、重复点击、异步加载、无触点导航和失败恢复，报告实际结果，不能声称普遍可靠。
6. 正常平台导入、核对和原门禁通过，才用 ecbfd645 / 9888E0094F2A 完整 Runner 执行。已有归属明确测试任务有则取消、无则继续；不操作其它设备、不确认物理打印。生成、内容正确、条件分支覆盖、手机成功分别报告。
