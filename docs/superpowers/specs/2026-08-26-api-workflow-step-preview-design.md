# API 前置步骤试运行与响应取值设计

## 目标

让用户在编辑 API 用例时，不必先保存并运行完整用例，就能校验前置步骤、执行到指定步骤、查看真实响应，并从响应中勾选需要传给后续步骤的数据。Token 等敏感字段允许主动显示、编辑和用于本次预览替换，但不把动态明文固化到用例、执行日志或报告。

## 用户流程

1. 用户添加并配置一个或多个前置步骤。
2. 在目标步骤点击“试运行到此步骤”。平台先做结构和变量校验，再按顺序执行所有已启用的前置步骤，执行到目标步骤后停止，不执行主体请求。
3. 面板展示每个已执行步骤的状态、断言、缺失变量和目标步骤的真实响应字段。
4. 用户搜索并勾选 JSON、响应头、Cookie 或状态码字段，调整建议变量名后点击“应用选择”。平台把选择转换成现有 `extractions` 规则。
5. 敏感字段默认遮罩，用户可主动显示。用户修改预览值后，该值仅作为当前编辑会话的变量覆盖，用于继续试运行后续前置步骤；保存用例时仍保存真实响应提取规则。
6. 如果需要长期固定替换 Token，用户应在环境配置中保存为敏感变量，再在请求中引用，避免把临时凭证写进用例版本。

## 后端设计

新增 `POST /api/api-testing/v1/workflow-steps/preview`。请求包含：

- `environment_revision_id`：当前环境版本。
- `setup_steps`：当前草稿中的前置步骤。
- `target_index`：运行到的步骤索引。
- `initial_variables`：首条启用测试数据及编辑会话提供的初始变量。
- `processing_pre`：草稿的前置变量处理。
- `extraction_overrides`：当前编辑会话中手工修改过的变量值。

HTTP 层必须校验环境版本归属当前用户。`WorkflowStepPreviewService` 严格解析步骤和变量处理配置，再调用 `HttpExecutor.preview_setup_steps()`。执行器复用正式执行的环境解析、请求渲染、主机策略、超时、轮询、断言和提取逻辑，因此预览与正式运行不会出现两套规则。

预览结果包含：

- `status`、`failure_category`、`error_message`。
- 已执行和跳过的 `trace`。
- 目标步骤的 `response`，仅在本次 HTTP 响应中返回，不进入执行记录。
- 扁平化的 `fields`，每项包含来源、路径或名称、数据类型、真实值、敏感标记和建议变量名。
- `available_variables` 与 `missing_variables`。

正式执行的 `sanitized_response` 和事件流保持原有脱敏行为。预览原始响应只保存在请求生命周期内，服务端不落库、不写日志、不进入报告。

## 前端设计

`CaseEditor` 把当前环境版本传给前置步骤编辑器。每个前置步骤增加“试运行到此步骤”命令，运行时提交当前草稿前置链路。配置存在阻断错误时不发请求，直接定位并显示错误。

新增独立的响应选择面板：

- 顶部显示执行结论、耗时、执行到哪一步以及缺失变量。
- 搜索框固定在字段列表顶部，支持按路径、名称和值过滤。
- 字段按 JSON、响应头、Cookie、状态码分组。
- 每行支持勾选、编辑变量名、查看类型和值；敏感值可显示或隐藏。
- 编辑值会标记为“本次预览替换”，并写入内存中的 `extraction_overrides`，不会随用例保存。
- “应用选择”按来源生成或更新提取规则，避免重复路径和变量名冲突。

## 校验与错误处理

- `target_index` 必须指向存在且启用的前置步骤。
- 步骤结构、HTTP 方法、断言、提取规则和变量名使用现有严格契约。
- 缺少环境、依赖变量或请求渲染失败时，不执行目标请求，返回可定位错误。
- 前序步骤失败时停止链路，并保留完整前序轨迹。
- 手工覆盖变量名必须已经由前序提取产生，未知覆盖项返回校验错误。
- 响应字段最多返回 500 个、最大深度 16，超出时明确标记截断，防止大响应阻塞编辑器。
- 非 JSON 响应展示摘要但不生成不受支持的 JSONPath 提取规则。

## 测试与验收

- 后端单元测试覆盖：运行到目标步骤、前序变量传递、失败阻断、手工变量覆盖、字段展平、敏感字段标记且正式轨迹仍脱敏、数量和深度限制。
- HTTP 契约测试覆盖：鉴权、环境归属、非法索引、合法响应结构。
- 前端组件测试覆盖：按钮状态、预览请求、字段搜索、敏感值显示、编辑替换、生成/去重提取规则、错误展示。
- 完整门禁继续运行后端、前端、生产构建、视觉检查和 Chromium E2E；浏览器验收至少覆盖两级前置步骤，验证第一步提取的变量可用于第二步。

## 非目标

- 不新增另一套用例执行协议。
- 不在预览时执行主体请求。
- 不把预览执行写入执行记录或测试报告。
- 不把预览中看到的动态 Token 明文保存到用例版本。
