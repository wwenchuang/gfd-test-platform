# 3D API 核心业务链路设计

## 目标

在保留现有 291 条全量活动基线的前提下，为 Apifox `默认模块 v11` 建立一套数量少、业务含义明确、能独立执行的核心链路。以后可以优先执行这套核心链路判断 3D 主流程是否可用，再按需要执行全量基线。

## 当前事实

- 项目：`3D家用`。
- 当前接口版本：`默认模块 v11`，1031 个接口。
- 当前执行环境：`生产环境（新）-腾讯云 v30`。
- 现有 291 条活动基线属于旧接口版本，不能当作 v11 核心链路已经建立或通过的证据。
- v11 有 25 个接口没有当前版本用例，包含 CAD 建模、京东之家默认切片、EPOne 设置与动作、EPONEPro Camera、勋章、打印记录删除及打印队列详情。

## 资产结构

核心链路按执行稳定性分为三组，现有全量基线不删除、不改名、不移动。

1. `核心链路 / 家用 / 稳定回归`
   - 账户与首页上下文。
   - 模型浏览与收藏闭环。
   - 设备状态与能力读取。
   - 打印历史与详情。
   - 下载记录创建、查询和清理。
   - 学习冒险只读链路。
2. `核心链路 / 共享 / 稳定回归`
   - 复用已经反复通过的共享业务查询基线，保留家用与共享边界。
3. `核心链路 / 扩展 / 按需执行`
   - 文字、图片与 CAD 建模。
   - 京东之家默认切片。
   - EPOne 设置、设备动作、EPONEPro Camera。
   - 真实切片、重新打印和打印取消。

稳定回归和扩展回归分别建立任务，避免设备状态、AI 费用或长轮询使日常核心结果失真。若需要一个入口执行全部核心链路，再建立只引用已通过基线的组合任务。

## 用例建模规则

- 每条链路是一个用例版本，通过 `setup_steps -> 主体请求 -> cleanup_steps` 串联，不把多个互不相关的接口堆在一个用例里。
- 模型 SN、组件 SN、设备 SN、任务 ID、打印记录 ID 等均从前置接口动态提取。
- 写操作只清理由本次链路创建或修改的数据；主体失败后仍执行清理。
- 设置类操作先读取原值，主体写入可逆值，清理阶段恢复原值。
- 打印创建只有在能提取打印任务 ID、成功取消并验证取消结果时才允许采纳。
- HTTP 200 只表示传输成功；每一步都要断言准确业务码、关键领域字段和必要结构。
- 业务允许为空与必须有数据分开建模，不用放宽断言掩盖缺少前置数据。
- 自动修复或失败重跑产生的候选留在修复区，不直接混入固定核心基线。

## 第一批核心链路

| 链路 | 前置与主体 | 清理 | 准入要求 |
| --- | --- | --- | --- |
| 账户与首页上下文 | 用户信息 -> 首页热门模型 -> 当前设备 | 无 | 用户身份字段、模型列表结构和设备响应业务码有效 |
| 模型收藏闭环 | 模型列表 -> 模型详情 -> 添加收藏 -> 收藏列表验证 | 取消本次收藏 | 使用当前上架模型；收藏及取消都返回预期业务码 |
| 设备状态链路 | 设备列表 -> 当前设备 -> 设备状态 -> 耗材信息 | 无 | 设备在线；扩展写操作还要求空闲 |
| 打印历史链路 | 打印列表 -> 打印详情 -> 打印任务查询 | 无 | 动态取得仍可查询的历史打印记录 |
| 下载记录闭环 | 已完成作品 -> 新增下载记录 -> 下载详情/列表 | 删除本次下载记录 | 本次新增记录可查询且清理成功 |
| 学习冒险只读链路 | 当前冒险 -> 世界地图 -> 任务详情 | 无 | 不修改用户任务进度 |
| 共享业务稳定链路 | 复用已通过共享业务基线 | 无或各用例自有清理 | 当前环境身份可访问共享数据 |

## v11 扩展链路

- CAD：创建 -> 详情轮询 -> 列表验证 -> 改名 -> 删除。本链路会实际创建 AI 任务，必须独立执行并记录耗时。
- 京东之家：当前设备 -> 有效组件 -> 默认切片预览 -> 共享设备状态。设备型号与组件必须存在默认切片匹配关系。
- Camera：设备设置/能力查询 -> prepare -> heartbeat -> stop。仅允许绑定、在线且 `capabilities.camera=true` 的 EPONEPro。
- EPOne 设置：读取设置 -> 原值写回或安全改值 -> 状态确认 -> 恢复原值。
- 真实打印：模型与设备就绪 -> 创建打印 -> 查询 -> 取消 -> 验证取消。缺少取消证据时不能采纳。

## 外部数据边界

优先从接口动态取得。只有以下数据无法取得时才向用户索取：

- 长期可用于回归的在线空闲设备及允许执行的操作范围。
- 支持 Camera 的已绑定 EPONEPro。
- 与京东之家设备型号匹配且已配置默认切片的模型组件。
- 共享业务测试身份；凭据只写入平台环境，不写入仓库或用例。
- AI 建模和真实打印是否允许产生实际任务或费用。

2026-09-03 范围更新：用户明确不做京东之家及 EPOne/EPONEPro 链路，因此不再为这些链路索取设备、组件或权限数据，也不把它们加入核心任务。当前唯一待确认的外部条件是专用空闲打印机及允许真实创建后立即取消打印任务。

## 完成证据

- 每条核心链路保存为 v11 用例，并在 Safari 中能从用例管理找到。
- 每条采纳基线都必须先有生产环境调试通过的执行用例 ID。
- 核心任务执行完成后记录执行 ID、原始通过/失败/异常数量、总耗时和失败分类。
- 在测试报告中逐条抽查请求、响应、断言及前置/清理轨迹。
- 任何未执行、仅保存或仅弹出确认的动作都不得写成通过。
