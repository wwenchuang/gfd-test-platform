# API 测试平台渐进式操作体验设计

## 目标

在不改变现有接口、用例、任务、执行和基线数据结构的前提下，把 API 测试工作台整理成新用户能够理解、熟练用户仍能高效操作的渐进式界面。

本次不是增加另一套“新手模式”，也不是把独立管理能力重新塞回工作台。工作台继续负责范围选择、用例设计和调试；`用例管理`、`任务管理`、`执行记录`、`测试报告`继续使用各自独立页面。

核心原则：

- 高频操作直接可见，低频和高风险配置按需展开。
- 先选择对象，再创建配置，避免产生无意义的空白步骤。
- 折叠状态仍展示足够的执行摘要、变量关系和错误状态。
- 错误反馈指向可修改位置，不要求用户从原始 JSON 或日志中自行定位。
- 保留结构化编辑与原始 JSON 两种能力，已有用例加载、保存和执行语义不变。

## 当前问题

### 用例内步骤

- 点击“添加步骤”会立即生成一个 `GET /` 空白步骤，用户还要二次寻找接口。
- 接口使用原生分组下拉框，接口较多时无法搜索名称、方法、路径或目录。
- 每个步骤同时显示基础字段、轮询、请求 JSON、断言 JSON和提取 JSON，信息密度过高。
- 第一条步骤默认展开；连续增加步骤后列表快速变长，难以确认当前编辑对象。
- `required_variables` 依赖手工输入逗号分隔名称，用户看不到变量来自哪一步，也容易拼写错误。

### 主体用例编辑

- 用例名称、目的、请求、数据、断言、提取和依赖纵向铺开，缺少完成状态与问题摘要。
- `保存草稿`与页面外的`保存并调试`分离，用户难以判断当前修改是否已保存、能否调试。
- 服务、请求体 JSON、断言超时、变量处理等低频字段与常用字段处于同一视觉层级。

### 调试反馈

- 调试抽屉优先展示完整请求和响应 JSON，执行结论、失败步骤、失败断言不够突出。
- 执行器已经返回前置、主体和清理步骤的 trace，但前端将 trace 压缩为日志文本，无法直接定位出错步骤。
- 失败后没有跳回对应步骤或字段的快捷操作。

### 页面之间

- 工作台、用例管理和任务管理边界已基本正确，但“编辑 -> 调试 -> 采纳基线/查看执行”的下一步状态仍不连贯。
- 各列表已经具备部分搜索和折叠能力，不应重复重做；本次只统一状态和操作语言。

## 方案概览

采用“默认简洁、按需展开高级配置”的单一界面，不增加模式开关。

用例编辑从上到下保持现有三段执行语义：

1. 前置步骤
2. 主体请求
3. 清理步骤

每段只展示当前需要操作的内容。步骤选择、步骤摘要、结构化配置、变量关系、配置检查和调试结果形成同一条连续工作流。

## 一、可搜索的接口选择器

### 触发方式

点击“添加前置步骤”或“添加清理步骤”时，先打开接口选择器，不立即修改用例草稿。用户选择接口后才创建步骤；关闭选择器不会留下空步骤。

选择器提供两个入口：

- `从接口资产选择`：默认入口。
- `手工请求`：创建空白请求，仅用于接口资产中不存在的合法场景。

### 搜索与分组

- 搜索框固定在选择器顶部。
- 支持接口名称、方法、路径、目录/标签联合搜索。
- 命中字段高亮，搜索时自动展开命中分组。
- 无搜索词时所有目录默认折叠，当前主体接口所在目录可优先展示。
- 每个目录展示接口数量；每行展示方法、名称和完整路径。
- 选择器高度受视口约束，只有结果区滚动，搜索框和操作区不滚动。

### 选择结果

选择接口后创建步骤，并使用接口真实方法和路径。现有默认 HTTP 状态及业务码断言继续保留；接口参数推导沿用当前生成和校验能力，不在前端伪造业务数据。

## 二、单项展开的步骤列表

### 折叠行为

- 同一阶段同一时间只展开一个步骤。
- 新建步骤自动成为当前展开项，其他步骤收起。
- 调整顺序后保持当前步骤展开，不因索引变化误开其他步骤。
- 保存校验失败时，自动展开第一条存在错误的步骤；其他步骤保持收起。

### 折叠摘要

每个步骤的摘要行固定展示：

- 顺序号、启用状态、步骤名称。
- 方法和路径。
- `参数 N`、`断言 N`、`提取 N`计数。
- 轮询状态。
- 错误或警告数量。

摘要行支持展开/收起；启用开关、上移、下移、复制、删除放在行尾操作区，并提供图标提示。删除保持二次确认；复制生成独立步骤名称并立即展开。

### 空状态

没有步骤时只保留段标题和添加按钮，不展示大面积说明卡。前置与清理的执行语义通过简短副标题和状态标签表达。

## 三、步骤的渐进式结构化编辑

展开步骤后默认展示三个区域：

### 基本请求

- 步骤名称。
- 已选接口摘要和“更换接口”命令。
- 方法、路径。
- 请求头、查询参数、路径参数、Cookie 和请求体，复用主体请求的键值行编辑方式。
- `服务`在非默认值或高级配置展开时显示。

### 业务校验

- 断言改用与主体请求一致的结构化断言行。
- 默认只展示类型、比较、路径/名称、期望值和启用状态。
- 超时等低频字段进入单条断言的高级项。
- 没有业务字段断言时展示阻断或警告状态，不能把单纯 HTTP 200 描述为业务通过。

### 输出变量

- 响应提取改用与主体请求一致的结构化提取行。
- 每个变量展示变量名、来源、路径及是否必需。
- 变量名重复、路径格式错误或未被后续使用时给出就地提示。

原有三块原始 JSON 编辑器保留在`高级配置 -> 原始 JSON`中。打开时仍使用原有严格解析和错误提示；结构化编辑与原始 JSON 之间必须保持双向一致，不丢失未知但合法的已有字段。

轮询放在`高级配置 -> 异步等待`中，仅 GET/HEAD 可启用；非查询请求继续保持禁止轮询的安全规则。

## 四、变量目录与依赖选择

### 可用变量目录

编辑器根据执行顺序计算当前步骤可用变量：

- 环境公开变量只展示变量名和来源，不展示密钥值。
- 跨用例依赖导出的变量。
- 当前步骤之前的前置步骤提取变量。
- 清理步骤额外包含主体请求提取变量。

每个变量显示来源标签，例如`环境`、`依赖：登录`、`前置 2：创建切片`、`主体请求`。

### 必需变量

`必需变量`由手工逗号输入改为可搜索多选：

- 默认只列出当前步骤之前可产生的变量。
- 已有历史用例中的未知变量仍可保留并以`未找到来源`标记，避免加载后丢数据。
- 选择变量后以可移除标签展示。
- 变量来源被删除、停用或移到当前步骤之后时，立即显示错误。

### 请求值插入

请求参数和请求体字段旁提供变量插入命令，选择后写入现有 `{{variableName}}` 语法。该功能只帮助输入，不改变执行器模板语义。

### 跨用例依赖

现有“共享用例依赖”继续保留在高级区域，用于登录、设备初始化等跨用例复用流程。依赖选择器同样支持按用例名称、接口路径和分组搜索，变量导出使用复选列表，不要求输入版本 ID。

## 五、主体编辑器状态与操作

### 配置检查条

用例编辑器顶部增加紧凑状态条，展示：

- 前置步骤数量。
- 主体断言数量。
- 清理步骤数量。
- 错误和警告数量。

存在问题时可展开问题列表。每条问题展示所属阶段和简短原因，点击后滚动并展开对应步骤或字段。

### 分区层级

- 用例名称、测试目的、主体方法/路径、必要请求参数和业务断言保持默认可见。
- 无内容的测试数据、提取变量和共享依赖默认折叠；已有内容或错误时自动显示摘要。
- 原始 JSON仍作为专家能力保留在顶部切换，不移除、不改格式。

### 底部操作栏

将`保存草稿`和`保存并调试`统一到编辑器底部的粘性操作栏：

- 左侧展示`有未保存修改`、`已保存`或`存在 N 个错误`。
- 右侧提供`保存草稿`和主操作`保存并调试`。
- 有阻断错误时禁用执行，并可通过错误数量打开配置检查。
- 保存和调试继续调用现有 store/API，不改变自动保存任务范围的现有逻辑。

## 六、调试结果的任务化呈现

### 结果摘要

调试抽屉顶部优先展示：

- 通过、失败、跳过或中断状态。
- 总耗时和失败分类。
- 前置、主体、清理各阶段完成情况。
- 第一条失败断言或错误原因。

### 步骤轨迹

复用执行结果已有 `trace`，将 `workflow_step` 映射为按执行顺序排列的步骤列表。每个步骤展示状态、名称、尝试次数、耗时/错误、提取变量名和断言摘要。请求、响应和完整断言放在步骤详情中折叠展示。

清理步骤必须独立显示，即使主体失败；清理失败不能被主体结果遮盖。

### 返回修改

失败步骤提供`返回修改`：

- 前置或清理失败时，关闭抽屉并展开对应步骤。
- 主体请求失败时，定位主体请求或断言区域。
- 无法映射到具体字段时，定位到对应阶段，不伪造精确位置。

通过后继续展示`采纳为基线`，已有准入与清理门禁不变。

## 七、列表与页面衔接

- `接口范围`继续使用现有固定搜索、命中高亮和目录折叠，不重复实现另一套树。
- `用例列表`继续使用现有搜索、自定义分组、展开/收起和基本操作。
- `用例管理`与`任务管理`继续作为独立页面，工作台不重新增加完整管理列表。
- 从用例管理进入编辑时保留当前项目、接口版本和环境上下文。
- 调试完成后可前往本次执行记录；任务执行后继续进入执行记录页面。
- 页面切换不改变已有保存状态，不隐式采纳基线或覆盖环境。

## 八、兼容性与数据边界

- 不新增数据库字段或迁移。
- `CaseDraft`、`InlineWorkflowStep`和后端 payload 结构保持不变。
- 旧用例的 setup/cleanup、原始 JSON、未知来源变量、禁用步骤和轮询配置必须完整加载并可原样保存。
- 不将环境密钥、Token、Authorization 或 Biz 值写入浏览器持久化状态、日志、提示或报告。
- 不修改执行顺序、always-run 清理、轮询限制、业务断言和基线准入语义。
- 所有新增筛选、展开状态和选择器状态仅为前端临时状态。

## 九、组件边界

建议新增或拆分以下前端组件：

- `EndpointPicker.vue`：可搜索、分组折叠、命中高亮的接口选择器。
- `WorkflowStepCard.vue`：步骤摘要、单项展开、排序、复制和删除。
- `RequestMapEditor.vue`：主体与步骤共用的请求参数键值编辑器。
- `AssertionEditor.vue`：主体与步骤共用的结构化断言编辑器。
- `ExtractionEditor.vue`：主体与步骤共用的响应提取编辑器。
- `VariablePicker.vue`：带来源的变量多选和模板插入。
- `CaseValidationSummary.vue`：错误/警告汇总与字段定位。
- `DebugTrace.vue`：调试阶段与步骤轨迹。

`CaseEditor.vue`负责执行顺序、可用变量计算和分区编排；`InlineWorkflowStepEditor.vue`负责阶段级步骤管理；`WorkbenchView.vue`只负责保存、调试、页面上下文和 store 调用。

组件拆分以消除主体和步骤的真实重复为准，不为每个小字段创建抽象。

## 十、交互与可访问性

- 选择器、折叠列表和操作栏支持键盘 Tab、Enter、Escape。
- 弹层打开后焦点进入搜索框，关闭后回到触发按钮。
- 图标按钮必须有 `title` 和无障碍名称。
- 删除确认明确展示步骤名称，不使用模糊的全局确认文本。
- 搜索无结果、加载、部分失败和空数据状态分别展示。
- 桌面端保证编辑区不因展开内容横向溢出；窄屏下所有结构化行改为单列，粘性操作栏不遮挡内容。

## 十一、实施顺序

1. 接口选择器与单项展开步骤列表。
2. 抽取主体/步骤共用的请求、断言和提取结构化编辑组件。
3. 变量目录、必需变量多选和来源校验。
4. 配置检查条与统一粘性操作栏。
5. 调试 trace 结构化呈现与返回修改。
6. 用例管理/任务管理进入编辑和执行结果跳转的状态衔接。

每一步都必须保持已有用例可读写和已有测试通过，不能等最后一次性补兼容。

## 十二、验收标准

- 在 1000 个接口规模下，添加步骤可在搜索后选择目标接口，不产生未完成空步骤。
- 搜索支持名称、方法、路径和目录，命中高亮，目录默认折叠。
- 连续添加 10 个前置步骤时只展开当前步骤，列表摘要仍可判断每步配置状态。
- 新用户无需编辑 JSON 即可完成请求参数、业务断言、响应提取和必需变量配置。
- 已有使用原始 JSON、未知变量和轮询的用例加载保存后语义不变。
- 清理步骤只能选择此前可产生的变量；变量来源失效时保存前可见错误。
- 所有后端校验错误都能在配置检查条中看到，并能定位到对应阶段或字段。
- 调试结果按前置、主体、清理展示，失败步骤和第一条失败断言无需查看原始日志即可识别。
- 主体失败后清理结果仍清晰可见；清理失败时不能误显示为可采纳基线。
- `用例管理`和`任务管理`继续为独立页面，原有编辑、删除、执行、移动/分组、任务开关和定时能力不回退。
- 前端单元测试、静态检查、桌面和移动端 Playwright 截图检查通过。

## 非目标

- 不重写后端执行器或用例数据模型。
- 不新增独立“新手模式/专家模式”。
- 不把接口资产、用例管理或任务管理重新合并进工作台。
- 不自动执行破坏性接口，不改变现有安全和基线门禁。
- 不用帮助文档、长说明文字或功能介绍卡代替正确的信息层级和状态反馈。
