# UI/API 用例所属业务设计

## 目标

测试应用固定展示为“智小白3D”，所属业务由应用配置维护。平台初始提供“家用”和“共享”，管理员可以新增、重命名和停用中文业务线；UI 与 API 用例从新建、保存、执行、历史、基线到飞书通知始终使用同一业务标识和中文名称。

## 配置设计

- “应用配置 -> 应用分组 -> 基本信息”维护业务线。
- 用户只填写中文名称，例如“家用”“共享”“校园版”，不填写英文编码。
- 平台为新增业务线生成不可见的稳定内部 ID；默认业务线沿用 `home`、`shared` 兼容历史数据。
- 重命名只修改中文名称，不改变内部 ID，历史用例和执行记录自动显示新名称。
- 停用后不再出现在新建和编辑选择器中，但历史用例、执行记录和通知仍能解析名称。
- 不提供硬删除，避免已有用例留下无法解释的业务标识；至少保留一个启用业务线。
- 中文名称不能重复，最多 20 个字符，必须包含中文；单个应用最多配置 20 个业务线。

## 交互设计

- “新建自动化测试”固定展示应用“智小白3D”，所属业务按当前启用配置动态渲染且无默认值。
- 全自动 Agent 使用同一业务线列表；未选择时不能预览或启动。
- API 用例编辑器使用同一动态列表，应用与所属业务分字段展示。
- 一次生成批次内的所有 UI 用例继承所选业务；生成后可在单条 YAML 用例编辑区纠正。
- 重新生成继承原批次业务。若该业务已停用，继承仍有效；用户主动改选时只能选择启用项。
- UI/API 用例列表、基线、定时目标、执行记录、历史记录和通知只展示中文名称，不展示内部 ID。

## 数据流

应用配置将业务线保存为 `business_lines: [{id, name, enabled}]`。前端控件提交内部 ID，后端只接受当前启用业务线用于新建，并把 ID 写入生成批次资产元数据、API 版本请求模板、执行快照和 UI `task-meta.json.case_businesses[case_id]`。

Midscene YAML 不增加非官方字段。展示层按应用配置把 ID 解析为中文名称；Sonic/UI 与 API 通知继续使用独立渲染器，但都复用同一业务线解析服务。混合执行按实际用例展示多个中文业务名称。

## 兼容策略

- 没有业务线配置的旧环境自动使用“家用 / 共享”默认项。
- 旧数据中的 `home`、`shared`、`家用`、`共享` 均可解析。
- 已停用业务可用于历史展示和原批次重新生成，不能用于新建或主动改标。
- 历史用例没有业务时展示“未标注业务”，允许选择当前启用项补标。
- 未识别的旧中文值保留原文展示，不静默改写为家用。

## 验收标准

- 管理员新增“校园版”时只输入中文，保存后服务器生成稳定 ID，页面不展示该 ID。
- 新建 UI、Agent 和 API 用例均能选择“校园版”，请求和持久化记录保存同一 ID。
- 将“校园版”重命名后，历史列表和通知显示新名称且关联不丢失。
- 停用后新建入口不再显示该项，历史记录仍显示名称。
- 未选择业务不能创建任务；没有任何启用业务线不能保存应用配置。
- UI/API 通知分别显示“UI 自动化”和“API 测试”，应用固定为“智小白3D”，业务使用配置中文名。
- 前端静态检查、后端静态检查、API 测试平台全量门禁、生产构建和浏览器视觉检查均通过。
