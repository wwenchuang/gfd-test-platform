# 平台整体质量检查与修复计划

**目标：**覆盖平台主要入口和跨页面状态链，修复可复现缺陷，由用户部署后用 Chrome 验收；不把静态检查等同业务通过。

**实施方式：**沿用现有架构，按问题小范围修改。使用系统排查、回归测试及独立审查。保留用户工作区与历史数据；只清理本轮创建的可丢弃测试数据。手机序列号与业务打印机 MAC 分开。

## 覆盖与验收矩阵

| 范围 | 必查路径与异常 | 验收标准 |
| --- | --- | --- |
| 全局导航/登录 | 菜单切换、异步迟到、401/403、重复点击、隐藏页面轮询 | 旧请求不能覆盖新页面；错误可见；无重复任务 |
| Agent 工作台/待确认 | 输入保存、预览、计划门禁、终态、继续执行 | 参数不丢，未达阈值不继续，终态准确 |
| 用例资产/脚本编辑 | 应用→模块、新建/上传、保存重开、历史、脏编辑保护 | 归属隔离，保存确实持久化，失败不假成功 |
| AI 生成/模型配置 | 加载/空/失败状态、模型配置、生成数量与官方动作 | 明确区分服务异常与脚本问题，不能静默空白 |
| 录制 | 实时设备与开始一致、会话切换、取消/历史、坐标/截图/编辑、YAML | 无旧缓存阻断，迟到结果不串会话，编辑不丢，结束状态准确 |
| 调试执行/运行记录 | 设备选择、执行反馈、取消、报告入口 | 请求状态和界面一致，失败有真实原因 |
| 报告/失败处理 | 超时、环境故障、Runner 清理、修复建议 | 成功清理不误报缺少关闭 App，环境故障不自动改 YAML |
| 应用/执行环境/通知 | 配置读写、设备状态、连接失败、空态 | 现有配置不被加载失败覆盖，状态可刷新 |
| 布局与性能 | 1366×768/768×480/390×600、长列表、请求重叠 | 按钮可见、无意外截断、无重叠轮询/抢焦点 |

## 实际覆盖与未完成项

- 21 个线上读取 API 均返回成功，覆盖认证、模块、应用、平台、任务、Runner、Agent、报告、修复、知识、Sonic、录制及模型。运行记录性能异常已单独记录；读取成功不是对应写入流程验收。
- Chrome 实际打开录制、模型配置、应用配置、执行环境、用例资产和 AI 生成页面；检查新建 YAML 弹窗后取消，未创建或删除线上业务数据。复现 A10。此时页面仍为已发布版本，不能算本地补丁验收。
- 三种布局 1366×768、768×480、390×600 检查历史、紧凑时间线、完整截图、编辑、准备失败重试按钮及横向溢出。
- 全套 Python 同进程尝试没有通过：初次身份库临时目录归属错误；改用用户自有子目录后发现既有测试导入/模块状态污染，代表文件独立运行通过。另有 Sonic 旧测试仍从启动脚本导入已迁出函数。没有以这些失败伪称产品通过，也没有改生产代码去迎合旧测试。
- 尚待用户部署后的 Chrome 写入/重开/真实录制与 Windows 准备耗时验收、任务接口生产耗时复测、Agent 生成→冒烟→报告端到端验收；这些清单保持未勾选。
- 全平台审查不是一次性“所有功能没有 bug”的保证。API 测试子系统的完整业务、权限矩阵、通知真实发送、长时并发与稳定性仍需后续专门验收，不在本次静态检查通过范围内。
