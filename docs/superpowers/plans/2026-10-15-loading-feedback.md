# 统一等待反馈实施计划

目标：用户能知道操作已经响应、正在做什么及下一步；保持精致深色、轻量和真实进度。

设计：复用 LoadingManager 和原请求生命周期，不接管业务门禁。不添加定时器、网络轮询、模型调用或虚构百分比。按钮使用紧凑转圈；首次列表加载用局部提示，保留已有内容；长任务用实际服务端阶段。支持减少动态效果偏好，完成、失败、取消或离页停止反馈。

- [x] 统一加载样式：既有 AI 修复、执行、Agent 入口复用；修正按钮文案转义、嵌套恢复和 aria-busy。
- [x] 视频上传显示上传中；排队、解码、识别展示真实阶段节点，完成/取消/失败停止。没有字节计数，不显示上传百分比。
- [x] 中文生成/保存/校验、基线搜索、首次设备/结果列表、截图刷新、报告下载接入局部反馈；后台静默轮询不反复闪动。
- [x] Node 生命周期/并发/失败回归；前后端静态；浏览器慢请求场景与宽窄屏、减少动画核对。
- [ ] 更新状态、提交推送，部署后复验；原视频两端 Runner 验收仍单独保留，不能把视觉验收替代执行验收。

覆盖边界：本批覆盖主测试流程和所有已有 LoadingManager 消费入口；API 独立前端、模型配置、成员、历史等页面仅盘点，已有专用加载反馈不强制改写。后续发现空白等待按相同组件接入。
