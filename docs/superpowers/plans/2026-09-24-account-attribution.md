# 平台账号归属、操作追踪与授权关联 Implementation Plan

> 执行时使用 executing-plans，按阶段实施；本文件是后续计划，不表示功能已经完成。当前先收尾录制三轮实机验收，不抢占用户正在使用的 Chrome、终端或手机。

**Goal:** 平台各类资产和操作能可靠回答“谁创建、谁修改、谁发起、谁执行、依据哪个版本”，并按当前账号权限控制查看与操作。

**Architecture:** 复用现有 identity/access_control，不新增平行账号系统。用稳定 user_id 关联人，用资源标识关联录制、用例版本、执行和报告；创建者、业务归属、操作人、自动执行主体分开保存。身份由服务端认证决定，前端姓名仅作展示。

**Tech Stack:** Python 服务、现有身份 SQLite、现有 JSON/YAML 资产存储、API 测试 SQLAlchemy、原生 JS 前端。

## Global Constraints

- 用户说创建用例、录制回放只是例子；范围覆盖 UI/API 测试、Agent 生成、资产版本、调试/回归/重跑/定时执行、报告、批量操作和配置修改。
- 本次只调查并记计划；不创建线上账号、不改变现有授权、不重写历史归属、不触发部署。
- 归属追踪和访问授权分开。知道某条记录是谁创建，不等于自动允许其他人访问；列表过滤不能替代接口鉴权。
- 沿用现有角色和应用/项目/环境范围，不默认扩大共享范围。先支持“我创建的 / 我执行的 / 权限内全部”；权限内全部不是全平台全部。

## 数据语义

| 对象/动作 | 需要保存的关联 | 展示用途 |
| --- | --- | --- |
| 用例资产及版本 | 稳定资产 ID、应用/模块、创建者 ID、版本作者 ID、版本号/内容摘要 | 区分原作者与后续编辑者，移动/重命名后不断链 |
| 录制会话/步骤修正 | 发起人 ID、会话 ID、截图/步骤 ID、修正操作人及时间 | 从生成用例回看原录制和人工修改 |
| 执行任务 | 发起人 ID、触发方式、执行主体、用例版本、录制来源、父任务/重跑来源 | 区分“张三创建，李四回放，Runner 执行” |
| 报告 | execution/job ID、实际脚本版本、实际设备、结果和证据引用 | 不能指向执行后已被修改的当前 YAML |
| 定时/Agent 自动触发 | 自动主体、配置责任人、触发链、当时授权来源 | 系统发起不能伪造成管理员手工操作 |
| 批量操作 | 批次 ID、操作者 ID、每项结果、原因码 | 支持部分成功追溯，避免整批都显示成功 |

字段名称在第一阶段根据现有持久化接口定稿，不把用户 ID、用户名、资源 owner_id 混成同一个概念。保留显示名快照便于历史阅读；账号停用、显示名变化不丢失来源。
