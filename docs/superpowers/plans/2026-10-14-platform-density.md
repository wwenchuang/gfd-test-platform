# 全平台紧凑工作台实施计划

> **For agentic workers:** 使用 subagent-driven-development 按任务实施、逐项复核；在当前隔离 worktree 内工作，不修改用户主工作区。

**Goal:** 消除结果大卡片和宽屏稀疏布局，统一UI及API平台展示。
**Architecture:** 公共主题单独CSS；简化流程样式局部调整；结果模板仅调整DOM层级；API样式通过源码构建发布。
**Tech Stack:** 原生JS/CSS、Vue/Vite、现有Node和Vitest回归。

## Global Constraints
不改变接口、轮询、依赖、权限、派发、历史数据或报告生成逻辑。允许修正前端结论与已有事实不一致的问题，必须补行为回归。真实状态/错误保留；页面自然自适应；临时视口不得留在交付窗口。

## 每页固定验收步骤

1. 进入页面，等实际数据或明确空态出现；加载中截图不能记通过。
2. 检查标题能否说明用途、主操作是否突出、空态是否有下一步、禁用按钮是否解释原因。
3. 在独立后台浏览器检查四档尺寸；比较 `clientWidth` 和 `scrollWidth`，再查看截图，避免只看 DOM 数值。
4. 检查顶部筛选、长标题、表格、底部操作、键盘焦点、详情与弹窗。表格自身横滚可接受，整页被撑宽不可接受。
5. 只读筛选/切换/详情直接验证；保存、执行、打印、删除与通知等有副作用流程使用隔离数据或已有明确范围，不把视觉巡查当真实业务执行。
6. 记录问题、修改文件、复验结果；颜色和描述不能掩盖失败、未知、未执行状态。

## 发布门槛与性能约束

- 按下面任务顺序合入可独立验收的改动，避免不断叠加未验证样式。
- 行为更改先写失败回归，再最小修改；样式通过实际浏览器验收，不写只重复 CSS 的测试。
- 不新增网络请求、轮询、AI 调用、运行依赖；检查 diff 确认现有刷新频率和执行逻辑保持不变。
- 不以“没有新增轮询”替代性能实测：上线复验检查页面加载、切换、滚动和网络请求是否出现重复/失败。后端负载和 Runner 吞吐没有本轮实测时明确不作提升承诺。
- 每次发布给出提交号、部署命令、已验项目与未验项目；保留部署前提交用于回退，不覆盖历史测试数据。
- 最终交付需要同时满足：自动检查通过、候选页面验收、线上版本与静态资源核对、用户自然窗口复验。
