# 可配置服务监控与性能报告交付规划

日期：2026-09-08。状态：规划稿，未实现、未部署。本轮按用户“好好规划一下”只完善设计与验收，不修改运行代码。

## 1. 目标与范围

让使用者在网页完成：选择应用和环境 → 设置场景与压力 → 勾选被测服务和监控项 → 填写或复用监控配置 → 检查采集 → 执行 → 查看实时指标 → 生成可交给领导的报告。

配置一次可以复用；每次执行允许调整选择，但不能修改过去报告的配置或数据。一个执行支持多个服务、每个服务多个实例，不按当前两台压力机写死。

本规划细化并调整 2026-09-07-performance-statistical-analysis.md 的交付顺序：先修统计可信性，再优先交付“单次执行 + 多服务监控 + 报告”，不要求先做完大型统计中心才能看到 CPU。随后做多轮计划、对比、覆盖和回归。旧计划未完成项继续保留，不能用本规划覆盖成已完成。

## 3. 先解决数据可信性

最近小流量执行存在 20 次 k6 迭代、21 次 HTTP 请求、19 次链路和耗时样本的差异。不同指标不必天然相等，但每一差异必须能通过脚本阶段、实际请求和原始采样解释。

- 定位原始 k6 输出、Agent 读取、窗口聚合、幂等写入和报告之间是否丢点或重复。
- 区分预检、setup、每 VU 初始化、主体请求、清理、重试及重定向；分别保存阶段和计数范围。
- 建立固定次数的受控场景、每轮含多请求的链路场景、到达率场景三种验证。不能拿“1 次/秒 × 20 秒”当固定次数模式。
- 校验计数守恒及采样完整性；不要求一个业务链路一定只有一个请求，不对不同范围的计数直接强制相等。
- 报告单独呈现“执行状态、负载达标、业务质量、指标完整性、监控覆盖”。退出码为 0 不代表完整验收通过。
- 无样本显示“无数据/无法判断”，历史指标不补造。旧 Agent 缺能力时显示具体缺项。

验收门槛：原始输出 → Agent → 数据库 → 页面/导出的同口径总数一致。完成这项前不把现有短跑报告作为容量结论。

## 4. 网页操作设计

### 4.1 可复用配置放在环境配置

环境配置增加“服务与监控”页签，避免增加零散一级菜单。以应用、环境隔离服务目录。支持新增、编辑、测试连接、停用；被历史报告引用的配置不能物理删除。

每个服务显示名称、业务用途、部署类型、监控来源、覆盖指标、最近连接检查结果。空列表提供“新增监控服务”，有历史配置则可复用。

### 4.2 创建压测时逐步选择

1. 应用、环境、业务版本、场景版本。
2. 压力模型、阶段/时长、测试数据、验收标准。
3. 压测节点及容量。
4. **服务监控**：勾选本次涉及的服务；可就地新增，填写配置并测试，不必跳出向导。
5. 执行前检查和配置汇总。

每个选中服务可以展开编辑监控项、阈值和本次必需性；默认复用配置，临时修改仅影响本次。另提供“保存到环境供后续复用”的明确动作。切换应用/环境时清除不兼容选择并说明原因。

服务列表采用紧凑行：勾选框、服务名、实例范围、CPU/内存等覆盖标签、连接状态、配置按钮。不要恢复成多排巨大卡片。选中若干服务时在同一区域展示完整性摘要。

### 4.3 配置字段与动态表单

| 分组 | 页面字段 | 规则 |
| --- | --- | --- |
| 归属 | 应用、环境、服务名、用途 | 继承向导环境；作用域不可跨项目混用 |
| 部署 | 主机 / Docker / Kubernetes / 托管数据库 | 决定定位字段，不要求每种部署填写同一套表单 |
| 实例 | 主机标识；或容器标识；或集群、命名空间、工作负载、标签 | 连接测试列出实际匹配实例，空匹配不能显示成功 |
| 来源 | Prometheus 兼容数据源、离线证据 | 首批自动采集支持前者；其他源按后续适配开放，未实现选项不可伪装可用 |
| 连接 | 监控地址、TLS、只读凭据引用、访问通道 | 普通用户不填写 shell；密码不返回前端、不入报告或 AI |
| 指标 | CPU、内存、实例数、重启；网络/磁盘/数据库可选 | 明确支持/未接入/不涉及；不默认全选 |
| 规格 | CPU 核数、内存容量、实例数及获取方式 | 优先实际采集；人工填写标注“人工配置”，不得假装实测 |
| 策略 | 采样间隔、前后观察窗口、阈值、必选监控 | 冻结进本次执行快照；默认不设通用“CPU 80% 必失败” |

常规指标采用模板映射，避免让用户手写 PromQL。高级查询仅向有配置权限的人开放，并限制范围、耗时与返回量。首次需要管理员接好监控网络和只读权限；之后日常勾选、修改和执行都在页面完成。

## 5. 采集方式选择

选择：优先复用 Prometheus 兼容数据源；无现成监控则提供标准采集部署包；截图/文件作为历史证据补充。

| 方式 | 优点 | 边界 |
| --- | --- | --- |
| 已有 Prometheus 兼容源 | 可按运行时间读取真实历史序列，无需每次部署 | 需要只读地址、凭据与正确实例映射 |
| 标准监控采集部署包 | 没有监控的环境也可接入同一数据模型 | 主机与容器/Pod 采集方案不同，首次部署需要环境权限 |
| 截图/CSV 附件 | 可复用旧报告材料 | 截图不生成实时曲线，不凭图片补造精确统计 |

不采用网页保存 root 密码并执行任意 SSH 命令的方案；不挂载 Docker Socket 到压测 Agent 来获得宿主机控制权。压力执行和监控访问权限分离。

官方能力依据：Prometheus HTTP API 提供时间范围查询；Node Exporter 提供主机指标，不能用主机资源冒充单个服务资源。

- https://prometheus.io/docs/prometheus/latest/querying/api/
- https://prometheus.io/docs/guides/node-exporter/

网络通道：首批由平台后台只读访问已授权监控源，访问检查从实际采集方执行；浏览器能打开不代表平台可访问。只能内网访问的源需要部署可达的监控通道，不能默认为每台压力机都能访问。通道不通时显示“未接通”，不把连接配置页面当成完成采集。

## 6. 采样、异常与安全约束

- 压测指标保持自身采样粒度，资源监控遵循数据源实际采样间隔；网页默认建议 5 秒，但不会把 15/60 秒数据插值冒充 5 秒实测。
- 默认前后各观察 60 秒，可页面修改。压力结束先显示“压测已结束，监控收集中”；后观察窗口和回补结束再形成最终快照。零后观察窗口支持短跑。
- UTC 保存时间，页面按用户时区展示。图表时间联动、保留原始时间戳、来源、单位、实例 ID 和查询/指标版本。
- 有效样本比例、最大缺口、覆盖起止均入报告。连接成功、权限成功、有匹配实例、有新鲜样本分开检查。
- 必选监控缺失：默认阻止正式启动，允许用户返回修改本次范围；运行中丢失不擅自扩大压力，保留测试并标记监控证据不足。停止条件由本次明确配置决定。
- 可选监控缺失：明确警告后可继续；最终只能下已有数据支持的结论。没有数据库涉及时填写“不涉及”而不是“数据库正常”。
- 超时重试有次数与时间上限；任务取消、节点异常、平台重启后可以恢复监控任务或明确终止，不能永久“收集中”。补采只读监控，不自动重新发业务请求。
- 后台执行采集，避免 HTTP 请求线程等待数分钟；多节点发压共用一次服务监控任务，不能重复统计同一服务。
- 访问地址按环境授权校验，防任意地址探测及云元数据访问；重定向、DNS 解析、TLS 和查询资源限额纳入测试。私网业务监控通过显式授权配置访问，不一刀切禁用私网。
- 凭据使用现有秘密管理能力，配置和执行快照只保留引用；删除/轮换凭据不能泄露历史明文。查询结果、日志和导出均脱敏。
- 原始序列与正式报告快照有明确保留策略，配置查询区间、最大实例数和点数限制。删除执行需说明关联证据范围；正式报告已固化的数值不依赖外部监控永久保留。

## 7. 指标及展示口径

| 指标 | 展示 | 必须注明 |
| --- | --- | --- |
| CPU | 使用核数、占分配额度百分比、峰值及趋势 | 宿主机/容器/进程；分母是核数还是额度；无 quota 时百分比不可假算 |
| 内存 | 实际 MB/GiB、使用率、峰值、结束后走势 | working set/RSS/used 的具体口径；容量未知时只显示实际用量 |
| 实例 | 匹配数、就绪数、扩缩容、重启 | 服务/Pod/容器真实 ID；人工期望实例数不等于实时实例数 |
| 网络 | 收发速率、可用时的错误/丢包 | 所属实例、单位、实际时间段 |
| 磁盘 | 吞吐、IOPS、延迟、空间 | 设备与指标含义；空间占用不是 I/O 压力 |
| 数据库 | CPU/内存、连接数、慢查询、锁等待 | 按实际接入能力；关系型数据库指标不强套 Redis |
| 业务 | 成功事务、降级、跳过、限流、排队 | 需要业务断言、日志或埋点，HTTP 200 不等于真实完成 |
| 压力机 | 发压进程/容器 CPU、内存及采样缺失 | 与被测服务独立分区；校准结果不是运行中的采样 |

多实例展示每实例结果和聚合口径。CPU 核数可求和，百分比使用同时间点总用量/总额度；同时提供最忙实例，不能平均掉热点。扩缩容时分母随实测额度变化，无额度时未知。

没有原始数据不补画 0；缺口断线。每张图显示横轴时间、纵轴单位、可选阈值和悬停数值。指标解释放简短提示，完整词典仍在工作台，报告页不加词典入口。

## 8. 报告组织

报告支持简报与技术详情，同一个数据快照生成，不维护两套相互矛盾的数字。

领导简报首页：
1. 测试目的、应用/版本、环境、时间、场景范围。
2. 实际达到的压力与明确结论：达标 / 不达标 / 存在风险 / 证据不足。
3. 吞吐、P95、业务失败率、关键服务资源与最忙实例。
4. 主要问题、业务影响、建议动作、负责人及复验状态。
5. 结论适用范围：经验证的负载区间，不从一次小流量推算系统最大容量。

技术详情顺序：测试背景与链路 → 环境和资源快照 → 负载及分阶段结果 → 接口/事务统计 → 被测服务监控 → 压力机健康 → 错误证据 → AI 分析 → 风险和复验。

历史选择保持紧凑分页/侧栏，不随执行数量增长把结果挤到页面底部。服务指标按服务切换，默认展开异常服务；更多实例在详情里查看，避免所有曲线无限堆叠。

运行期间自动更新，保留搜索、滚动、服务选择和展开状态；失败提示与最近更新时间常驻。结束后自动进入完整报告，不要求手动刷新。最终版报告保存监控覆盖、来源及配置快照。

正式导出覆盖 Word 汇报稿和 Excel 明细，页面与导出数字一致，支持鉴权下载；模板章节参考公司附件，术语作为导出附录。飞书发送保持用户触发或明确授权策略，不自动群发。

## 9. AI 诊断边界

- 先修复现有诊断因数值校验反复回退的问题，测试提示词与响应契约一致性，不放宽成无证据结论。
- 输入经过脱敏的指标、时间窗、异常实例和错误类型；不传密码、完整环境变量或无关业务数据。
- 每条诊断按“观察到的事实 → 可能原因 → 验证方法 → 建议动作”输出，附来源和置信度。
- CPU 升高同时 P95 升高，只能提示相关性；无堆栈/日志不声称已定位 SQL、死锁或内存泄漏。
- 压力机资源紧张与目标服务资源紧张分开判断；监控缺失必须降低结论范围。
- AI 失败不影响基础报告生成；AI 不改平台阈值、不触发自动扩容、不自动重跑高压。

## 10. 分批交付与检查

| 批次 | 交付内容 | 不可省略的验收 |
| --- | --- | --- |
| A 统计可信性 | 计数根因修复、阶段范围、完整性校验、诊断契约 | 固定次数和多请求链路原始计数对账；重复/迟到/停止反例；真实 k6 |
| B 配置到报告闭环 | 环境服务目录、执行勾选、Prometheus 只读接入、CPU/内存/实例、实时及结束报告 | Safari 从新增配置到最终报告；至少一个真实被测服务；数据源与页面抽样一致 |
| C 无监控接入及维度扩展 | 标准采集包、网络/磁盘、可用数据库指标、Agent 运行资源 | 部署包权限及资源验证；主机/容器分离；断连、重启、额度缺失和多个实例 |
| D 公司报告交付 | 领导简报、Word/Excel、证据冻结、可编辑背景和风险 | 与两份 Word/覆盖表逐项对照；分页、鉴权、脱敏、数值一致 |
| E 统计与持续回归 | 多轮计划、阶段/版本对比、覆盖矩阵、性能基线和告警 | 同条件可比、不同硬件明确差异；基线人工采纳，自动修复重跑隔离 |

每批独立提交和部署说明。B 交付不能以只有静态表单或截图作为完成；没有真实监控源时只能标记本地样本已验证、真实接入未验收。D 不必等 E 完成。

后续逐批实现时采用 executing-plans，针对该批补充可执行测试和数据库迁移细节，不预先承诺全部云厂商适配。
