# API 测试模块收口修复计划

## 目标

把当前接口测试流程收敛成测试人员能顺手使用的闭环：

1. 从 Apifox 手动同步接口、分组、参数示例和环境。
2. 按项目、接口分组、接口版本选择要测试的范围。
3. AI 只基于业务请求参数、Body 示例和响应契约生成用例，不生成 Biz、Authorization、Token 等公共请求头专项用例。
4. 调试通过后采纳为基线。
5. 基线作为稳定资产独立展示，可选择任意环境执行基线回归，并按项目发送飞书通知。

## P0：先修阻塞闭环的问题

### 1. Apifox 分组与参数示例

- Apifox OpenAPI 导出打开 `addFoldersToTags`，让 Apifox 目录天然进入 tags。
- OpenAPI 规范化阶段增加 Apifox 扩展字段兜底：当 tags 缺失时，从 `x-apifox-folder`、`x-apifox-folder-path` 等字段提取目录。
- 前端接口树不再只看 `tags[0]`，支持多级 tags 和 Apifox 扩展目录，并把“未分组接口”排到最后。
- 锁定参数 `example/default/schema.example` 在接口资产、草稿和 AI 输入链路中不丢失。

验收：

- 已同步版本中有 Apifox 目录字段时，接口树能显示分组。
- 新同步版本不再把绝大多数接口堆到“未分组接口”。
- GET 查询参数、POST JSON Body 示例能进入草稿和 AI 输入。

### 2. 任务范围交互

- 消除“保存测试范围”和“新建任务”之间的状态冲突。
- 新建任务后选择接口、AI 生成或调试时，应自动以当前选择保存任务范围，不再出现“测试任务范围与当前请求不一致”这种不可操作提示。
- 错误提示改为能指导操作的中文，例如“当前任务保存的是 A 接口，请先保存当前选择或新建任务”。

验收：

- 保存范围后新建任务，再选择另一个接口生成用例，不报旧任务范围冲突。
- 执行记录能看到所属任务名称。

## P1：基线和任务资产化

### 3. 基线跨版本与跨环境显示

- 基线是项目内稳定测试资产，不按当前接口版本和环境强过滤隐藏。
- 基线列表默认展示当前项目全部活跃基线，显示“采纳来源版本/环境”和“当前版本匹配状态”。
- 执行基线回归时由用户选择执行环境，不能混入工作台当前选中的非基线用例。

验收：

- 切换环境版本后仍能看到已采纳基线。
- 执行基线回归只执行被选中的基线。
- 报告和执行记录标记为“基线回归”。

### 4. 任务列表与重命名

- 增加任务列表入口，展示历史任务。
- 支持新建任务、修改任务名称、切换任务。
- 执行记录显示任务名称和执行类型。

验收：

- 之前保存的任务可以重新打开。
- 修改任务名称后，执行记录和报告使用新名称。

## P2：体验和运维增强

### 5. 报告和飞书

- 报告页继续优化为领导可读的概览：结论、问题分布、失败摘要、环境、版本、耗时。
- 飞书机器人按项目绑定；基线回归完成后自动发送项目对应群。

### 6. 后续能力预留

- 基线分组支持新建、编辑、删除。
- 基线支持批量加入定时任务。
- Mock、定时任务和分布式执行后续基于稳定任务/基线模型扩展，不在本轮混入。
