# 测试平台全流程体验修复计划

1. 记录线上全入口、执行子页和 API 测试导航点检证据，区分已验证、外部副作用未执行和待部署复查。
2. 先补回归检查，覆盖请求去重、详情轻量读取、失败重跑、有效 YAML 模板、历史批量操作、搜索与中文展示。
3. 修复 Agent、Jobs 和模型配置的重复请求；收窄 Agent 详情读取路径并保留摘要降级。
4. 补齐失败重跑真实按钮、历史批量操作、Trace 空状态和新建 YAML 模板。
5. 增加模型目录搜索、应用模块搜索与未归属统计，隐藏历史页无关执行侧栏。
6. 统一页面中文标题、失败类型、步骤和数量单位，明确失败分析与 AI 修复的上下游职责。
7. 为 API 测试的调试、任务、基线、定时手动执行、历史重跑和步骤预览增加统一执行确认；生产环境持续显示风险标识，取消操作不得产生保存或执行副作用。
8. 将 API 测试管理页的英文装饰标题改为中文，保留必要技术名词；补桌面和移动端视觉检查。
9. 运行 API 测试完整门禁、前端/后端静态检查、核心 Python 编译和差异检查；启动本地服务做桌面与移动浏览器回归并核对请求次数。
10. 更新体验走查记录与 `CODEX_STATE.md`，列出已完成、暂缓原因和部署后复查项。
