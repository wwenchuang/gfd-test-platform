# 录屏删除用例的运行时对象复用

用户要求：录屏中的打印编号不能固定在反复执行的删除用例中。本次打印记录允许任选一条；不推广成其他业务的任意删除授权。

## 方案

- 中文草稿新增“选取本次测试对象”，明确页面、数据范围和条件。选取步骤只读。
- 编译成官方 aiQuery；平台适配器在每个 task 中只取一次唯一标识和一条保留记录。编号为字符串，禁止 JS 数字精度丢失。
- 后续目标与结果使用本次绑定，失败不改选；新执行才重新选择。缺少可辨认数据则删除前失败。两台设备分别读取本机数据。
- SDK 并不原生支持本平台的对象标记。服务端检测 ui_dynamic_object_v1；Runner 启动前校验，适配器不可用时不得降级执行。
- 视频原始观察和帧引用保留。复用后的选择范围和结果建议独立确认，不把模型建议伪装成已观察事实。
- 普通用例不增加查询、轮询。动态用例增加一次查询和一次唯一性检查。
- 操作预期先短等待再断言，沿用显式等待并保留来源映射。高级 YAML 编辑同步支持无损回导。

## 检查与交付

1. 契约、无绑定/重复绑定/未知引用、旧 Runner、iOS 编译门禁。
2. Mock SDK 验证长编号、无数据、取消、task 隔离、新执行新绑定。
3. 视频导入到确认保存；高级 YAML 回导；主链与静态检查。
4. 独立审查。更新 Mac 两端 Runner（空闲时备份后替换并重启，原配置保留）。服务器更新 main。
5. 平台原视频新生成，核对来源和选择范围，再分别进行 Android/iOS 真机试跑；每次观察删除对象、保留对象、收尾与报告证据。

尚未完成真机验收前不得声称端到端通过。旧已发布基线不批量改写，旧草稿编译变化需要新试跑证明。
