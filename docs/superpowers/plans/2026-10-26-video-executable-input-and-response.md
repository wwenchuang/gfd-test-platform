# 录屏业务输入与延迟响应通用修复

用户明确要求继续修复至同原片生成可执行用例，不人工补值或删步骤。

1. 保留观察阶段全量输入脱敏。最终业务动作确定后，新增有界原图输入复核：只识别搜索、文字编辑等明确普通业务字段的最终可见内容；字段语义、凭据/个人信息上下文及令牌格式由平台独立拒绝。禁止从历史文件名、人工答案或观察描述正则抄值。保留原帧证据及恢复/需人工处理的审计。不对密码/验证码/令牌自动赋值。
2. 对同一控件→弹窗确认→3秒内再次同控件的假设，专门复核完整原操作、确认、响应的连续原帧（最多4项/60帧/1调用）。只改最后争议候选且必须精确保留争议帧、通过现有check_coverage；真实新点击仍保留。复核不直接删除/合并前序操作。
3. 测试先行：输入证据/越界/敏感/未知/取消、相邻确认延迟/真实重试/不同业务/窗口接线；完整视频回归及仓库必跑检查，独立审查。
4. 部署后原片重新上传，补充目标为空。对照固定人工稿与原始画面，核对两个输入、两次独立取消、耗材确认及末尾导航，无额外下一步或最终确认打印。导入后严格静态校验通过才计可执行格式通过。人审门禁与现场取消对象归属仍保留，不把静态通过等同真机执行。
