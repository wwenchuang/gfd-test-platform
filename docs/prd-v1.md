# 第 1 周练习范围与规则 v1

冻结日期：2026-11-05。使用已有平台的**反馈一级分类只读查询**和**平台匿名登录页**作为最小练习范围。原手册的采购订单审批是建议示例；此处不假定现有业务有采购订单、审批状态或金额规则。本文冻结的是本次演练的输入、可观察结果和安全边界，不冒充正式业务需求或权限设计。

## 实际接口与角色

| 项目 | 本次范围和证据 |
| --- | --- |
| 环境 | 现有业务服务；团队此前在真实环境执行只读查询，不能假设这是隔离测试库 |
| 请求 | `GET https://print.wisebeginner3d.com/app/print3d/api/v1/feedback/category/first?source=3D&bizCode=ZXB` |
| 操作者 | 平台已授权账号通过 API 测试使用配置好的业务凭据。曾观察到请求存在 `Authorization`；具体角色、凭据类型、最小权限和越权规则没有足够证据，标记待确认，不记录凭据内容 |
| 已有正向结果 | 平台此前一次真实执行为 HTTP 200、业务码 `0`、`data` 为列表，三条断言通过；只能说明该输入与当时配置、数据下的实际行为 |
| 已有反向演练 | 独立练习草稿故意期望 `code=999`，实际为 `0`，页面记录断言失败；它是测试断言演练，不是业务返回异常或正式错误码规则 |
| UI 范围 | 匿名访问 `http://127.0.0.1:8088/task-manager.html` 登录页。已有 Playwright 检查空用户名必填、浏览器判定无效、焦点定位，且登录 POST 为 0；不是登录后业务流程 |

## 本次可执行规则

| 规则 ID | 规则与验证方式 | 依据及限制 |
| --- | --- | --- |
| W01-API-01 | 使用固定 `source=3D`、`bizCode=ZXB` 对上述已知地址发送只读 GET。 | 已有线上请求证据；不能推断其他参数、来源或业务类型同样适用。 |
| W01-API-02 | 在当次执行的已授权环境中，检查 HTTP 状态、JSON `code` 和 `data` 类型；本次正向预期分别为 200、0、列表。 | 依据此前实测；列表内容随业务数据变化，不把具体分类值、顺序或数量硬编码成业务合同。实际偏离时保留响应摘要、环境和时间并先调查，不立即断言平台缺陷。 |
| W01-API-03 | 使用独立的错误预期 `code=999` 练习失败证据；清楚标注“故意失败”，保留预期与实际值和终态。 | 999 仅是本次错误预期，不代表业务错误码；不采纳该演练为基线，不放入定时任务。 |
| W01-API-04 | 不携带认证信息访问同一只读接口，本次预期 HTTP 200、业务码 4009。 | 2026-11-05 服务器匿名场景实测；这只是一次未认证拒绝观察，尚不代表正式错误码合同或已覆盖角色越权。 |
| W01-UI-01 | 访问匿名登录页，空用户名时浏览器表单校验应阻止提交，并聚焦用户名输入框。 | 服务器独立 Playwright 历史 run4 观测 `required=true`、`valid=false`、`focused=true`、登录 POST 0；不覆盖正确账号登录。 |
| W01-UI-02 | 用固定可见文案做单独确定性断言，再对错误文案单独执行故意失败，保存截图、trace、退出码与日志。 | 2026-11-05 在服务器新终端重新下载配套浏览器后检查标题：正确预期退出 0，故意错误预期退出 1，截图与 trace 留存；动态库复用了服务器已有隔离副本，详见 `docs/audits/2026-11-05-week1-gap-closure.md`。 |
| W01-UI-03 | 空用户名检查不得发送登录 POST。 | 历史 run4 中登录 POST 为 0；不代表所有登录场景均无请求。 |
| W01-UI-04 | 故意断言错误的标题必须返回进程退出码 1；环境或浏览器异常退出码 2 不计作预期失败。 | 依据服务器独立脚本合同和 `fresh-browser-rerun.log`；不能将退出码 2 当作通过。 |
| W01-EVIDENCE-01 | 每次页面正向及故意失败演练保留独立截图和 trace，证据保存在受控目录。 | 新浏览器实跑对应目录内两组文件非空；含页面内容的证据不得匿名公开。 |
| W01-SAFE-01 | 本范围只查只读接口和访问匿名页面，不输入真实账号，不触发手机、打印、删除、重置、升级或业务写入。 | 如要增加其他场景，先核查具体副作用、归属和清理；本条不授权设备或打印操作。 |

以上 10 项是本次**测试与操作规则**，包括技术和安全约束；现有证据不足以宣称已经确认 10 条正式业务规则。采购订单、多角色权限及角色越权仍不在本次冻结范围内。

## 仍需确认，不可由模型补造

- 业务负责人对 HTTP 200 / `code=0` / `data` 列表是否作为长期合同的确认，以及接口错误码、空数据、字段、顺序和分页规则。
- 各角色是否有权调用、凭据失效或越权时的正式表现；本轮只验证了未携带凭据的拒绝，尚未验证各角色越权。
- 接口的频率限制和测试环境数据策略；真实业务环境测试应控制请求范围与频率。
- 采购订单的创建、提交、审批、查询、金额和状态转换规则均不在此范围，尚未确认。
- 练习 UI 与真实业务 API 暂不是同一个端到端用户流程；需要后续选择可控、可清理的业务场景，再补登录后 UI 和 Runner 证据。
