# 账号角色与数据范围

账号需要同时配置“角色”和“数据授权”：角色决定能做什么，数据范围决定能操作哪些应用、项目和环境。新成员默认角色为测试成员，默认数据范围为空；只选角色不会自动开放所有应用。

## 内置角色

以下是代码中的初始权限；除超级管理员外，角色权限可以由有权管理员调整，实际权限以“角色”页面的当前配置为准。

| 角色 | 初始用途与权限 |
| --- | --- |
| 超级管理员 | 管理账号、角色、平台配置及全部数据。超级管理员角色本身不可修改，平台要求保留至少一个有效超级管理员。 |
| 测试负责人 | 在授权范围内管理、执行、删除测试及基线，管理接口环境、发送通知和使用性能测试；默认不含成员管理、平台配置、生产环境执行、压测节点管理。 |
| 测试成员 | 在授权范围内查看、编辑、执行 UI 和接口测试；默认不含删除、基线管理、接口环境管理。 |
| 只读成员 | 在授权范围内查看 UI 和接口测试，不能编辑、删除或执行。 |

可创建自定义角色，例如只含查看和执行权限的“测试执行员”。超级管理员和只读角色是独立身份，不与写入角色混选。权限依赖由服务端校验，例如执行权限必须包含相应查看权限。

## 配置步骤

1. 使用有“管理成员与角色”权限的账号，进入“配置 → 成员与权限”。
2. 在“角色”页查看现有权限；确有不同职责时创建自定义角色。
3. 在“成员”页新增或编辑账号，选择对应角色。新增账号首次登录需要修改临时密码。
4. 在“数据授权”页为成员选择 UI 应用、API 项目、API 环境。API 环境还必须属于已授权项目。超级管理员显示全部数据。
5. 使用该成员实际登录，核对可见应用及允许的操作。角色或范围撤回后，已有会话的后续接口请求也必须立即按新授权校验。

本次未自动给线上成员升权，也未改变任何线上账号的角色或范围。账号归属/操作记录说明谁执行了操作，不替代上述角色和数据授权。
