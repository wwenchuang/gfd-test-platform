# 在工作台运行接口和网页检查

打开「测试工作台 → 工具执行」，选择套件后点击「开始检查」。页面会发起后台任务，可以离开再回来。从「我的运行记录」点选一条，查看业务断言和耗时，下载 JUnit XML。网页用例另有截图和 trace。接口结果只保留状态码、响应结构检查和请求标识，不保存鉴权或完整业务响应。

- **反馈分类只读接口检查**：按当前账号的接口执行权限，使用原平台已配置的智小白环境，核对 HTTP 200、业务码 0 和列表结构。
- **已发布用例目录数量核对**：实际打开工作台，比较页面显示数量与目录接口返回数量。
- **目录故障演练**：在同一只读目录上使用刻意错误的预期，检查平台能否记录断言失败和证据。演练失败本身不代表业务缺陷。

刷新后可以找回相同的运行编号。提交结果不明确时可重试原请求；复用原编号不会新建任务。另发一次检查会生成新的运行记录。如需中止，只能取消自己权限范围内的本次任务。运行中会先显示“正在取消”，收到执行器结果后才显示终态。

“用例退出码”描述业务断言，“进程退出码”是操作系统观察到的数值。没有观察到的值留空。例如浏览器可以正常保存失败截图和 trace 后退出 0，而用例断言仍然返回 1。历史记录缺失的字段不会补造。JUnit 把断言失败、执行器错误、取消分别记为 failure、error、skipped。

## 如何复现隔离演练

在 QA 主机使用项目 Python 环境和全新的输出目录：

```bash
.venv/bin/python scripts/week11_runner/recovery_drill.py --output-dir /var/tmp/workbench-recovery-NEW
```

脚本用独立数据库和短命子进程验证崩溃、取消、超时和重新读取中断任务，不读取生产身份、访问业务接口或重启共享服务。每项留存原运行 JSON 和 JUnit。管理员可将通过校验的 recovery-drill.json 以服务账号所有、0600 权限放在身份库同目录，文件名 mcp-recovery-drill.json。只有这份简短摘要展示在工作台的「隔离恢复演练」里。
