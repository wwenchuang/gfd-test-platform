# 看懂测试结果和失败分析

进入「测试工作台 → 工具执行」。运行报告汇总当前账号仍有权查看的最近记录。阅读数字时先看分母：按“再运行一次”产生独立运行，不能仅凭用例名称相同推断同一次重试。故意失败的演练单独标记，不影响正式业务通过率。

需要跟进失败时，选中具体运行编号，打开失败分析。先看机器记录的实际值、预期值和证据编号；再看千问建议与下一步验证动作。建议只对这份证据有效。可以根据草稿补充复现步骤、提交缺陷；工作台不会把演练或模型猜测直接提成业务缺陷。

有执行权限的同事可以点「用千问分析本次失败」。这会对当前证据显式发起一次千问分析。网页展示机器观测、候选原因及待核对动作；相同证据重复点击读取原回执，单账号每小时最多发起 6 次新分析。网页查看历史结果不发起模型请求。已脱敏的事实包是模型可见的全部输入，原始凭证、完整业务响应和原始 trace 不发送。没有可用证据、回包无法校验或未生成时，保留“未知”或“未生成”。

人工金标按计划单独维护。未完成独立人工标注和比对时，页面不会给出归因准确率。隔离故障样例只能验证分类流程，不可充作人工样本或线上产品缺陷。
