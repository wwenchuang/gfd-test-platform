# 需求与原型的生成对照

服务端使用同一份冻结材料对比两套提示词，每组对照使用同一请求模型、原型像素、采样配置与响应格式。四组交替先运行带例子或无例子的提示词。两组提示共享提取事实、区分可见状态、记录未知、生成单一检验点和关联来源的要求。带例子版本额外包含图书馆领域的独立示范。参考答案和人工标注不进入请求。

在带有平台模型配置的环境中，自仓库根运行以下命令。输出目录由脚本创建；已有目录需要权限 0700。将路径替换为私有文件目录。运行将串行发起最多八次模型请求，每次最多输出 5000 tokens。程序复用网页的模型调用与结构校验函数，并对每条 visual 观察检查图片引用。

```bash
python3 -m scripts.requirement_design_evaluation --inputs /private/frozen-materials --output /private/eval-output
```

准备 `g1` 至 `g4` 四个子目录，各含现有需求设计服务可读的 `source.json` 及其中引用的图片。输入、模型或提示词变更时另建输出目录。重新运行同一命令会跳过已验证的组别和提示词组合，对失败组合发起新调用，保留历次失败记录和已收到的受限原始响应。单进程文件锁避免两个操作者重复调用。若程序在供应商收单后、写入已验证记录前被中断，下次调用可能产生额外费用。

在模型与数量均满足时 CLI 退出 0。比较完整性取决于两次回执是否都有效且实际模型名相同。候选数量只统计带例子版本的用例，按规范化步骤及预期进行精确文本去重。文本引用覆盖和去重仅为机械检查；人工有效覆盖、幻觉、语义重复、修订分钟数均待评审。

| 文件 | 读者与内容 |
| --- | --- |
| `report.json` | 原需求的授权读者。包含输入摘要、两组回执、去重后候选、来源、观察和问题 |
| `blind-review.json` | 仅看盲表和原材料的评审人。两套提示的候选混排，记录匿名编号及空白评审字段 |
| `private/plan.json`、`private/*-prompt.txt` | 执行人。冻结的参数、模型、输入、提示词及哈希 |
| `private/g*/{zero,few}/attempt-*/` | 执行人。隔离的模型原始响应、请求编号与散列、解析通过或失败记录 |
| `private/blind-seed`、`private/blind-key.json` | 评估组织人。保留用于盲评后解盲以及重复导出，不提供给盲评参与人 |

发布展示文件时使用工作台原有权限边界。人工评审完成前不将候选录入稳定基线。本次工具不会执行业务用例。

若校验规则更新，可以用相同参数追加 `--replay-only`，按每个方案的时间顺序从已保存回执重建报告。该模式不发送模型请求。确定事实、测试点和视觉观察仍要求有来源。仅在标记为 unknown、原本就没有资料可供判断时允许空引用。报告包含各组尝试次数、被拒的回执以及重新校验状态；人工质量评估独立保留。
