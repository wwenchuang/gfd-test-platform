# 读取知识评估报告：隔离实例阶梯实测

业务问题：同事同时在测试工作台展开已发布的 30 题知识检索评估时，请求是否稳定返回正确内容？本次只查询一个接口，无创建、审批或手机操作。已确认本轮在隔离实例执行。线上测试工作台用于查看结果，不是本轮负载目标。

- 目标版本：b9738e2e，使用真实平台 HTTP 处理器、登录和应用授权、SQLite 身份库、上一轮正式评估 JSON 文件；新建的一次性 viewer 仅能查看 com.kfb.model。JMeter 直接连接回环地址，没有 QA 的代理层、容器资源配额或其他用户流量。
- 数据路径：GET /api/platform/requirement-design/knowledge/evaluation。固定同一已登录账号与报告；HTTP 200 只是第一层检查，业务必须满足 ok、30 题、两种方法的评估字段符合预期。登录和获取令牌在计时外；JTL 不保存请求头、响应正文或登录信息。
- 预检：故意将题数设为 31，须出现 HTTP 200 + 业务失败；再用正确断言 1 用户运行 2 次。错误预期不计入业务错误率。
- 工作负载：JMeter CLI 闭环用户，每次请求间隔约 1 秒，1 → 5 → 10 并发；每档先预热 60 秒，稳态 180 秒，档间至少恢复 20 秒。最后按第一档的相同条件复测。并发数不是每秒请求数。
- 统计：按请求起始时间切分预热和稳态。记录请求总数、HTTP 成功、业务成功、各类错误、p50/p95/p99 和每秒请求数。记录停止原因；不把未完成的档位记零或通过。
- 资源：同一台物理机上分别采集服务进程和 JMeter 进程的 CPU、内存；SQLite 嵌入平台进程，没有可拆分的独立数据库 CPU。记录 SQLite 文件与 WAL 大小；文件大小不能说明数据库锁等待、I/O 延迟或 SQL 耗时。
- 结论边界：单账号、热点报告、同机回环、无共享负载；只评价这个读取动作。没有业务 SLA 时，不把安全停止阈值当作生产 SLA。不外推生产容量，也不以此评价向量检索速度。

停止条件与衡量口径：连续 3 次失败、最近 20–30 个样本的错误率 ≥5% 或 P95 >2秒、服务进程消失、服务 RSS >1536 MiB，或档位超时即停止后续升档。这些是保护条件，没有预先设定业务 SLA。本机 macOS 按 2 秒采样进程，用 CPU 时间增量计算 CPU 百分比（单核 100%）。额外的整机 CPU 和内存页采样由 5 并发途中开始，每 5 秒一次；不可用于补写 1 并发的主机读数。

复现：用同版真实平台代码和报告建立独立实例，启动命令见 tools/perf_environment/isolated_platform.py 的 --help。将此实例的监听端口、PID、SQLite 路径、临时 token 文件分别传给 tools/perf/run_knowledge_jmeter.py；指定 JMeter 可执行文件和从未使用过的输出目录。完成后先用 tools/perf_report/report.py 复算；需要本机 JMeter HTML 时，用 tools/perf_environment/render_dashboards.py，将每档稳态数据分别渲染到一个新的空目录。记录指纹和真实数值，不提交口令、会话文件或数据库。
