# API 测试平台全流程体验点检记录

## 点检目标

从真实使用流程验证接口同步、用例设计、调试、基线、任务、定时回归、执行记录和报告是否连续、真实、易理解。自动化门禁只作为基础证据，不能替代 Chrome 中的实际点击与状态转换。

## 评估维度

1. 功能正确性：按钮结果、状态、计数、断言和执行结论是否真实。
2. 上下游衔接：每一步是否明确告诉用户下一步、结果位置和返回路径。
3. 信息可理解性：中文业务文案、技术字段解释、状态命名和提示是否一致。
4. 新手友好性：空状态、首次创建、危险操作、必填项和推荐路径是否清楚。
5. 历史操作效率：搜索、筛选、分组、刷新、深链、列表详情和批量处理是否高效。
6. 性能反馈：加载、同步、生成、调试和执行是否及时显示阶段、进度和可恢复状态。
7. 异常恢复：网络、后端、AI、目标接口、断言和部署异常是否可定位、可重试、不伪成功。
8. 展示质量：桌面与移动端层级、密度、按钮、长文本、中文换行和视觉一致性是否合理。

## 浏览器覆盖清单

- 登录、退出、登录回跳、刷新和会话失效。
- 工作台：当前项目、接口版本、执行环境、任务范围和版本冲突提示。
- 接口资产：同步预览、正式同步、新接口搜索、分组折叠、接口详情和取消路径。
- 用例管理：手工、基础正向、AI 生成、普通/已调试/已基线分类、编辑、保存和分组。
- 调试：请求确认、过程状态、响应证据、业务码、断言、失败建议和基线门禁。
- 任务与基线：创建、编辑、范围、历史版本、当前有效基线和上下游跳转。
- 定时任务：创建、编辑、启停、立即执行、有效基线限制和执行结果入口。
- 执行记录与报告：搜索、筛选、详情、原始证据、失败分析、深链、刷新和返回列表。
- 环境与通知：环境版本、敏感变量占位、应用/业务配置、飞书自检和错误提示。
- 桌面与移动端：长名称、操作区、抽屉、列表密度、无重叠和无截断。

## 已确认问题与处理状态

### 已修复并复验

- **登录 404 与新旧后端混跑**：根因为旧 `midscene-upload.service` 自动拉起 `/opt/midscene-upload.py` 并占用 8091。停用旧 unit、清理 PM2、备份旧入口后，服务端和公网健康检查均上报 `b75b72e6d9dc7ab128bf47ee2b3413e538d443c1`，登录探针返回 HTTP 401 JSON，不再返回 404。
- **部署入口不唯一**：堡垒机保存命令统一为 `cd /opt/midscene-task-platform-src && git checkout main && git pull --ff-only origin main && bash deploy/update-main-server.sh`。更新脚本固化旧 systemd/PM2 启动器迁移、提交号、登录合同、健康接口和前端资源门禁。
- **部署伪成功**：提交号与登录合同门禁已在本次恢复中真实拦截旧后端，并在恢复后通过，不能再由旧进程的通用健康响应冒充部署成功。
- **同步完成但新接口仍找不到**：接口更新现在明确分成“检查接口更新”和“保存并切换到新版本”。Apifox 和通用 OpenAPI JSON 导入保存后都会更新当前项目、来源版本和有效环境；接口资产页可直接携带该上下文进入用例管理。版本保存成功但范围切换失败时单独提示，不会把已保存版本说成保存失败。
- **用例中的基线状态刷新后消失**：本地浏览器网络证据确认 `/cases` 已返回 v2 的 `debug_status=PASSED` 和 `baseline_status=active`，随后页面恢复旧 AI 生成任务中的 v1 并覆盖当前版本。现统一按同一逻辑用例的最高版本注册，旧生成结果不能覆盖新调试或基线版本；同版本的分组等元数据更新也会保留已有生命周期。
- **用例分类和创建入口不连续**：本地 Chromium 已逐项点击普通、已调试、已基线、当前任务、有编排、一次性、候选和全部 8 个视图；已验证搜索、“从接口创建用例”、接口搜索、关闭返回以及工作台/用例管理来回跳转。
- **生成过程和结果去向不清楚**：AI 任务在工作台和用例管理恢复同一任务，展示批次状态、进度、生成数、失败原因和结果入口；本地 E2E 已验证生成完成后进入用例管理仍可找到结果。
- **接口版本更新后历史记录断链**：执行用例结果增加接口稳定标识，详情和执行控制台可按当前接口或跨版本稳定标识查找同源历史；调试记录和报告显示具体“用例名称 · 在线调试”。
- **基线采纳中途关闭造成状态丢失**：采纳请求进行中关闭按钮和 Escape 均被禁用，直到生命周期刷新完成；历史基线编辑携带项目、来源版本、环境、接口和精确用例版本。
- **断言升级不能直接覆盖历史基线**：审计为“可补精确断言”的条目可生成新待复核版本，原活动基线不变。新版本必须重新调试通过再采纳；实际 HTTP 失败、业务失败、证据不足、缺少领域断言、冲突断言或已有较新人工版本均禁止自动生成成功断言。

### 已实现，待 Chrome 复验

- **错误提示误导**：登录 404 曾同时显示“用户名或密码错误”和技术 Toast。现统一为“登录服务版本不匹配，请联系管理员重新部署并重启后端服务”。
- **请求无限等待**：普通 API 测试请求增加 30 秒超时；工作台首屏恢复使用独立 8 秒只读超时，项目/环境、任务、接口或用例任一关键读取失败就停止后续请求，展示中文原因和“重试恢复”，不再串行等待几分钟。历史 AI 任务改为后台补读，不阻塞工作台。草稿持久化成功但保存后校验失败时明确区分状态，调试仍保持严格校验门禁。
- **约 240 条活动基线无法按实际响应复核**：基线页新增按需“检查断言”，批量读取采纳时的调试证据并以中文展示六类数量：断言已精确、可补精确断言、实际 HTTP 失败、实际业务失败、缺少领域断言和证据不足。列表只展示脱敏后的 HTTP 状态、业务字段和值，不返回原始响应和请求头。当前环境安全候选同时要求活动基线、原基线环境一致、接口流程允许且应用/业务仍可执行；切换环境后保存任务和立即执行按钮会再次校验审计证据环境。普通写操作保持人工复核，打印必须有本次任务 ID 提取和引用该 ID 的取消打印清理。检查本身不执行接口，也不修改历史基线。
- **布尔业务值被数值断言误判**：断言审计改用严格 JSON 类型比较，`false` 不再因为语言层面的相等规则匹配数值 `0`；`code` 与 `success` 仍分别核对，任一实际失败都不会被另一个成功字段掩盖。
- **普通 `API Test` 分组被误标一次性**：前后端均只识别明确的“一次性 / one-time / one time”标记，普通 API 回归分组保持常规基线；历史一次性用例可通过持久化分组名称补充明确标记。
- **刷新后随机恢复错误 AI 生成任务且查询会随历史变慢**：未指定接口版本时，生成任务恢复曾只按事务时间和随机 UUID 排序，同一事务内的运行中/已完成任务结果不确定。现在优先恢复 `queued/running` 未结束任务，没有未结束任务时才回退最新终态；指定接口版本时使用 PostgreSQL JSONB 条件和 `LIMIT 1` 同时限制当前版本接口与返回数量，不再在 Python 中扫描全部历史任务。
