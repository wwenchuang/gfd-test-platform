# 性能参考基线与退化预警

性能分析页面支持人工采纳性能参考基线，再手动选择完成执行核对退化。它与接口功能回归基线分开存储；不会修改原执行报告、自动创建定时任务、发送飞书消息或触发压测。

## 采纳与历史

需要 `api.view`、`api.loadtest.view` 和 `api.baseline`，同时校验项目与环境范围。只有正常完成、有完整请求/节点证据、达到实际负载目标、所选监控已收齐、比较条件已记录且实测资源分母可用的执行才能采纳。所选预警指标必须有样本。未记录缓存、数据规模、版本或未核验资源不能通过采纳；API 会说明缺少的条件。

采纳时必须输入名称和理由，并明确选择预警阈值。每个项目、场景和环境只保留一个当前参考；新采纳会将原参考停用，原快照、采纳理由与阈值仍保留。同一完整采纳请求可重试，不重复创建记录，也不会重新启用已停用的记录。

快照冻结条件、源执行标识、指标值、统计口径版本及采纳时的预警阈值。后续修改场景、环境或源执行配置不会重算历史参考。证据快照读取时核验摘要；摘要不能替代数据库访问控制或审计签名。已停用记录仍可手动比较。删除源执行不会删除冻结参考，但项目、场景与环境/环境版本仍有保留约束，不能绕过外键删除。

## 核对规则

候选必须是同一项目、场景和环境下有权限的完成执行。环境版本、场景内容、测试目的、数据/账号规模、缓存状态、负载与验收标准、数据集、压力机规格、监控范围、实测资源分母和停止策略沿用多轮比较规则。业务版本可以是明确记录的比较变量；其他条件变化或未知、采样不完整、负载未达标都会阻止差值判断。统计口径版本变化也会阻止差值，不把旧口径数据直接用于新口径回归判断。

支持的人工预警指标：

| 指标 | 计算与单位 |
| --- | --- |
| P95 增幅 | `(当前－参考) / abs(参考) × 100%` |
| 请求吞吐降幅 | `(参考－当前) / abs(参考) × 100%` |
| HTTP 失败率增幅 | 当前失败率百分数减参考失败率百分数，单位为百分点 |
| 业务断言失败率增幅 | 当前断言失败率百分数减参考值，单位为百分点 |

严格超过人工阈值才预警，等于阈值不预警。参考值为零时，相对增降幅未知；百分比变化与百分点不混用。任一已选指标无法计算时，整体结果为“条件或证据不足”，仍显示可用单项信息。未触发已选预警不等于整体性能达标，也不是优化因果证明或最大容量评估。

## API 与容量边界

- `GET /api/api-testing/v1/load-performance-baselines?project_id=...`：当前与历史记录，优先当前，最多 200 条并标记截断。
- `POST /api/api-testing/v1/load-performance-baselines`：参数仅接受 `run_id`、`name`、`adoption_reason`、`regression_policy`。
- `GET /api/api-testing/v1/load-performance-baselines/{id}`：冻结快照详情。
- `POST /api/api-testing/v1/load-performance-baselines/{id}/retire`：停用，不能修改快照或阈值。
- `GET /api/api-testing/v1/load-performance-baselines/{id}/compare?run_id=...`：手动只读核对。

只读用户可查看与核对，但不能采纳/停用。每个候选处理上限为 50,000 个指标桶、10,000 个样本；超过上限拒绝，不用截断数据给出结论。UI 候选来自性能分析页最近执行列表；不是全历史检索。

## 部署与回滚

新增迁移 `0012_load_performance_baselines`，依赖 `0011`；需在启动新后端前使用平台现有迁移入口升级至 head，随后更新后端和前端。模型注册与 HTTP/权限分发已接入。迁移只新增参考表、索引和外键，不改变既有接口回归基线或定时任务。

应用代码回滚可保留新表。若明确执行 Alembic 降级到 `0011`，会删除整张性能参考表，必须先备份所有参考记录并按数据库维护流程操作；这不是无损回滚。本次只在随机隔离 PostgreSQL 测试 schema 中验证升级与降级，没有迁移真实业务 schema 或部署服务。

定时生产压测、自动回归执行、通知规则和外部告警仍未实现。后续启用至少需要独立的发压授权、维护时窗、目标白名单、容量/环境门禁、熔断与紧急停止、数据隔离和通知接收配置，不能套用现有功能回归定时任务。
