# 压力机运行资源采样验收（2026-09-08，本地）

本批提供压测运行期间的压力机 CPU / 内存证据，与校准结果和被测服务监控分开。Agent 仅通过只读 cgroup/proc 文件或 macOS ps 读取计数，不使用 Docker socket、宿主机挂载或控制权限。

- `summary.load_generator_resources.role=load_generator`；运行中每约 30 秒通过现有指标接口上报最近 12 个样本，服务端合并到分片摘要；结束摘要保存完整保留序列。
- 默认 5 秒一次，按计划时长自适应到最多 1500 个样本（24 小时约 58 秒一次，另留 60 秒结束缓冲）。超出保留量时明确记录 `dropped_samples`，不把截断序列当全程证据。序列低于现有 1 MB HTTP 请求上限。
- cgroup v1/v2 的 CPU 用累计 CPU 时间差换算已用核数，再除以可见 CPU/配额的有效限制。内存保留已用字节和可确认的限制字节；v1 无限值和 v2 max 不伪造分母。读取当前 cgroup 及可见父级限制，支持 cgroup namespace 挂载根。
- cgroup 范围包含该组所有进程，不能解释为仅 k6 或整台被测服务。进程回退仅测所传入 k6 PID 的 CPU 和 RSS；内存限制为空。首次 CPU、缺失计数、进程消失均保留空值。
- 后端严格验证采样时间、范围、有限数值、原始分子/分母和百分比一致性、数量及大小边界；实时序列按样本序号合并，拒绝倒退及覆盖已收样本。旧 Agent 没有此字段仍可上报。

本机实际自身进程采样（2026-09-08 03:54:14 UTC）：约 0.153 秒区间内 CPU 0.9771 核，可见 10 核，折合 9.7712%；RSS 11,436,032 字节，内存限制和百分比为空。此处仅验证读取当前真实进程的计算链路，手动强制第二次采样；不是 5 秒生产采样、真实 k6 压测、容量校准或业务主机验收。

测试覆盖 cgroup v1/v2、父级配额、namespace、无限内存、缺失/非法计数、真实自身进程、序列截断、大小限制、runtime 成功/失败和实时上传、服务端严格校验。真实 PostgreSQL 隔离测试验证资源单独回传、幂等性、归属校验、实时合并和结束摘要落库。上线前需先部署支持该协议的平台，再升级 Agent；本说明不宣称已部署或已采集生产业务环境。

后续独立审查修复并实跑本地 k6 0.52.0 → Agent runtime → PostgreSQL：旧冻结 v1 和新版 v2 各执行 2 次/秒、两个 3 秒阶段的只读回环请求，请求计数、耗时样本和完成迭代逐项对账。v2 观察到 12 次请求中阶段一 5 次、阶段二 6 次、结束边界外 1 次；边界外发起独立保存，不能回填到阶段冒充达标。旧 v1 不产生新阶段证据，原脚本哈希通过固定摘要及 HTTP 下发验证。

停止流程另以真实 PostgreSQL 两个并发会话复现并修复了 run/shard 加锁次序冲突；停止中的分片可以回传末尾指标，自动错误保护遇失联仍保持 failed，不改写成人工取消。相关检查为本地运行与隔离数据库证据，不等于生产多节点加压验收。完整方案使用 Agent 0.1.5，旧 0.1.4 版本不包含本批新增采样协议。
