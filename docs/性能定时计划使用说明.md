# 性能定时计划

性能测试侧栏的“性能定时计划”独立于功能回归基线。先在“压测执行”完成只读场景的连通性检查和功能预检，再在计划页选择该记录、填写计划名称及每日北京时间。保存结果始终停用；核对目标环境、固定配置与压力后，勾选授权才能启用。

计划固定场景/环境版本、阈值、负载模型、实际选中的节点、监控版本和必选性、观察窗口、停止条件及测试条件。节点不自动替换，不允许不足容量强行运行；监控只保存版本引用，不复制只读令牌。当前仅接纳每个步骤均明确标记只读的场景；修改配置须从新的已预检执行另建计划。

调度器按北京时间每日运行。过期超过 90 秒跳过，不补发；同一计划有准备或活动执行时，不产生重叠执行。worker 每阶段短事务认领，联网操作不持有认领锁，准备阶段超过 180 秒阻断，worker 最长 90 秒，失联或不确定操作不重试创建。每轮重验创建人权限及环境范围，重新请求并核对本轮连通性命令结果、检查监控和执行一次功能预检，通过后调用统一启动门禁。缺失身份、权限撤销、节点离线或监控/预检失败均不自动发压。

停用阻止后续轮次和未启动的准备流程；已经启动的压力需要到“压测执行”停止。执行结果链接到原报告；删除来源执行不改变计划的固定参数。若 worker 在创建草稿后、写回关联前退出，可能留下未启动草稿，调度器不会盲目重建同轮执行。

飞书报告默认不发送。创建时显式选择通知需要 `platform.notify`，并使用项目现有已配置通知渠道。每轮记录独立发送状态：等待、发送中、已发送或失败；失败不改压测结论。发送采用至多一次尝试；进程在提交发送后退出时会保留“送达待确认”，不会自动重发，避免重复通知。

部署需数据库迁移到 `0013`，同步 API、worker、API testing scheduler 和前端。调度依赖现有独立 API testing scheduler 进程，不是打开页面才工作。当前交付验证使用隔离 PostgreSQL 和前端交互测试；没有在线启用计划、发送消息或进行真实定时发压。

应用筛选会在刷新后保留；页面每五秒静默刷新状态，不清空正在填写或编辑的内容。停用且没有准备或活动执行时，可以调整名称及每日时间；环境、节点和压力快照始终不变。支持归档并保留历史，不提供物理删除；勾选“显示已归档计划”可查看。

启动屏障超过120秒会按统一失联恢复收尾；已运行任务超过冻结持续时间（阶梯为阶段总时长）加180秒收尾宽限时终止，不让计划永久占用活动轮次。预检失败、准备取消或watchdog终态均进入持久化报告收尾队列，即使未选择监控也会生成报告并执行显式选择的通知；队列投递中断可恢复，通知发送仍至多一次。
