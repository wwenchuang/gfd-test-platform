# 多轮性能对比与接口覆盖

多轮对比是独立只读视图，不修改正式单次报告、性能基线或定时任务。当前支持同一项目 2–5 个已正常完成执行，按选择顺序以第一轮作为参照，也可在页面切换参照。服务端先检查所有执行的项目与环境权限，再读取报告；超出 50,000 指标桶、10,000 失败样本或 20,000 当前接口资产时要求缩小范围。

## 可比条件

页面列出环境版本、场景内容版本、业务版本、测试目的、数据与账号规模、缓存状态、负载参数、验收标准、数据集快照、压力机版本/限额/分配、监控选择和实测资源分母。业务版本可以作为比较变量变化，其他条件必须一致且关键字段已记录。未填写历史条件不会补成默认值；没有资源规格采样或运行中分母发生变化时，不声明规格一致。

执行必须完成、节点及请求/耗时证据完整、实际负载达到目标、所选监控全部最终收齐，才允许同条件差值。当前显示 P95、请求 RPS、HTTP 失败率、业务断言失败率的原始值与差值；百分比指标的绝对差值使用“百分点”，参照值为 0 时相对变化未知。字段无样本时不补零。条件或证据不足仍能查看两轮原始值，但不给差值和改善结论。

“记录条件可比”只说明这些记录和采样支持数值比较。它不证明某次代码修改造成改善，不将较低延迟推导为系统最大容量，也不将两分钟资源 rate 与瞬时请求延迟硬做因果关联。尚未提供自动显著性检验、重复试验计划、性能基线人工采纳或定时回归告警。

## 接口覆盖口径

覆盖分母为查询时同项目、当前激活接口来源版本中的接口资产，按实际 endpoint ID 去重。不是全部历史接口版本总和，也不是历史执行当时的资产快照。覆盖分子仅计有实际请求指标的 `iteration` 步骤，排除 setup、cleanup 等阶段。

归属要求冻结场景的复制来源指向真实用例版本，步骤标识匹配复制规则，且步骤、来源和持久化用例版本的请求方法/路径/服务一致，再通过该用例版本 endpoint ID 关联当前接口资产。手写步骤、修改路径、来源缺失、已停用或被替代的历史接口版本均明确计入未归属/历史范围，不按相似路径猜测。存在这些项时显示覆盖率未知；已确定的接口数仍保留。

“2 个执行轮次都请求同一接口”显示 2 轮、1 个已归属接口。覆盖仅代表实际尝试，不代表业务成功，也不是测试设计、业务分支或需求覆盖率。接口明细最多列前 200 项，汇总保留完整已归属计数。

## 接口与页面整合

接口：`GET /api/api-testing/v1/load-run-comparisons?run_ids=ID1,ID2`。返回独立 `comparison` 对象，包含查询时间、逐轮条件、逐对差异和实际接口覆盖。需要 `api.view`、`api.loadtest.view`，并逐执行验证环境和项目范围。请求不创建数据库记录，没有新增迁移。

页面组件：`api-testing-ui/src/components/LoadRunComparison.vue`，输入 `runs` 与可选 `projectId`，负责筛选已完成执行、2–5 轮选择、参照切换和差异/覆盖展示。项目切换清除旧选择，异步旧结果不会跨项目显示。

真实 PostgreSQL 测试覆盖双轮同接口去重、手写/改写步骤、历史资产、环境权限、全部选择先授权、证据预算与资源分母变化。组件测试覆盖选择上限、失败提示与旧请求隔离。代码验证不等于线上多轮业务压测或性能回归计划已执行。
