# 发布申请测试报告展示验收（本地）

## 用户约束

报告用于发布申请，保持简洁、中文为主。展示业务应用标题、执行人、测试时间、测试版本号和构建号、已执行用例、覆盖场景、真实结论；不展示操作流水和内部编号。少量图标区分结论/概况/覆盖/关注项。历史累计缺陷不直接否决本次测试。

## 实现

- 创建批次时冻结配置中的应用名称及用例目标/预期；报告从冻结批次构建 presentation，缺失场景或版本明确提示，未执行项不算已验证。
- 顶部测试版本按安卓/苹果系统分别列出应用版本与构建号，复制摘要同样包含版本；不重新查询设备当前版本。用例数与验证次数分开，失败后成功不覆盖原失败。
- Word/HTML/Markdown/页面使用同一份展示数据。Word 使用中文字体声明、浅色表头、细灰边框、自然分页与重复表头；✅/❌/⏳、📋、🎯、⚠️ 仅作辅助标记。
- 我的报告一键打开；报告失败可单独重试生成，不触发用例重跑。文件按固定报告版本下载，并校验当前账号、应用权限、格式与大小。账号/页面切换时中止旧下载和旧响应。
- 就绪报告沿用父页面刷新，每 15 秒有界检查后到证据的新版本；未改变时保留 DOM，改变时保留证据展开和键盘焦点。401/403/404 清除私有标题和正文。
- 同平台多目标在覆盖行和关注项使用稳定“设备 N”，概况同编号对应完整冻结型号/系统/应用版本；复试和列表重排不换号，避免整串设备信息挤占场景表。双同型手机一通过一未通过的样例最终一页完整显示。
- 原步骤和原始诊断继续保留在私有快照/证据中。旧脑图报告默认渲染选项保持不变。
