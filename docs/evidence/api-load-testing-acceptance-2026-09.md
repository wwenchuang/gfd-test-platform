# API 性能测试验收证据（2026-09）

## 当前结论

本地受控环境已完成性能场景、分布式调度、Agent 私有执行交接、指标汇总、确定性报告、AI 失败隔离、中文页面和部署包的集成门禁。主服务器与本机备用 Agent 已完成一轮真实 k6 小流量闭环；专用服务器、多节点并发、正式业务场景、飞书送达和多服务器资源峰值仍需继续验收。本文不把 1 次/秒演练当作生产容量结论。

## 本机备用节点真实闭环

- 场景：`本机备用节点最小压测-公开只读配置`；接口为 `GET /print3d/api/v1/open/webPage`，同时断言 HTTP 200 与 `$.code = 0`。
- Agent：`1155326d-7e3c-4d8f-bc46-1fb7de6abf72`，名称“本机（备用）”，k6 0.52.0、Agent 0.1.1，校准容量 80 VU / 200 次每秒，调度级别为备用。
- 最终成功执行：`734e7699-b64a-424f-81f3-5c92aba720e3`。Chrome 真实点击创建草稿、连通性检查、预检、开始压测、刷新报告、五秒数据表、节点明细与 AI 重新诊断。
- 配置：固定吞吐 1 次/秒，预分配与最大并发均为 1 VU，持续 10 秒，P95 必选阈值小于等于 1000 ms。
- 结果：10 个请求、10 次完整链路；吞吐 1 次/秒；HTTP、业务和链路失败率均为 0；P50/P90/P95/P99 均为 10 ms，最大 9.462 ms；节点退出码 0，6 个原始指标桶，证据节点 1/1 完整。
- 报告接口对正常节点返回空错误说明 `{\"message\": \"\"}`；页面曾因错误对象包含 `message` 字段而误显示“节点执行失败”。现已按真实数据补回归，只在错误码或说明非空时显示错误。
- 真实运行依次暴露并修复了 k6 语法兼容、VU 状态变量、控制台非 UTF-8 字节、施压窗口口径、历史结论锁定、同时间点重复 0 行、节点原始 JSON 和 AI 无效证据引用问题。失败执行均保留用于追溯，没有冒充通过结果。

## 受控目标与集成缺口

受控目标提供四种可重复行为：约 20 ms 成功、约 200 ms 延迟、HTTP 503，以及 HTTP 200 但业务 `code=1001`。首轮端到端测试发现 Agent 领取分片时只有元数据，没有可运行的 k6 脚本、环境或数据集；补齐交接后，第二轮又发现每个分片仍使用全局负载，会让多节点总压力成倍增加。

修复后平台在领取阶段执行以下检查和交接：

- 重新编译不可变场景并核对创建任务时的内容哈希。
- 确认环境包含场景引用的全部服务地址，缺失时直接返回中文阻断原因。
- 下发服务地址、环境变量和默认请求头，不输出到平台报告或日志。
- 按分片下发私有数据行，并核对文件哈希、大小和边界。
- 对固定并发、固定到达率、阶梯并发和阶梯到达率分别拆分负载；N 个分片之和保持为任务目标。

双节点受控链路验证了数据范围无重叠、重复指标批次不放大总数、HTTP 失败与业务失败分开统计、工作流失败独立汇总，以及 AI 超时后确定性报告仍可读取。五节点非均匀容量用例进一步验证 137 VU 和 137 行固定数据可完整拆分到五个节点，目标和数据总数均不变化。

## 页面与视觉

压测节点页增加节点总数、心跳正常数、可调度数和全部可调度节点剩余容量汇总。在线节点显示带中文“心跳正常”的脉冲绿灯，离线节点显示“心跳中断”的红灯，停用节点使用灰色状态；状态不只依赖颜色。节点卡仍显示最后心跳时间、校准状态、硬上限、软上限、校准容量和当前占用。

真实专用节点首次升级时暴露了假在线问题：最后心跳早于校准请求约 7 分钟，平台仍接受命令并让页面持续显示“校准中”。现改为页面每 3 秒自动读取最新状态，服务端按 45 秒心跳窗口计算有效在线状态；超时校准直接显示失败原因，且离线节点不能继续接收校准、连通性检查或压测分片。

升级后的新容器还因本机硬上限低于平台注册时保存的软上限而被服务端拒绝心跳。平台现于心跳时自动把旧软上限收紧到新硬上限，使节点可以恢复并重新校准；管理员从页面主动设置超过硬上限的值仍会被拒绝。

部署恢复修复后，专用节点实时状态确认为 Agent 0.1.1、k6 0.52.0、心跳正常、校准有效，实测容量 400 VU / 2000 次每秒；校准记录中的峰值为约 204.67% CPU 和 143.74 MB 内存。本结果只证明 Agent 本机校准完成，尚未证明目标 3D API 的正式容量。
