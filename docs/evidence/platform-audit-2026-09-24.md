## 录制准备行为

平台和 Sonic 显示真实阶段：等待 Runner 接单 → 正在采集手机画面和控件信息 → 已就绪，包含已等秒数。120 秒是单次准备超时上限，不是预计完成时间；超时后显示失败原因和手动重试，迟到结果不能改回成功。普通采集报错保留最多三次短间隔重试。桥接请求连同 JSON 正文限时 8 秒。

## 部署（按用户要求由用户执行）

1. 平台源码目录执行：

```bash
cd /opt/midscene-task-platform-src
bash deploy/update-main-server.sh
```

脚本默认同步 `deploy/sonic-recorder-hook.js` 至 Sonic Web，修改资源版本并核对哈希。检查终端最后的部署 revision 和健康结果；未看到成功输出不视为部署完成。原“无空闲手机”热修复为 `94f3deb`，本批应在其后。

2. Windows Runner 需要同步仓库根目录 `windows-midscene-runner.py`，并重启原 Runner：
   - 确认没有任务执行，停止原 Runner 控制台，备份正在使用的同名脚本。
   - 用本批脚本替换该文件，保留原 `winRunner.bat`、环境变量和密钥设置。
   - 通过原 `winRunner.bat` 启动一次，避免同时运行两个 Runner。
   - 默认版本为 `2026.09.24-midscene1.13-qwen3.7-result-retry-v1-recording-preparation-v4`。若启动脚本显式设置 `MIDSCENE_RUNNER_VERSION`，需同步对应版本标记并核对实际文件。
   - 本次无需重建 Sonic Agent JAR，也无需重新安装 Midscene CLI。

3. Chrome 刷新平台与 Sonic，重新创建一条可丢弃录制。必须实测三阶段、真实手机页面、点击截图/红点/语义、结束 YAML 与实际回放；服务端发布成功不等于 Windows 新 Runner 生效。只部署平台时旧 Runner 仍可上传截图，但不会发“采集中”回执，也没有此次调度优化。
